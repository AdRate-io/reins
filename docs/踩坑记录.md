## 怎么写
**标题**：`## <编号> [<域>] <可执行的结论>`，结论写"下次该怎么做"或"什么会出事"，并自带可搜的专有名词（报错原文、API、字段名）。
**正文三段，封顶 10 行**：机制 → 正确做法 → 教训。只写经验不写排查过程；教训写判断规则，不写"下次小心"。
**每条最普适的教训再提炼一行进 AGENTS.md 技术要点与风险。**
**域标签是闭合词表**，新增需明确决定：
`循环`（core：时间线 / 投影 / runLoop / 回放）/ `脑子`（brain 各模块）/ `降级层`（pi 版与 fetch 版）/ `服务端`（server / 总包 / 鉴权）/ `安全` / `MCP` / `eval` / `发布`（构建 / 打包 / npm / 公开仓库）/ `运行时`（Workers / Bun / Deno / Edge）/ `上游`（厂商 API、网关、宿主 CLI 的行为）/ `方法论`（探针、验证、批量改动的做法）

## 1 [降级层] pi-ai 0.85.1 的 `Message` 没有 system 角色，注入的 `system_note` 会以 user 身份发出——在 `onPayload` 里改写并自己守摆放规则

**机制**：Anthropic 官方支持带正文的中途 `role:"system"`（Fable 5.x / Mythos 5.x / Opus 5 / 4.8；Sonnet 5 及更早不支持），规则是不能首条、须紧跟 user（含只带 tool_result 的 user）、后接 assistant 或收尾，否则 400。pi-ai 数据结构里没有这个角色，只能降成 user。
**正确做法**：不 fork pi-ai，用公开的 `onPayload` 钩子把带内部标记的 user 改写成 system，并由降级层自己归位（第一版改写完直接发，紧跟一条 user，违规）；`capabilities.midConversationSystem` 按模型族声明，第三方上游由宿主声明，缺省不支持（发错是 400，发保守只是有损）。
**教训**：官方 API 支持 ≠ 我们用的客户端库支持，进代码前用实测看**真正发出去的请求体**；改写别人的请求体时，目标协议的排列规则也归改写方负责。

## 2 [脑子] 模型会把"先整理，然后做 X"连同 X 一起折进摘要，整理完反问 X 是什么——最近一条用户消息必须由库缺省保住

**机制**：compact 切在模型轮边界，最近一条用户消息正好落在折叠范围里；模型只能总结发生过的事，复述不了还没处理的指令（claude-opus-5 真模型，全程 200 无报错）。
**正确做法**：`keepLatestUserMessage` 缺省开，最近一条用户消息进 `pinsKept`，随 pin 在摘要之后重注入；修后同一情形模型整理完直接去做第二段。
**教训**：把上下文管理交给模型时，库仍要守住模型**结构上不可能做对**的事。判断规则：一项内容丢了，模型有没有办法自己发现并补救？没有的（未执行的指令、当前目标）库缺省保住。这类缺陷只有真模型能暴露。

## 3 [循环] 装了带静态贡献的脑子模块，server 恢复预校验一律 409 配置漂移——同一个值两处比对必须调同一个纯函数

**机制**：B2 引入 `Socket.tools` / `systemPrompt` 静态贡献后，runLoop 起步把它们并入 configHash，server 开流前的恢复预校验却只用宿主工具表算，两边哈希天然不同。
**正确做法**：解析抽成 core `resolveSocketContributions`，循环、server 预校验（后来还有 TanStack initRun）共用。
**教训**：凡是"同一个值在两处独立算出并比对"（configHash、签名、摘要），两处必须调用同一个纯函数；各写一份迟早分叉，表现是莫名其妙的校验失败，最难查。

## 4 [上游] aireiter 网关的 Claude 端点会改写请求：最后一条 user 正文之后的一切都丢，中途 system 被换成 "Continue" / "OK"

**机制**：模型 thinking 里说"用户只发了一个句号"——网关前置了自己的身份提示与 Human / Assistant 对，末尾中途 system 被换成 Assistant "OK" + Human "."，中段换成 user "Continue"。DeepSeek 直连七种落点全部到达。
**正确做法**：Boss 决定不为测试用中转打补丁；如实记"经该网关 perception 当轮不可见"；后续对照改用忠实上游（DeepSeek 直连，后来是 CF AI Gateway 透传）。
**教训**：第三方兼容端点先做忠实度体检（暗号法 + 让模型逐条复述看到的对话）再拿来实测；模型行为与"我们发出去的内容"对不上时，第一嫌疑是中间层；凡"经网关测得"的结论都标注链路。

## 5 [发布] tsup 8 缺省 `removeNodeProtocol` 把 `node:sqlite` 剥成裸包名 `sqlite`，源码与 vitest 全绿，只有跑 dist 才 `ERR_MODULE_NOT_FOUND`

**机制**：`node:sqlite` 不在 esbuild 内置清单里，剥前缀后变成不存在的 npm 包；tsc 与 vitest 都经 `paths` / alias 走源码，从不加载 dist。
**正确做法**：含 `node:*` 的包（store-sqlite、brain 等）tsup 设 `removeNodeProtocol: false`；验收加一次对 dist 的真实 import，后来固化为 `pnpm check:dist`（新 `/node` 入口登记进 `NODE_ALLOWED`）。
**教训**：monorepo 里源码路径与 dist 路径是两套解析规则；打包器能改写 import 说明符时（剥前缀、externals、条件导出），验收必须真跑产物——`node:` 内置、可选依赖、子路径导出最容易出事。

## 6 [循环] `replayTurns` 按 actor 切轮，会把模型自决的 compaction / pin / memory_op 切成额外的轮——轮边界按模型输出类型判

**机制**：这些事件 actor 也是 `model`，并行工具时落在 tool_result 之后，被当成"模型又输出了"，轮数与每轮 token 指标全歪。
**正确做法**：按输出类型（thinking / text / tool_call）判边界，导出纯函数 `isModelOutput`，eval 与回放共用。
**教训**："谁做的"（actor）与"是不是一次模型输出"是两个维度，不能互相代用；引入模型自决类机制后，所有按 actor 分组的逻辑都要重审。

## 7 [降级层] 并行工具之间夹一条说明会把 tool_result 拆成两段，DeepSeek 直接 400——说明后移到同批结果之后

**机制**：pin / memory 的留痕 `system_note` 排在自己的 tool_result 之前，模型并行调两个脑子工具时就落在两条结果中间；协议要求同批 tool_result 紧跟 tool_use。dogfood 239 个事件没撞上，只因模型碰巧没并行。
**正确做法**：降级层把落在两条 tool_result 之间的 `system_note` / `compaction` 后移到同批之后，落点备注"说明后移"（与 TanStack 适配器、用户插话后移同一机制）；改 `to-request.ts` 先跑其测试。
**教训**：真实 dogfood 跑通 ≠ 覆盖协议约束；涉及厂商排列规则的地方，要专门构造并行 / 多条 / 交错用例去撞。

## 8 [脑子] 模型看到 "compactions so far: 1" 就认定旧细节已被折叠而拒答，即使原件就在上文——给它一条取回的路，而不是删说明

**机制**：E3（DeepSeek 99 格）brain 臂召回比 threshold 低 3～6 点，被问的工具结果明明在视野里，模型说"那部分已折叠，可以重查"。是**以为丢了**，不是真丢；把说明改成明说"折了什么"只缓解不消除。
**正确做法**：compact 摘要后自动附被折叠工具结果清单（`seq N tool(入参) — 大小`，core `foldedToolResults` / `renderFoldedToolResults`，阈值摘要同列），加 `recall({ seq })` 逐字取回；两族复测必丢那条 Sonnet 12/12、DeepSeek 9/9，门槛 2 达成、compact 转推荐默认。
**教训**：给模型加"会消失"的机制，必须同时给"拿得回来"的路，并把事实上还在的（清单）与模型的取舍（摘要）分开呈现。eval 失分先定位机理——"丢了"与"以为丢了"修法相反。

## 9 [脑子] Sonnet 整理时只留结论不留字段值，"Keep exact values" 一句提示改不了——机制代价用机制兜

**机制**：E3b（claude-sonnet-5）每格都真调了 compact，摘要与 pin 只留 "operationStatus=ENABLE" 这类结论，同一条细字段 6/6 丢；规则里早已写了保留原值。两族一起指向机制本身：模型按自己的重要性判断丢细粒度。
**正确做法**：不和模型抢"留什么"的决策权，给取回的路（见 8）。同轮另得：没装 approval 的臂两族都出现"列完候选停下等 Owner 批准"，装了就直接提交（100% vs 93%）——approval 默认开还因为它"让模型敢动"。
**教训**：对策只是往提示里加一句话的，必须有 eval 数字证明它改变了行为，否则不算修复；跨模型族的结论要复测，同一个失分数字可能是两种机理。

## 10 [安全] 网络端点原样接受任何事件草稿，伪造一条 `approval_decision(approved=true)` 就能绕过审批——每个信任边界各设一道类型白名单

**机制**：server 对 `input` 草稿不限类型直接写日志；同理可伪造 `system` 信任的 `system_note`、伪造 `compaction` 藏历史。"日志是唯一真源"被单向理解成"什么都能写进日志"。
**正确做法**：循环层 `inputDraft` 只收 `core.user_message` / `core.tool_result` / `core.system_note` / `ext.*`（其余写日志前抛 RangeError）；server 层只放 `user_message`（只取 content）与客户端工具 pending 的 `tool_result`；审批结论只走 HMAC 保护的 `decisions` 通道。
**教训**：外部可提交事件的系统要按类型列白名单，并区分客户端可声明字段与服务端权威字段（actor、trust、审批、折叠）；网络边界一道、库公开 API 一道，进程内调用方也可能在转发不可信输入。

## 11 [降级层] 用户在 tool_result 回来之前插话，下一次请求被 Anthropic 400——日志顺序不动，由降级层后移并记 `lossy(user)`

**机制**：续跑带新 input 或进程死后再发消息，日志如实是 `[user, tool_call, user, tool_result]`；"tool_result 紧跟 tool_use"是线协议硬约束。
**正确做法**：降级层把未到齐结果前落下的用户消息后移到同批之后，记 `lossy(user)`（pi 版、fetch 版、TanStack 同规则）。不改 runLoop 让 input 等 pending——暂停时用户的话要么丢、要么仍在结果之前。
**教训**：厂商排列约束属于降级层；判断规则：这个约束换一家模型还成立吗？不成立的就在降级层改形状并声明有损，绝不回头改日志顺序。

## 12 [循环] 宿主中止在工具批中途不生效，剩下的调用在下一轮开头被当 pending 继续执行——中止检查放在每个副作用动作之前

**机制**：runLoop 的中止检查在"补齐 pending"之后，中止只跳出当前批，下一轮开头先补齐、再检查。
**正确做法**：中止检查前移到补齐 pending 之前；批中途中止后余下调用留作 pending，下一轮开头直接 `paused(host)`。
**教训**：中止的语义是"没执行的别执行"，检查必须在每一个会产生副作用的动作之前，而不是循环顶部一次；验收专测"批量中途中止"与"暂停后恢复"两条路径。

## 13 [降级层] 同一轮的多条说明归位后前后颠倒（边算边 splice）——先算落点、分组、再一次拼出

**机制**：中途 system 归位逐条算位置并立刻 `splice`，同落点的第二条顶到第一条前面；测试只断言角色序列，不查文本顺序，请求照样 200。
**正确做法**：先算每条说明在原始列表里的落点，按落点分组，再一次性重建；补断言文本顺序的用例。
**教训**：边遍历边修改同一列表默认怀疑顺序；测试断言粒度要覆盖到"这个字段错了会有什么后果"那一层。

## 14 [服务端] POST 的 sessionId 在请求体里，`principal(request)` 钩子里根本判不了会话归属——鉴权拆成 `principal` + `authorizeSession`

**机制**：`principal` 跑在 handler 解析 body 之前，宿主要判归属就得 `clone()` 抢读一次性流；GET 分支甚至没收到 principal。结果是知道 sessionId 就能读走整条时间线。
**正确做法**：`principal` 只答"谁在问"；`authorizeSession({ sessionId, principal, request, method, isNew })` 在解析出 sessionId 之后、读写日志之前统一调用，**只有字面 `true` 放行**，`false` / `undefined` 回 404（不用 403，不确认存在）。缺省不检查，README Security notes 明示。
**教训**：设计安全钩子先问"做判断需要的输入在这个时机拿得到吗"，拿不到就是层级错了；布尔型安全钩子一律只认显式 true，漏写 return 当拒绝。

## 15 [服务端] sessionId 里一个中文字符就把 400 变成 500——会进 header 的客户端输入在入口按白名单校验

**机制**：sessionId 回写进 `X-Reins-Session`，中文 / emoji / 控制字符让 `Headers` 抛未捕获 TypeError；真实边界是 latin1（`é` 能进），CRLF 被 `Response` 挡住、不是注入漏洞。
**正确做法**：`SESSION_ID_RE = /^[\x21-\x7e]+$/`，POST 与 GET 各校验一次，越界 400 `bad_request`；故意比 latin1 严：一句话说得清，且 header 首尾空格会被 trim 造成回写值静默不一致。
**教训**：最终会进 header、SQL 标识符、文件路径的字符串在入口白名单校验，别等下游库抛异常；校验边界宁可比真实边界严一档。

## 16 [运行时] Workers 新 compatibility_date 缺省带部分 Node 兼容，只跑新 date 会高估 edge 结论；HTTP 200 也不等于探测通过

**机制**：2026-09-09 档不加 flag 也能 `import("node:fs")`、有 `process` / `Buffer`。另两回假通过：块注释里写了含 `*/` 的路径提前闭合；正则抓 baseUrl 抓到反引号，worker 把 `Invalid URL` 包成 JSON 照样回 200。
**正确做法**：判据取最严档 `compatibility_date = 2023-01-01` 无 flag（`process` / `Buffer` / `node:*` 全无），并记录该档实际可用面；每层探测逐项核对产出内容（入参中文未乱、usage、toolCallId）。
**教训**：兼容性结论的强度由最严那档配置决定；探测脚本的通过判据永远不是状态码。

## 17 [循环] 上游瞬断能掐死整格跑数而 runLoop 没有重试——只在本次尝试一个字都没落日志时重试

**机制**：E3 的 99 格里 3 次 DeepSeek "Connection error"（pi-ai `terminated`、输出 0 token），runLoop 把调模型当原子操作，整格作废。
**正确做法**：`LoopConfig.retry`（缺省 3 次、1s 起翻倍封顶 8s），判定是纯函数 `loop/retry.ts`；**只在本次尝试未落任何模型输出时重试**，落了半截照旧 error 并标 `partialOutput`；每次将重试的失败记一条模型不可见的 `core.error(willRetry)`。后续 R3 改为状态码优先（408/409/429/5xx），关键词只在没有状态码时兜底。
**教训**：重试先问"会不会污染唯一真源"——append-only 时间线上只有零输出时重试才安全；判不出是否瞬断一律当非瞬断，反过来会把 4xx 变成重试风暴。

## 18 [脑子] 模型瞄着字数上限写却数不准自己写了多少（pin 500 字写成 502～558）——对外声明严格值，对内留两成容差

**机制**：上限已写进工具说明与 schema `maxLength`，Sonnet 仍 3/3 格越界几个到几十个字符；差几字整条拒掉，等于用一次模型往返换几十字额度。
**正确做法**：`overshootTolerance` 缺省 0.2：声明 500、601 起才拒，报错仍报 500（不告诉模型真实阈值，否则它改瞄 600）；复测撞限从 5/6 降到 2/6，剩下的 608 / 680 拒得对。
**教训**：让模型自控数值上限的校验，按越界代价定容差——只多占点上下文的可容差，会 400 或产生错误结果的必须严格。

## 19 [MCP] 一个 `WebStandardStreamableHTTPServerTransport` 只服务一个会话，第二个客户端 initialize 回 400 "Server already initialized"

**机制**：示例服务器用全局单个传输实例；续跑时宿主重建 `mcpTools()` 再连就被拒，run 写日志前抛 `McpToolsError`。单测只连一次所以全绿。另一层：工厂每次造新 `McpServer`，业务状态必须放工厂外。
**正确做法**：服务器用 `createMcpHandler(factory)`，业务状态提到模块级；测试加"两个客户端先后初始化"断言；示例按配置缓存 `mcpTools()`，配置变了才换并关旧连接。
**教训**：自己搭的示例 / 测试服务器至少让两个客户端先后连一遍；示例会被照抄，写法必须是生产形态。

## 20 [服务端] asTool 经 HTTP 续跑必 409 `unknown_tool_call`：server 预校验把子代理的审批结论对照了父会话 pending

**机制**：runLoop 按 `decisions[].sessionId` 分流（本会话的校验、别的会话的经 `ToolContext.decisions` 转发），server 预校验还是老逻辑全对照父 pending；覆盖用例全在进程内，没有一条穿过 handler。
**正确做法**：预校验对带别的 sessionId 的结论跳过 pending 校验原样下传，sessionId 走 `isValidSessionId`；加两条经 `agent.handler` 的跨包用例。
**教训**：同一判定在两个入口各写一份，就必须有一条穿过两个入口的用例（configHash、pendingDigest、decisions 分流已三次）；新公开路径要沿文档写给用户的那条路验收。

## 21 [上游] AdRate `skills install` 落盘的 SKILL.md 是"请运行 `adrate skills read`"的存根，正文只在 CLI 里

**机制**：`~/.agents/skills/adrate-ads/SKILL.md` 只有 686 字节 frontmatter + 一句跑 CLI 的指令；正文与 CLI 版本绑定（`minCliVersion` / `contentSha256`）。对没有 shell 工具的 reins agent，这是一句做不到的指令。
**正确做法**：示例不用 `fsSkillSource`，启动时 `adrate skills list --json` / `skills read --json` 拼成 SKILL.md 喂 `inlineSkills`；frontmatter 解析跳过缩进的嵌套字段、去引号。
**教训**：接任何"符合规范"的目录前先看一眼正文，规范只定形状，内容可以是转发。

## 22 [脑子] 两族真模型都不按截断提示续读技能：`skill_read` 16k 上限把 AdRate 技能截掉 110 行，模型直接开工

**机制**：截断 + 续读提示对 memory 成立（模型自己分页读熟悉结构的文件）；SKILL.md 是"读完才能动手"的说明书，模型读到 245 / 355 行就觉得够了，被截掉的恰是写操作契约。
**正确做法**：缺省 `maxReadChars` 提到 40000（Agent Skills 规范 ≤500 行 ≈ 40k 字符，规范内一次读完）；DeepSeek 复跑核对 355 行一次读完。
**教训**：续读 / 取回机制只在模型有动机时起作用；"读完才能动手"的内容，缺省上限按内容规范定，不能照搬另一个模块的数字。

## 23 [脑子] 按"token ≤ 字符"给 `skill_read` 定 spill 限额，40k 字符的中文技能照样被外溢成预览且取回来是 untrusted

**机制**：core 粗估 `estimateTextTokens` 是 ASCII 4 字 1 token、**非 ASCII 1 字 1 token**，中文没有余量；视图每行加行号与表头再大 8%；软上限还能被 `range: [1, -1]` 与超长单行绕过。结果同一份字节两条路两个信任级别。
**正确做法**：skills 视图用硬上限（带 range 也截、超长单行切开）；`resultPolicy.maxTokens = 2 × maxReadChars + 256`，推导写在注释里；用例换成 500 行中文 + 缺省 spill。
**教训**：给另一个模块的阈值写"永远不会触发"之前，把两边度量口径摆一起算最坏情形（用中文，不用 ASCII）；先问上限是硬的还是软的，软上限不能当另一条机制的前提。

## 24 [发布] 以为敏感数据只在录像里，按值扫全历史才发现真实广告主 id 散落在 10 个文件、72 个提交——脱敏按值查，不按文件查

**机制**：测试广告主 id 被当常量写进示例源码、pin 文案、单测样例与文档叙事，层层复制；E2 定脱敏口径时只盯录像一个载体。
**正确做法**：`examples/adrate/scrub.ts` 出别名表，`git filter-repo --replace-text` 改写全部提交（先 `git bundle` 备份，改后按值扫零残留）；真实值改从环境变量或 gitignore 的信息文件读；测试按形态断言（"只剩别名形态"）而非按值断言。
**教训**：先从源数据抽出全部敏感值，再拿值表 `git grep -F -f` 扫全历史；本地专用值一开始就走 gitignore 的配置读取；批量改文件用 Node 脚本（zsh 不分词、本机 grep 是 ugrep 别名）。

## 25 [eval] 门禁差一格没过，根因是 fixture 的 `authId` 给了字符串 `"auth_001"` 而 schema 要整数，模型合理地停下来问人

**机制**：工具发现 eval 第一轮 Sonnet 候选臂 96.7% 对基线 98.3%，掉分全在同一题、两臂都有；模型按"不猜 id"的契约拒绝编造整数 id——对的行为。
**正确做法**：`authId` 改整数、任务文案同步，两族重跑；第一轮报告保留并注明缺陷。
**教训**：fixture 给模型的每个值都按工具 schema 核类型；门禁差一两格先看掉分在哪题、两臂是否都掉——两臂同题都掉多半是题的问题；"停下来问人"在 eval 算没完成、在产品里是正确行为，造题要先消掉这类歧义。

## 26 [上游] Cloudflare AI Gateway 的 REST 路径用网关令牌一律 401 "Authentication error"——官方靶子走透传路径 + `cf-aig-authorization`

**机制**：`api.cloudflare.com/…/ai/v1/*` 认账户级 API token、模型名要 `anthropic/…` 前缀；`gateway.ai.cloudflare.com/v1/<account>/<gateway>/<provider>/…` 透传路径才认网关令牌、用厂商原模型名。后台最显眼的是前者。
**正确做法**：用透传路径，三条协议原样回暗号、Anthropic 流式透传；用法写进 `spikes/README.md` 末节，私有值在 gitignore 的信息文件末尾。
**教训**：平台给的入口 url 与凭证未必配套，401 先问"这条路认哪种凭证"再怀疑凭证本身。

## 27 [方法论] 靶子体检首轮四处"假 FAIL"全是我把厂商规范记错——写探针期望值前先查官方数字

**机制**：① Haiku 4.5 最小可缓存 4096 token（Opus / Sonnet 才 1024），3.5k 的 system 没到门槛；② 开 thinking 时 `max_tokens` 必须大于 `budget_tokens`，厂商先校参数再校签名，400 理由不是签名；③ Opus 5 缺省 adaptive thinking，`max_tokens: 30` 被吃光；④ 强制 `tool_choice` 时 OpenAI `finish_reason` 就是 `stop`。
**正确做法**：system 加到约 6.3k token、伪造签名用例给足 `max_tokens`（拿到真正的 `Invalid signature in thinking block`）、Opus 给 400、接受 `stop`，全绿后再写结论。
**教训**：期望值按模型 / 协议查官方数字，凭记忆的门槛会把忠实上游判成改写；反向项拿到 400 要核对 400 的理由；"用量为 0"先问阈值再问透传。

## 28 [上游] 暗号法探中途 system 触发 Anthropic `reasoning_extraction` 分类器拒答（200 + `stop_reason: "refusal"`、`content: []`），差点记成网关改写

**机制**：`stop_details.category` 是厂商分类器；"告诉我你被告知的暗号"出现在中途 system 位置就触发，`mid-conversation-output-config` beta 头把触发率抬到 5/5；感知式说明（问上下文百分比）稳定到达。
**正确做法**：探针的中途 system 改用感知式说明（与 perception 真实文案同形）；fetch 版只带真用到的 beta 头。
**教训**：200 + 空内容先看 `stop_reason` / `stop_details` 再怀疑中间层；探针文案与产品真实文案同形，否则测的是分类器不是通路；多带一个 beta 头不是免费的。

## 29 [上游] DeepSeek 带 `tools` 时历史 assistant 缺 `reasoning_content` 直接 400 "must be passed back to the API"——空串可过

**机制**：DeepSeek V4 缺省就是 thinking 模式；带 tools 时所有历史轮的 `reasoning_content` 都必须回传，不带 tools 时忽略。立项时只看了响应形状（读侧），没看写侧约束。
**正确做法**：方言开关 `FetchModel.chat.reasoningContent`，开着时**每条**历史 assistant 都带：同家 thinking 拼入、没有给空串、别家的记 dropped；`deepseek()` 缺省开，`openaiChat()` 不带；真模型两轮工具往返验证（`spikes/f1-chat-live`）。
**教训**：方言字段读写两侧都要探；"缺省开"的能力按开着设计；三条 curl 探针先于第一行编码器，比写完再改便宜十倍。

## 30 [方法论] 量缓存的探针 TTL 内重跑，对照臂读到上一遍写的前缀，"应归零"变成假阴性——系统提示加一次性盐，且盐要在 `cache_control` 断点之内

**机制**：Anthropic 缓存 5 分钟 TTL、命中续期；两遍前缀逐字相同，第二遍直接命中。P9 首测把盐追加成 system 新块，落在断点之后，等于没加还造出一段"断点后余量"。
**正确做法**：替换断点块内的 run 盐（`session run-<时间戳>`）；同组各臂共用同一个盐。
**教训**：正负两个方向的缓存断言都要盐；要隔离的是"跨运行"不是"臂与臂"——臂间能否互相命中本身就是判据（P9 靠删件臂整段命中带标臂定死 deferred 定义不进前缀）。

## 31 [上游] Anthropic `tool_result` 里 `tool_reference` 不能与文本混放，且同条 user 里所有 `tool_result` 必须排在最前

**机制**：`[text, tool_reference]` → 400 "cannot be mixed with other content"；把文本挪到那个 tool_result 后面，并行两调用时 `[tool_result, text, tool_result]` → 400 "tool_use ids were found without tool_result blocks immediately after"。IR 的后移只管事件级内容，encoder 自己造的块没守这条。
**正确做法**：Anthropic encoder 把引用结果里的文本攒进 `asides`，`closeUser` 时插到最后一个 tool_result 之后，落点记 lossy `tool-reference`；用例锁 `[tool_result, tool_result, text, text]`。
**教训**：给 user 消息新加任何非 tool_result 块都要过"排在这批结果之后"这关；单调用绿灯说明不了并行形状，"两个结果之间夹东西"是固定变体。

## 32 [运行时] npm 装的 `bun` / `deno` bin 是 shell 包装，kill 包装的 pid 留下真二进制占端口，后面的臂全 `EADDRINUSE`

**机制**：`spawn` 拿到的是 `/bin/sh` 的 pid，真正的 `bun.exe` / `deno` 继续监听。
**正确做法**：`spawn(..., { detached: true })` 自成进程组，`process.kill(-pid)` 整组收掉；起下一臂前轮询等端口释放。
**教训**：spawn npm 包的 bin 默认它是包装脚本，按进程组 kill；串行复用端口要显式等端口空出来，别靠 sleep。

## 33 [运行时] `Bun.serve` 缺省 `idleTimeout` 10 秒，慢模型调用被无声掐断，客户端只见 "fetch failed"

**机制**：连接空闲超时直接关、不记日志；一次模型调用含 SDK 重试轻松超 10 秒，Bun 进程活着、stderr 空。
**正确做法**：宿主 `Bun.serve({ idleTimeout: 255 })`（上限 255），写进根 README Runtime 注记；拉高后同一格如实报出上游 "servers overloaded"。
**教训**：Agent 循环挂到 Bun 上第一件事是改空闲超时；编排器抓探测失败要带出宿主退出码与两路输出尾巴。

## 34 [运行时] pi 版 OpenAI Responses 路径在 Vercel `edge-runtime` 裸 vm 里抛 "Cannot read properties of undefined (reading 'version')"——Edge 宿主要有 `process` 全局

**机制**：`openai` SDK 6.40 在 `EdgeRuntime` 分支裸读 `globalThis.process.version`（没有 `?.`），Anthropic SDK 同处有防御；裸模拟器有 `EdgeRuntime` 没 `process`。
**正确做法**：库不改；加一个只补 `process.env` 的臂（Vercel 对线上承诺的最小面）后 pi 版 10/10；README 写明。后来真 Vercel 部署 7/7，线上自带 `process`。
**教训**：同风格的两个 SDK 同一处防御可以不同，"Anthropic 路径通了"推不出 OpenAI 也通，每条协议路径单独验；模拟器与线上的差异用只补"官方承诺最小面"的臂量出来。

## 35 [运行时] pi 版在 Deno 最小权限下每次请求失败 "Requires sys access to osRelease"——pi-ai 的 UA 偷读 `os.release()`

**机制**：pi-ai `getPiUserAgent()` 见到 `process.versions.node` 就 `process.getBuiltinModule("node:os")`；Deno 为兼容设了这个字段，又把 `os.release()` 归入需授权的 sys 权限。fetch 版不读系统信息。
**正确做法**：宿主配置，不改库：Deno 起 pi 版给 `--allow-sys=osRelease`；fetch 版只要 `--allow-net`。写进两份降级层 README。
**教训**："零 `node:*` 静态依赖"挡不住 `process.getBuiltinModule`；有权限模型的运行时是最便宜的探测器，运行时矩阵给 Deno 留最小权限臂，别只跑 `-A`。

## 36 [方法论] 运行时文案英文化按词表批量替换，把中文注释里的同一短语也换了，留下"…the text支持 Fable 5.x"式碎片

**机制**：519 处替换不区分字符串字面量与注释；中文标点（`；`、`——`）是词表没收的字符级残留，留在了英文句子里。
**正确做法**：注释按替换前原文改回；用 `grep -rnP "[a-z]{3,}[\x{4e00}-\x{9fa5}]" packages/*/src` 扫"英文词紧贴中文"。
**教训**：批量替换文案限定在字符串字面量（按 AST，至少排除注释行），改完用碎片正则回扫；审查报告点名的位置只是样本，同一词表的其它命中要自己扫全。

## 37 [降级层] fetch 版把别的模型产出的 thinking 签名照发，Sonnet 5 回 400 "Invalid `signature` in `thinking` block"——回放条件精确到型号

**机制**：判"能否回放"只比 provider + api，eval resume fixture 的种子是 DeepSeek 的 Anthropic 端口录的（`replay.provider` 也是 anthropic），喂给 claude-sonnet-5 整格 0 秒 error；Responses 线的加密推理项同理。
**正确做法**：两线统一为 provider + api + model 三者一致才回放，否则 dropped 并在落点里点名两个型号；有损矩阵 `when` 改为"同源"，矩阵测试加"同家另一型号"变体。
**教训**：凡厂商校验的不透明字段（签名、加密项、配对 id），回放条件都精确到型号；fixture 种子跨模型复用时第一格先看能不能发出去。

## 38 [发布] 0.2.0 用 `npm publish` 发，tarball 里依赖是 `workspace:*`，11 个包装不上（`ERR_PNPM_WORKSPACE_PKG_NOT_FOUND`）

**机制**：npm 不认 pnpm 的 `workspace:` 协议原样上传；`pnpm publish` / `pnpm pack` 才重写成版本号。npm 不允许覆盖或重用已发版本号，0.2.0 作废。
**正确做法**：同码加全包 patch changeset 升 0.2.1，从仓库根 `pnpm -r publish --access public --no-git-checks` 重发，0.2.0 `npm deprecate`；步骤写进 `CONTRIBUTING.md`。
**教训**：monorepo 发布只用包管理器自己的 publish；发后必须从官方源空目录**真实安装**冒烟，`npm view version` 只证明传上去了；给 Boss 的操作命令也要先翻归档里的现成做法。

## 39 [降级层] 模型能看图、工具也回了图，Chat 线上模型一张都看不到——协议装不下的内容先找"挪到哪能装下"，占位是最后一档

**机制**：Chat Completions 的 `role:"tool"` 只收文本，encoder 把图换占位、记 lossy；有损声明了，但能力位为真的模型在这条线上静默失明（Anthropic / Responses 原生收图）。发前审查又抓到：第一版在"第一个非 tool_result 条目"前放出附件，而运维事件与 `ext.*` 留痕（dropped）原位夹在同批结果之间，附件插进两条 tool 之间（400）。
**正确做法**：图片上浮到同批 tool 之后的一条 user（原位留指路、untrusted 照包），落点 `tool+lifted-images`，`chat.liftToolImages: false` 可关；dropped 条目不触发放出并加用例。暗号图片的字符集去掉易混字形（W/M、8/B）。
**教训**：三条线按"模型最终看见了什么"对齐，不只按"有没有声明"；"IR 保证同批结果连续"只对会下发的条目成立；用图片做暗号时把 OCR 误差与机制缺陷分开。

## 40 [循环] 感知告诉模型"已 ≥85%、到 85% 自动折叠"，阈值兜底却一次没折——报给模型的读数与框架的触发条件必须同一把尺

**机制**：onset-pause tight 切点（真实约 340K / 窗口 400K）：感知按 `contextOverheadOf` 校准（估算 + 上一请求"真实 − 估算"的固定开销），兜底只拿未校准的投影估算比 `contextLimit − reserveTokens`，没过线。更坏的一面：系统提示 + 工具表大于 reserve 时兜底在厂商 400 之前永远不触发。
**正确做法**：`contextOverheadOf` 搬进 core，`project()` 缺省从时间线取开销，兜底切点与 `overBudget` 共用 `estimateBudgetOf(budget)`；`targetTokens` 与感知文字不变。先写复现用例（旧代码两条都红）。
**教训**："同值同纯函数"也管"报给模型的读数"与"框架真正的触发条件"；告诉模型一个阈值，就要有一条用例锁住"报过线 ⟺ 真的动作"——这是 eval 跑出来的，单测各自正确拼不出来。

## 41 [方法论] 文件改名后批量改写路径，会把快照里"指旧文件"的引用改成"指新文件"——旧名换了语义的不能一律替换

**机制**：2026-10-30 文档换代把 `docs/TASKS.md` 归档、另建内容完全不同的 `docs/待处理任务.md`，路径改写脚本把 `docs/TASKS.md → docs/待处理任务.md` 也套到了 `docs/archive/` 的 7 份冻结文件上，历史记录从此指向一个不相干的文件（还有两处指向新文件里根本没有的章节）。无报错，链接也"不断"，只有按语义对照才看得出。
**正确做法**：每条替换规则先分类——文件只是**搬家**（同一份内容换路径，如 `模块盘点/` → `系统全景图_模块盘点/`）可全仓库替换；旧名被**换了语义**（归档后由新文件接替职责）的，只替换活文档，快照保持旧名并在归档文件头加冻结封条说明旧名指谁。
**教训**：断链检查抓不到"错指"；改写引用后要抽查快照里的引用与目标文件标题是否语义一致，而不只是目标是否存在。

## 42 [方法论] 短文本探针里模型 9/9 照做的"末尾追加说明"，到 30 万 token 的真实会话 0/58——行为结论必须在目标线路、目标长度上验

**机制**：forced-compact 探针（8k～10k token，DeepSeek 官方 + Haiku 5.5）末尾 system 说明 9/9 照做；onset-pause force 臂走公司中转站（OpenCode Go 订阅号池，背后可能有非官方部署）0/4，单次请求 6 种措辞 0/54、暗号指令 0/6。同一现场换官方 `deepseek-flash`（即 V4.1 Flash；`deepseek-v4-flash` 是旧别名）暗号 3/3、整理 6/6；中转站改 `midConversationSystem: false`（user 身份 + `<system_note>`）暗号 3/3、整理 3/3；中转站 system 说明 + 用户追问暗号 3/3 答对——内容到了，只是不被当作要执行的指令。
**正确做法**：长上下文行为在目标线路、真实长度上用"决策现场单次请求"验（`examples/eval/fixtures/onset-pause/wording.ts`：从录像截到决策点、只走一步，并发、几美元）；先用暗号法分开"没送到 / 送到了不执行 / 执行了"。号池类中转对中途 system 不可信时，宿主声明 `midConversationSystem: false`。
**教训**：探针的照做率不能外推到长上下文与别的线路；排查线路问题只用正式降级路径发请求——手写请求体测出的 400 曾让我误判"中转站换了路线"。
