## 1. 架构原则（由宪法推出的工程约束）

| # | 原则 | 工程含义 |
| --- | --- | --- |
| P1 | 决策权默认在模型 | 任何"框架替模型做决定"的逻辑必须同时提供"模型自决"路径，且后者为默认；框架动作降为兜底 |
| P2 | 时间线是唯一真源 | 内部只有一种数据：带发起者的事件；角色格式只在降级层出现；不存在第二份"消息数组"真源 |
| P3 | 不拥有循环 | 循环是一个导出的普通异步生成器函数，几百行，无私有状态；用户可复制修改后仍能接入所有模块 |
| P4 | 一切可拆 | 每个脑子模块是独立包中的独立对象，通过统一插座挂到循环上；移除任一模块不破坏其余 |
| P5 | 运行时无关 | 核心包零 Node 内置依赖，只用 Web 标准 API；子进程、`node:vm`、真实文件系统只出现在可选包 |
| P6 | 进程可随时死亡 | run 状态可序列化；暂停是显式返回值；任何事件边界可重入 |
| P7 | 有损必声明 | 降级层对每种事件声明在每家 API 上是否有损；禁止静默丢弃 |
| P8 | 无 eval 不默认开 | 模型自决类机制附 eval 并达标后才默认开启，否则默认关闭 |
| P9 | schema 有版本 | 事件 type 各自带 schemaVersion；读时升级；查不到升级函数即拒绝读取 |

## 2. 总体结构

```
宿主应用（TanStack Start / Hono / Next / 任意 fetch 服务端）
   │  (Request) => Response            ← @reins/server：Web 标准 handler，SSE 由宿主注入
   ▼
┌───────────────────────── 循环 Loop（@reins/core，可复制）─────────────────────────┐
│  for each turn:                                                                │
│    events   = eventLog.read(session)                                           │
│    ctx      = projection(events, budget)        ← 过滤 → 折叠 → 注入 → 预算     │
│    request  = lowering.toRequest(ctx, tools)    ← 事件 → 某家 API 请求          │
│    for e of lowering.stream(request): eventLog.append(e)                       │
│    for call in toolCalls: policy → execute/spill → eventLog.append(result)      │
│    decide: continue | paused(serializable) | done | handoff                     │
└────────────────────────────────────────────────────────────────────────────────┘
   ▲ 插座 Socket：beforeModel / afterModel / beforeTool / afterTool / onTurnEnd
   │
┌──┴──────────── 脑子 Brain（@reins/brain，每个模块独立可拆）────────────────────────┐
│ perception  compact  pins(幸存契约)  spill  handoff  memory  approval  budget  │
└────────────────────────────────────────────────────────────────────────────────┘
   │
┌──┴─────────────── 存储接口 Stores（接口在 core，实现在可选包）─────────────────┐
│ EventLog（append-only）   BlobStore（外溢与附件）   MemoryStore（记忆文件）      │
└────────────────────────────────────────────────────────────────────────────────┘
   │
┌──┴─────────────── 降级 Lowering（@reins/lowering-pi，包裹 pi-ai）──────────────────┐
│ 事件 → Anthropic / OpenAI Responses / 其余 10 种线协议；流式响应 → 事件          │
└────────────────────────────────────────────────────────────────────────────────┘

投影方向（同一条时间线的多种视图）：
  → 模型上下文（projection）   → 前端（@reins/ui-agui）   → 审计回放（原样 + replayTurns 逐轮重算）   → eval fixture（@reins/eval）
```

**同一插座的三种宿主：** 我们的默认循环；TanStack AI 的 middleware（S2 核实，0.53.0：`onConfig` 对应 beforeModel，可同时返回 `providerMessages` 与 `systemPrompts`；`onBeforeToolCall`/`onAfterToolCall` 对应工具钩子；`onInterruptBoundary` 对应审批暂停；`onShouldContinue`/`onUsage` 对应预算；`onChunk` 对应模型事件入日志）；pi-agent-core 的 `transformContext`/`beforeToolCall`/`afterToolCall`。脑子只依赖插座，不依赖循环实现。TanStack 的消息角色无 system，`system_note` 在该路径有损（见 §11）。

## 4. 核心数据模型：事件时间线

沿用 v0.1 §4.1，补充信任与来源字段。

```ts
interface EventBase {
  id: string                      // uuidv7，时间有序
  sessionId: string
  seq: number                     // 会话内单调递增
  at: number                      // Unix ms
  type: string                    // "core.user_message" | "core.tool_result" | "ext.*"
  schemaVersion: number
  actor: "user" | "model" | "tool" | "system" | "host"
  parentId?: string               // 因果链 / 分叉点
  trust: "principal" | "system" | "model" | "untrusted"   // 工具输出与外部内容默认 untrusted
  provenance?: { source: string; ref?: string }           // 哪个工具、哪个 URL、哪个用户
  replay?: Record<string, unknown>                        // thinking signature / encrypted reasoning 等厂商回放数据
}
type Event<T extends string, P> = EventBase & { type: T; payload: P }   // 载荷统一放 payload，壳永远稳定
type ContentPart = { type: "text"; text: string } | { type: "image"; mime: string; data: string /* base64 */ }
```

实现（T3，`packages/core/src/events/`）：载荷放在 `payload` 字段下而非平铺，升级函数只碰 payload；`EventSchemaRegistry` 登记 type → 当前版本 + 逐级 upcaster，`read()` 对未知 type、未来版本、缺升级步骤、壳字段畸形一律抛 `SchemaError`（fail-closed）；登记时即校验升级链完整，宁可启动报错；`createEvent` 从注册表取版本号，未登记的 type 写不进日志；`trust` 缺省按 actor：user→principal、system/host→system、model→model、tool→untrusted；id 为自实现的 uuidv7（仅 `crypto.getRandomValues`）。

核心事件类型（`core.*`）：

| type | 载荷要点 | 备注 |
| --- | --- | --- |
| `user_message` | content parts | 中途插话就是再 append 一条 |
| `model_text` / `model_thinking` | text；thinking 带 replay | |
| `tool_call` / `tool_result` | toolCallId、name、args / content parts、isError、`spilled?: {blobId, summary}` | 结果外溢时 content 只留指引 |
| `system_note` | kind: "perception" \| "pin" \| "budget" \| "host"，text，`meta?`（不进模型上下文），`supersedes?: id[]`（取代的旧说明，B3） | 脑子注入的一切都是可见事件 |
| `approval_request` / `approval_decision` | toolCallId、policyId、摘要 / approved、by | 审批是事件级，可跨进程 |
| `compaction` | coversSeq [from,to]、summary、decidedBy: "model" \| "threshold"、pinsKept[] | 不删原事件，只追加 |
| `handoff` | toSessionId、summary、triggerMessage、reason | |
| `memory_op` | op、path、bytes | 模型读写记忆留痕 |
| `budget_usage` | tokens、toolCalls、wallMs、remaining | 用量是事件，宿主可聚合配额 |
| `run_paused` / `run_resumed` | reason、stateRef | |
| `error` | 分类、message、retryable | |

不变量：EventLog 只 append；压缩、外溢、交接都以追加事件表达；模型可见的一切都在日志里（"model-visible ⟺ logged"）。

Schema 演进：沿用 v0.1 §8（只加可选字段不升版本；改义升版本；读时 upcast；查不到拒绝）。**读时升级发生在 `readTimeline` / `readEvents`（`@reins/core` store 层，T16）**：存储实现只原样存取、不认识 schema；循环每轮、run 起步、server 补发与预校验、回放全部经它读，逐条 `registry.read`，未登记的 ext.* 或未来版本在写任何东西之前抛 `SchemaError`。宿主有 ext.* 事件时通过 `LoopConfig.registry` 给自己的注册表。

## 5. Store 接口

```ts
interface EventLog {
  append(events: Event[]): Promise<void>                       // 同会话原子
  read(sessionId: string, opts?: { fromSeq?: number; toSeq?: number }): AsyncIterable<Event>
  tail(sessionId: string, n: number): Promise<Event[]>
  fork(fromSessionId: string, atSeq: number, toSessionId: string): Promise<void>
}
interface BlobStore {   // 外溢结果、附件、代码执行文件
  put(bytes: Uint8Array | string, meta: { mime: string; sessionId: string }): Promise<{ id: string }>
  get(id: string): Promise<{ bytes: Uint8Array; meta: BlobMeta }>
  slice?(id: string, range: { start: number; end: number }): Promise<Uint8Array>   // 可选：模型分段取回
}
interface MemoryStore {  // 记忆工具后端，路径限定在 /memories 下
  list(prefix: string): Promise<string[]>
  read(path: string): Promise<string | null>
  write(path: string, content: string): Promise<void>
  delete(path: string): Promise<void>
}
```

- 契约细则（T4 落地，`packages/core/src/store/`）：`append` 由调用方分配 seq，日志只校验同会话且从末尾 +1 连续（首条为 1），整批先校验再写；不连续抛 `StoreError("seq_conflict")`，这就是乐观并发控制。`fork` 原样复制 [1, atSeq]（保留 id 与 seq，只换 sessionId）以维持 parentId / pinsKept 引用，目标会话必须为空。`read` 区间闭合，`tail` 升序。BlobStore 字符串按 UTF-8 存，`get` 缺失抛 `not_found`；MemoryStore `delete` 幂等，路径限定由 memory 工具层负责。
- 允许部分实现：只实现 EventLog 即可跑；缺 BlobStore 则 spill 模块自动关闭并告警；缺 MemoryStore 则 memory 工具不注册。
- 每个接口附一致性测试套件，入口 `@reins/core/testing`（T5）：只要求宿主传入 `{ describe, it }`，断言自带，vitest / node:test / bun:test 皆可；内存实现是参考实现，必须全绿。
- 默认实现：内存（零依赖）、SQLite（可选包）、Postgres（可选包，dogfood 宿主投放工具用 pg，与 SQLite 同在 M1 B9）。

## 6. Run 状态与暂停

```ts
type RunResult =
  | { status: "done"; sessionId: string; lastSeq: number }
  | { status: "paused"; sessionId; lastSeq; reason: "approval" | "budget" | "host"; interruptions: Interruption[]; state: SerializedRunState }
  | { status: "handoff"; sessionId; lastSeq; toSessionId: string }
  | { status: "error"; sessionId; lastSeq; error: ErrorEvent }

type Interruption =
  | { kind: "approval"; toolCallId; request: ApprovalRequestPayload; call: ToolCallPayload }
  | { kind: "client_tool"; toolCallId; call: ToolCallPayload }     // 客户端工具，等宿主回填 tool_result
  | { kind: "budget" | "host"; note: string }

// 恢复：任何进程、任何实例。同一 sessionId 再跑一次即续跑；带 resume 多一层校验
runLoop({ sessionId, log, lowering, model, tools, secret,
          resume: JSON.parse(stateFromUrl), decisions: [{ toolCallId, approved: true, by: "boss" }] })
```

- `SerializedRunState` 只含 sessionId、lastSeq、pending 工具调用 ID、配置摘要（SHA-256 of 模型 + 工具名 + 系统提示）、pending 入参摘要（SHA-256 of 各调用的 id/名/入参），配了密钥再加 HMAC-SHA256 签名；内容全部从 EventLog 重读。实测不到 400 字节，能放 URL 参数或 KV。
- **恢复校验（T10）fail-closed，全部通过才写日志**，顺序：形状 → 会话一致 → 签名（配了密钥而无签名或签名不符都拒）→ 配置摘要一致（可 `allowConfigDrift` 放行）→ 日志不短于状态 → 日志里的 pending 调用与状态的 ID 列表、入参摘要一致 → `decisions` 都指向 pending 调用。不通过抛 `RunStateError`（8 种 code）。通过后 append `run_resumed(by)`、逐条 `approval_decision`，然后走"补齐 pending 调用"。不配密钥则不签名不验签，只适合可信环境。
- **续跑的统一机制（T9）**：每轮开始先扫时间线，凡是没有 `tool_result` 的 `tool_call` 都算 pending，先补齐再问模型。审批暂停、宿主中止、进程死亡、客户端工具回填，恢复时走的都是这一条路。已有 `approval_decision` 的按决定办（拒绝 → `tool_result(isError)`），已发过 `approval_request` 还没决定的不重复发、再次暂停。
- 嵌套（子代理）的审批冒泡到最外层 run（借 OpenAI Agents SDK）。

## 7. 循环与插座

```ts
export async function* runLoop(cfg: LoopConfig): AsyncGenerator<Event, RunResult> {
  // 约 600 行（M0 收口实测 578 行含注释），无私有状态，用户可整个复制。yield 每一条刚 append 的事件
}

interface Socket {                       // 脑子与底盘之间唯一的契约；钩子可不返回 = 无意见
  tools?: readonly Tool[]                // 静态贡献（B2）：模块带给模型的工具，整个 run 不变，续跑补齐 pending 时也在场，计入 configHash
  systemPrompt?: string                  // 静态贡献（B2）：规则提示片段，追加在宿主系统提示之后（空行分隔），整个 run 不变
  beforeModel?(ctx): BeforeModelPatch | undefined        // { events?, tools?, systemPrompt? } 顺序合并（后一个 Socket 在 ctx 里看到前一个改过的）；期间 emit 的事件本轮即可见
  afterModel?(ctx, events: Event[]): void
  beforeTool?(ctx, call: ToolCallEvent, tool: Tool | undefined): "proceed" | { block: string } | { defer: { policyId, summary } } | { rewrite: unknown } | undefined
  afterTool?(ctx, call, result: ToolResultDraft): ToolResultDraft | undefined   // 结果此时尚未 append，返回即替换（外溢、截断）
  onTurnEnd?(ctx): "continue" | "stop" | { handoff: HandoffIntent } | { pause: { reason: "budget" | "host"; note? } } | undefined
}
interface TurnContext {
  session: { id; turn }; principal?: Principal
  events: Event[]                        // 当前投影结果（可读）
  timeline: readonly Event[]             // 完整时间线快照（回看被折叠的事件）
  log: EventLog; blobs?: BlobStore; memory?: MemoryStore
  tools: readonly Tool[]; model: ModelRef
  budget: { contextLimit; used; tokensSpent; turns; toolCalls; wallMs }
  capabilities: LoweringCapabilities     // 本模型支持什么（中途 system、thinking 回放、并行工具）
  signal?: AbortSignal
  emit(e: EventDraft): void              // 草稿：无 id / seq / at / sessionId，循环补齐后 append
}
```

- 多个 Socket 按注册顺序执行。`beforeTool` 任一 `block` / `defer` 即定，`rewrite` 替换入参后继续问下一个；`onTurnEnd` 第一个给出意见的定，都无意见时"本轮有工具调用则继续，否则结束"。
- 静态贡献与动态补丁分两条路（B2）：模块给模型的工具与规则提示走 `Socket.tools` / `Socket.systemPrompt`，循环起步并入（宿主同名工具优先），整个 run 逐字不变——这是 §9.1 约束 3（系统提示与工具表每轮稳定）的落点，也让续跑补齐 pending 调用时模块工具在场；`beforeModel` 补丁留给真正的动态改动（宿主换场景、按 principal 增删工具），每改一次缓存前缀重算。
- 循环只有两处兜底（P1）：工具声明 `needsApproval` 且没有 Socket 做主时转审批暂停（policyId `tool.needsApproval`）；轮数达到 `maxTurns`（缺省 100）时 `paused(budget)`。细粒度预算在 B8。
- 每轮模型调用后循环 append 一条 `budget_usage`（用量、本轮工具调用数、耗时）；降级层 `stopReason=error` 或抛异常 → append `core.error` 并返回 `error` 态，已产出的内容块仍在日志；`aborted` → `paused(host)`，未回答的 tool_call 记为 pending。
- 工具执行：未知工具、`validate` 抛错、`execute` 抛错一律以 `tool_result(isError)` 告知模型，循环不崩；`execute` 返回值按 `normalizeToolOutput` 归一（string → 文本；ContentPart[] 原样；`{content,isError}` 原样；其余 JSON）；工具经 `ctx.emit` 留的痕（如 memory_op）排在结果之前。`side: "client"` 或无 `execute` 的工具 → `paused(host)` + `client_tool` 中断，宿主回填 `tool_result` 后续跑。
- 交接：`onTurnEnd` 返回 handoff → 旧会话 append `core.handoff`，新会话 seq 1 为 `system_note(kind=host, summary)`、seq 2 为 `user_message(triggerMessage)`（Anthropic 的 system 不能为首条由降级层归位解决），调用 `cfg.onHandoff(from, to)`，返回 `handoff` 态；续跑新会话由宿主再起一次 runLoop。
- 测试用 `@reins/core/testing` 的 `ScriptedLowering`：按剧本逐轮吐草稿，记录每轮 `toRequest` 输入，脑子模块与适配器的单测都靠它。
- TanStack AI 与 pi 的适配器只是把各自钩子翻译成这五个方法。

## 8. 投影（Projection）

策略链，输入完整时间线，输出模型本轮应看到的事件：

1. **过滤**：按可见性剔除运维事件（approval_*、run_paused/resumed、budget_usage、memory_op、handoff、error 默认不给模型看），宿主可加 principal 可见性判定。trust 标注（不可信内容加显式标记，不删除）**由降级层做**：事件已带 trust 字段，翻译成文本时按它包裹，投影不复制事件、不篡改 payload
2. **折叠**：用 `compaction` 事件替代其覆盖的 seq 区间；被折叠的原事件仍在日志。多条 compaction 的隐藏范围取并集，被盖住的旧摘要不再可见但其范围仍生效。摘要放在**被覆盖区间的位置**而非自身 seq 位置，所以投影输出顺序可以与 seq 不一致（视图给模型看，日志才按 seq）
3. **钉住**：幸存契约。被覆盖的事件只有在**每一条**覆盖它的 compaction 都保留时才幸存：出现在 `pinsKept`，或它本身是 `system_note(kind=pin)`（自动幸存，默认开，模型 pin 过的东西默认穿越折叠）。**被后来某条 `system_note.supersedes` 指到的事件一旦被覆盖就不再幸存**，不论谁保留过它（B3：append-only 日志里撤销一条钉住的唯一表达；取代者在完整时间线里找，自己被折叠了也算）。幸存者重排到覆盖它的最新摘要之后
4. ~~感知注入~~（B1 后移出投影链）：感知说明是 `@reins/brain` 的 Socket 在 `beforeModel` 里 emit 的**真实事件**，由循环追加到时间线末尾，模型本轮即见；投影只负责"看历史"，不负责"说话"。这样才满足 §9.1 的 prompt cache 约束（只追加、不改前缀），回放时它也和其他事件一样凭日志重现。默认链因此是四步
5. **预算裁剪**：仍超限时的最后兜底。按"轮"从最旧裁掉一个前缀，新造 `compaction(decidedBy=threshold)` 放最前、幸存 pin 紧随。切点三条硬规则：只在轮边界切（assistant 轮 = 连续 thinking/text/tool_call）；保留部分首轮不含 tool_result（不留孤儿结果）；seq 封闭（保留部分 seq 全大于被裁部分，保证新 coversSeq 是干净区间）。被裁的旧摘要原文并入新摘要。裁到只剩最后一轮仍超限则 `stats.overBudget=true`，交上层告警

投影是纯函数（T6，`packages/core/src/projection/`）：`project({ timeline, budget, strategies?, estimate?, registry?, now?, newId? }) → { events, emitted, stats }`。随机与时间全部从参数注入，同一输入逐字同一输出。策略新造的事件（目前只有阈值 compaction）通过 `emitted` 交给循环 append 进日志，seq 按时间线末尾预分配，冲突则重跑投影 —— 模型看到的每一条都要落日志。token 估算默认粗估（ASCII 4 字一 token、非 ASCII 一字一 token、图片 1600），宿主可注入精确 tokenizer；`reserveTokens` 缺省为窗口的 15%。

回放（T15，`packages/core/src/replay/`）：`replayTurns(timeline, { budget, strategies?, estimate?, registry? }) → { turns, preamble }`。因为投影是纯函数、循环又在每次请求前把模型将看到的一切先写进日志，所以"第 n 轮模型看到的" = project(该轮第一条模型输出之前的全部事件)，不需要额外的"请求开始"事件。每个 turn 给出 `requestAtSeq`、`visible`、`stats`、`output`（连续的 model 事件）、`aftermath`（到下一轮之前的工具结果 / 用量 / 暂停等）、`usage`（该轮 budget_usage）；重算若新造事件则 `diverged=true`（现在的策略或估算与当时不同，visible 不再是当时的事实）。边界：Socket 用 `patch.events` 整体替换投影的部分不可重算；一条模型输出都没回来的失败轮识别不出请求边界。示例 `examples/minimal/replay.ts` 在此之上叠加降级层 `toRequest` 的落点，生成终端时间线与静态页面。

## 9. 脑子模块规格

每个模块实现 `Socket` 的若干方法，注册若干工具，附开关、按模型族配置与 eval。

### 9.1 perception（感知）

- `beforeModel`：注入一条 `system_note`，含上下文使用档位（如 <50% / 50~70% / 70~85% / 85%+）、最旧未折叠段的年龄、本会话已用 token 与预算余量、上次整理位置、工具结果外溢数量。数值按档位而非精确值，减少 cache 抖动；每档只变一次。
- **prompt cache 约束（2026-09-08 与 Boss 达成共识，B1 实现时必须遵守）**：
  1. 感知说明**只追加在时间线末尾**（作为新事件 append，模型看到的顺序按 seq），天然落在最新 user 消息之后、模型回答之前；前面的历史一字不改，缓存前缀不受影响。Anthropic 中途 system 的摆放规则（S1：紧跟 user 轮）与此一致。**禁止**放在系统提示里或对话开头。
  2. **旧的感知说明不删、不隐藏**。隐藏一条曾经可见的事件等于改前缀，比多留几十个 token 更贵；每换一档才追加一条，一段会话通常三四条，整理时随历史一起折叠。这是宪法二"只追加"的自然结果。
  3. **系统提示与工具表每轮必须稳定**。`beforeModel` 的 `systemPrompt` / `tools` 补丁是给宿主换场景用的，感知不走这条路；改一次 = 整段前缀重算。
  4. 缓存本身不自造：pi-ai 已在系统提示、工具表末尾、最后一条 user 消息打 `cache_control` 断点，OpenAI Responses 用会话 id 作 `prompt_cache_key`；reins 只负责不破坏它，并用 `budget_usage.tokens.cacheRead / cacheWrite` 量出来。
  5. 唯一允许打掉缓存的是 compaction：折叠替换历史中段，前缀必变，所以只在轮次边界、由模型自决地做，把"重算一次缓存"当成有意识的花费。
- eval：与不注入对比，模型自决整理的时机质量（过早/过晚率）；**注入前后 cacheRead 占输入的比例不得下降**（§17 待核实项在 B1 验收时一并关闭）。
- 可选桥接 Anthropic task budget（模型支持时由服务端注入倒计时，我们不重复）。
- **实现（B1，`packages/brain/src/perception/`）**：`perception(options): Socket`。`beforeModel` 用 `readPerception(ctx)` 算读数 → `render` 成文字 → 与模型**当前可见**的最后一条感知说明逐字比较，相同则什么都不做，否则 `ctx.emit` 一条 `system_note(kind=perception, meta.reading=读数)`；永远返回 `undefined`（不碰 systemPrompt / tools）。读数：上下文使用率（估算 / contextLimit，缺省档 [0.5, 0.7, 0.85]）、阈值兜底触发点（`targetTokens / contextLimit`，新增到 `TurnContext.budget.targetTokens`）、可见的未折叠模型轮数（[5, 15, 40]）、会话整理次数（精确，只在整理时变）、会话累计 token（按 budget_usage 累加含缓存读写，[1e4, 5e4, 2e5, 1e6]）、可见外溢结果数（0 单列，[3, 10]）、配置 `limits` 时最紧一维的余量（[0.05, 0.2, 0.5]）。判重按文字而非读数：宿主自定义 `render` 后，模型看到的没变就不追加。折叠把旧说明盖掉后视图里没有说明，会重新注入一条（追加在末尾，不改前缀）。`system_note.meta` 是 T3 之后新增的可选字段（不升版本），降级层不翻译它。
- **缓存断点（B1 修的降级层问题）**：pi-ai 把 Anthropic 的 `cache_control` 打在"最后一条 user 消息"上；感知说明追加在末尾时，进 pi-ai 时它正是那条伪装成 user 的标记消息，`onPayload` 改写成 system 后断点就没了，而官方规则是"最后一个断点之后的内容一律不缓存"（`input_tokens` 的定义），整段历史都会按原价计费。处置做成 `PiAiLowering.midSystemCacheBreakpoint`，**缺省 `automatic`**：去掉该块级断点、在请求顶层补 `cache_control`（Anthropic 自动缓存：断点自动落在最后一个可缓存块上，与显式断点兼容、占 4 个槽位之一，满了就放弃不让请求 400）。实测（`spikes/b1-perception-cache`）：`automatic` 与不注入持平；`previous-user`（搬到前一条 user）低 3~6 个点；留在 system 消息本身上会让整段提示每次重写、命中率崩到 20% 以下，故不提供。第二家 Anthropic 协议上游 DeepSeek（`spikes/deepseek-anthropic-check`）接受顶层字段、注入亦不降命中，但其缓存全自动、分辨不出断点处置，直连官方 Anthropic 的对照仍未做。第三方上游是否接受中途 system 由 `ModelDefinition.midConversationSystem` 声明，缺省不支持。OpenAI Responses 用 `prompt_cache_key`，无此问题。

### 9.2 compact（自主整理）

- 工具 `compact({ keep: string[]; summary: string; coverUntilSeq?: number })`：模型给出保留要点与总结；库生成 `compaction` 事件；投影层折叠。
- 规则提示（一等交付物）：子任务完成、轨迹收敛时整理；推导中途、卡住时不整理；整理时逐条确认 pins 已包含。
- 兜底：使用率超硬阈值仍未整理 → `threshold` 整理并记事件；连续整理次数上限（默认 3）→ 暂停并告警。
- 只在轮次边界执行；产物追加不改写。
- eval：对照纯阈值，指标 token、完成率、关键信息召回、cache 命中率、死循环计数。
- **实现（B2，`packages/brain/src/compact/`）**：`compact(options): Socket`，工具与规则提示走 Socket 的静态贡献（§7）。工具入参 `{ summary, keep: string[], keepRecentTurns?: number }`——方案里的 `coverUntilSeq` 换成 `keepRecentTurns`，因为模型看不到 seq，能感知的是"最近几个模型轮"。真正的工作在 `afterTool`（需要 TurnContext 里的视图与完整时间线，ToolContext 没有；工具自己 readTimeline 会绕开宿主注册表）：按视图算出 `compaction(decidedBy=model, actor=model, parentId=tool_call)` 经 `ctx.emit` 入日志（顺序 tool_call → compaction → 回执 tool_result），再把结果换成回执。切点规则与投影裁剪同口径：只在模型轮边界切、发起调用所在的模型轮永不折（续跑 pending 时它在视图里，Anthropic 要求 thinking + tool_use 一起回放）、seq 封闭（旧 compaction 的 seq 不小于保留部分最小 seq 时不吸收、留在视图里继续可见；全部折叠时才吸收）。幸存者进 `pinsKept`：kind=pin 的说明、旧 compaction 已保留的事件，以及**被折叠范围内最近的一条用户消息**（真模型实测里模型把"先整理，然后做 X"这条指令折了进去、整理完反问 X 是什么；模型无法复述它还没处理的指令，所以由库保住，长任务里这就是原始任务陈述）。**阈值兜底**不重复实现：core 投影链的 `budgetTruncate` 在估算超过 `contextLimit − reserveTokens` 时机械折叠并记 `compaction(decidedBy=threshold)`，本模块只把它算进连续计数。**连续上限** `maxConsecutive`（缺省 3）：把完整时间线按轮切段（一轮 = 开轮时追加的兜底 compaction / 系统说明 + 模型输出 + 之后到下一轮之前的一切），从最近一轮往前数连续含 compaction 的轮里 compaction 的总数（模型自决 + 阈值兜底合计），加上本轮的，达到上限且本轮仍有工具调用（模型没收尾）→ `onTurnEnd` 返回 `pause(budget)` 交宿主处理。规则提示 `COMPACT_RULES`（英文，只讲经验不下指令）可整体替换或 `rules: false` 由宿主自放。真模型核实见 `spikes/b2-compact-live/`。

### 9.3 pins（幸存契约）

- 宿主声明 `pins: PinSpec[]`（静态文本或从事件中抽取的函数，如"最近一条用户明确约束"）；模型也可通过 `pin({ text })` 工具自行钉住。
- 折叠后由投影重注入；`compaction` 事件记录 `pinsKept`。
- eval：治理衰减测试（压缩前后约束违规率），目标 0% 不上升。
- **实现（B3，`packages/brain/src/pins/`）**：幸存契约本身在 core 投影链（T6：kind=pin 自动幸存、`pinsKept`、重排到摘要之后），本模块 `pins(options): Socket` 只让契约有人用。**宿主声明** `pins: PinSpec[]`——字符串（静态文本，名字即文本）、`{ name, text }`（命名静态文本）、`{ name, extract(ctx) }`（每轮从 TurnContext 抽取，返回 undefined 表示"没新说法、上一条继续生效"）；`beforeModel` 算出每条文字，与模型**当前可见**的同名（`meta.pin.spec`）pin 逐字比对，相同不动，不同（首轮 / 内容变了 / 被折掉了）就 emit 一条 `system_note(kind=pin, actor=system)` 追加在末尾，`supersedes` 指向该 spec 在完整时间线里的上一条；永不返回补丁（§9.1 只追加不改前缀）。**模型工具** `pin({ text, replaces? })`（静态贡献 + 规则提示 `PIN_RULES`，可 `tool: false` 只留宿主 pin、`rules` 替换或关闭）：工作在 `afterTool`（要视图判重、找被替换者），emit `system_note(kind=pin, actor=model, parentId=tool_call)` 再换回执；同文已钉不重复；`replaces` 须逐字匹配**模型自己钉的**（`meta.pin.source="model"`），指向宿主 pin 报错——宿主的约束模型动不了；单条缺省 ≤500 字。**取代**：core 新增 `SystemNotePayload.supersedes?: string[]`（可选，不升版本），fold / truncate / compact 规划三处幸存判定一致地排除被取代者（`supersededIds(timeline)`），旧值到下一次折叠才消失、折叠前照常可见。没有 unpin：撤销就是钉一条当前有效的说法去替换旧的。13 个 brain 用例 + 4 个 core 用例。

### 9.4 spill（结果外溢）

- `afterTool`：结果超 `maxResultTokens`（默认 8k，可按工具配置）→ 写 BlobStore，结果替换为 `{ 摘要（首尾各 N 行）、blobId、取回指引 }`；追加 `tool_result.spilled`。
- 工具 `fetch_blob({ id, range? })` 让模型分段取回。
- 同一 BlobStore 将来挂进代码执行沙箱的文件系统。

### 9.5 handoff（会话交接）

- 工具 `handoff({ summary, nextSteps, triggerMessage })`：库建新会话、写 `handoff` 事件到旧会话、在新会话首条 append `system_note(kind=host)` 携带 summary 与 pins、返回 `RunResult.handoff`。
- 宿主实现 `onHandoff(from, to)` 重绑对话锚点（聊天窗口、频道等）。
- 通用化 anima switch_session v3：事务性、旧循环优雅退出、新会话自动续接。

### 9.6 memory（记忆）

- 工具形状对齐 `memory_20250818`：view / create / str_replace / insert / delete / rename，路径限定 `/memories`，防路径穿越。
- 后端 MemoryStore 由宿主实现。
- 提示片段：任务开始先查记忆；只记未来有用的；不记能从代码或文档推出的。
- 模型每次读写留 `memory_op` 事件。

### 9.7 approval（审批与权限）

- 工具声明 `needsApproval: boolean | (input, ctx) => Promise<boolean>`；`risk: low|medium|high`。
- Policy 管线：deny → ask → allow，首匹配即定；deny 不可被 allow 覆盖；管线在所有钩子之前无条件执行；决策本身是 `approval_*` 事件。
- `ask` → `run_paused` + `RunResult.paused`；恢复见 §6。
- fail-closed：策略求值异常视为 deny。
- 默认：只读工具 allow，写与外部副作用 ask，未知 deny。

### 9.8 budget（预算）

- 上限：contextTokens、totalTokens、turns、toolCalls、wallMs；任一触顶 → `run_paused(reason=budget)`，模型在触顶前收到 perception 提醒。
- 每轮 append `budget_usage`；宿主可聚合做 per-user 配额（库不做配额）。

## 10. 工具模型

四个正交维度（不是四种工具类型）：

```ts
interface Tool {
  name: string; description: string; inputSchema: JSONSchema        // 原样给模型；不绑 Zod
  validate?: (input: unknown) => TInput                             // 可选校验/转换，抛错 = 入参不合法（T9：不引 StandardSchema，宿主用任何校验库包一层即可）
  side: "server" | "client" | "sandbox" | "provider"                // 执行位置
  execute?: (input, ctx: ToolContext) => Promise<unknown>          // 缺省 = 转客户端；返回值经 normalizeToolOutput 归一
  lazy?: boolean                                                    // 暴露策略：延迟加载/发现
  allowedCallers?: ("direct" | "code")[]                            // 可被代码模式调用
  toModelOutput?: (out) => ContentPart[]                            // 结果处置：多模态与压缩
  resultPolicy?: { maxTokens?: number; overflow: "truncate" | "spill" }
  needsApproval?: boolean | ((input, ctx) => Promise<boolean>)      // 人机交互
  risk?: "low" | "medium" | "high"
  ui?: { resourceUri: string }                                      // MCP Apps 形态，第三期
}
type ToolSource = inProcess(tools) | mcp({ transport: "stdio" | "http", ... }) | openapi({ spec, operations })
```

- MCP 客户端用 `@modelcontextprotocol/client@2`；stdio 传输只在 Node 可选包中提供（P5）。
- 代码模式是同一批工具的另一种投影（类型 stub + 沙箱绑定），第三期。
- 模型自建能力走进程内注册，不走 MCP（规范禁止工具集按连接变化）。

## 11. 降级层（Lowering）

- 接口在 `@reins/core/lowering`（T7）：`capabilities(model)`、`toRequest({ events, tools?, model, systemPrompt? }) → LoweredRequest`、`stream(req, { signal?, onDelta? }) → AsyncGenerator<EventDraft, LoweringOutcome>`。草稿只在内容块完整时产出（签名类回放数据此时才齐），流式增量只经 `onDelta` 给 UI；返回值带停止原因、用量、成本，由循环记成 `budget_usage` / `error`。
- `LoweredRequest.landings` 对每条输入事件记一条落点 `{ kind: exact | lossy | dropped, landing, note }`；`lossesOf(req)` 取非 exact 项。实现导出 `LossMatrix`（api → 事件 type → 可能落点），T8 测试断言实际落点必在声明内、矩阵无死条目。
- 第一版 `PiAiLowering`（`@reins/lowering-pi`）：事件 → pi-ai 三角色 Message[] → 线协议；连续 model 事件合成一条 assistant 消息，来源（replay 的 provider/api/model）不同则分开；pi-ai 类型不出此包，宿主自定义模型用 `ModelDefinition` 描述。
- `system_note` 落点（S1 核实）：Anthropic 支持中途 system 的模型族（Fable 5.x / Mythos 5.x / Opus 5 / Opus 4.8）与全部 OpenAI Responses（developer / system 角色）为 exact；做法是先以带内部标记的 user 消息进 Context，在 pi-ai 公开的 `onPayload` 钩子里改写并归位（Anthropic 规则：紧跟 user、后接 assistant 或收尾、不可为首条）。不支持的模型以 `<system_note kind=…>` 标签包住走 user，记 lossy。`compaction` 一律 user 文本，记 lossy。
- thinking 回放：事件 `replay` 记 `{ provider, api, model, thinkingSignature, redacted? }`（Anthropic 为 signature，OpenAI 为整个 reasoning item 的 JSON）。无签名或来源不同记 lossy。OpenAI Responses 只在请求带 `reasoningEffort`/`reasoningSummary` 时开 reasoning 并返回 `encrypted_content`，`capabilities.thinkingReplay` 按实例的 requestOptions 如实声明。
- `capabilities`：`midConversationSystem`（按模型族）、`thinkingReplay`、`parallelTools`、`taskBudget`（Opus 5 / Fable 5.1）、`images`、`contextWindow`、`maxOutputTokens`。
- pi-ai pin `@earendil-works/pi-ai@0.85.1`（原 `@mariozechner/pi-ai` 已 deprecated）；只从 `api/<api>` 与 `providers/<name>.models` 子路径导入，不用 `compat` 入口与 `providers/all`；升级走契约测试（假 fetch 断言请求体与 SSE 译回）。

## 12. 服务端与前端

- `@reins/server`（T12）：`createAgentHandler(agent, options?)` 返回 Web 标准 `(Request, ctx?) => Promise<Response>`，Node / Bun / Workers / Deno 同一份代码（Node 与 miniflare/workerd 实测）。
  - **POST** `{ sessionId?, input?, lastSeq?, resume?, decisions? }`：先补发 `(lastSeq, 末尾]`，再起 `runLoop`，实时推每条刚 append 的事件，结束给 `result` 帧（RunResult 四态，paused 含可回传的 state）。缺省新建会话，id 回在 `X-Reins-Session` 头与 `start` 帧。审批续跑 = 同一接口回传 `resume` + `decisions`。
  - **GET** `?sessionId=&lastSeq=`（或 `Last-Event-ID` 头，EventSource 重连自动带）：从 EventLog 补发；本进程正有该会话的 run 在跑则接着实时推到 `result`，否则 `end` 帧。补发不依赖 Redis：SSE 的 `id:` 就是 seq。补发与 resume 预校验读日志都经 `readEvents` / `readTimeline` 升级（用 `definition.registry`，缺省 core 注册表）。
  - 流的形状 `start → (event | delta)* → (result | end | error)`。缺省编码器原样推时间线事件：事件帧不带 event 名（落 `onmessage`）、`id` = seq；控制帧带 event 名。`encode` 是按流的工厂 `() => (StreamItem) => SseFrame[]`（编码器可有状态，多流并发按流隔离）。`delta` 只给 UI 用，日志里只有完整内容块。客户端报的 lastSeq 超过日志末尾时钳到末尾，不丢实时事件。
  - 同会话同时只允许一个 run（进程内登记 → 409 `run_in_progress`；跨进程靠 EventLog 的 seq_conflict 兜底）。发起者断开缺省 run 继续跑完（`onDisconnect: "continue"`），可选 `"abort"` → paused(host)。Workers 传 `ctx.waitUntil` 让后台 run 不被回收。
  - `resume` / `decisions` 在开流前先用 core 的 `validateResume` 校验一遍，不过给 409 + 错误码（循环内部照旧再校验，fail-closed 不靠这里）。`principal(request)` 钩子做鉴权（抛 Response 即原样返回）；路由、CORS、node:http 适配交给宿主框架。
- `@reins/ui-agui`（T13）：`mapEvent` 映射表 —— user_message / model_text → `TEXT_MESSAGE_START/CONTENT/END`，model_thinking → `REASONING_START/MESSAGE_START/CONTENT/MESSAGE_END/END`（无正文只有首尾），tool_call → `TOOL_CALL_START/ARGS/END`，tool_result → `TOOL_CALL_RESULT`（isError / spilled 进 metadata），其余 core.* 与 ext.* → `CUSTOM`（name = 事件 type，value = 事件；审批弹窗靠 `core.approval_request`）。每条带 `metadata.reins { seq, eventId, type, dropped? }`。`createAguiEncoder` 把 server 的流翻成 AG-UI：start → `RUN_STARTED`（threadId = 会话）、增量先开消息完整事件补 END、result → `RUN_FINISHED`（paused 为 interrupt outcome，RunResult 含 state 放 result）/ `RUN_ERROR`；`aguiEncoding()` 直接作 `encode`。运行时零依赖，测试用 `@ag-ui/core` 官方 schema 校验。最小页面 `packages/ui-agui/demo/`（无依赖的 HTML + node:http 脚本）。AI SDK UI stream adapter 第二期。
- `reins`（T14）：`createAgent({ model, store, tools?, sockets?, systemPrompt?, secret?, handler? })` → `{ definition, handler, run }`。`model` 是 `BoundModel`（`anthropic(id, { apiKey, baseUrl? })` / `openai(...)` 的返回，或自组 `{ model, lowering }`），`store` 是 `Stores`（`memoryStore()` 或自实现）。`handler` 缺省 AG-UI 编码；`run()` 不经 HTTP 直接跑 runLoop。示例 `examples/minimal/`。
- 长任务：一次请求跑到 `paused | done | handoff` 或宿主时长上限前主动 `paused(reason=host)` 返回 state；宿主用队列或 Workflow 续跑。库不自带调度器，只暴露 `runLoop({ resume })`。

## 13. eval harness

- fixture = 一段事件日志 + 任务目标 + 评分器（确定性或 LLM judge，judge 与执行分离）。
- 对照组：无脑子、纯阈值压缩、模型自决。
- 指标：任务完成率、总 token、关键信息召回（预埋事实问答）、治理衰减（预埋约束的违规率）、连续整理次数、cache 命中率（从 provider usage 读）、墙钟。
- CI 门禁：P8 规定的默认开启条件。
- 第一批任务来自投放工具真实长任务脱敏版。

## 14. 安全默认值

- 所有工具输出与外部内容 `trust=untrusted`，投影时显式标记
- 写与副作用工具默认 ask；未知工具 deny；策略异常 fail-closed
- 内容检测类（注入分类器等）为可插拔 Socket，默认 fail-open 并强制告警
- 记忆与外溢路径严格限定，拒绝穿越
- bypass 模式只在宿主显式传入且建议隔离环境
- 事件日志不可静默修改；schema 升级只读时 upcast
