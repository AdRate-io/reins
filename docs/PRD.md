## 1. 我们相信什么（产品宪法）

两条原则，其余一切都是它们的推论。

**原则一：决策权默认在模型。** 模型是有判断力的同事，不是被流程管着的执行器。什么时候整理上下文、记住什么、要不要问人、下一步做什么，默认由模型决定。框架的职责只有四件：让它看见（感知）、给它能力（工具）、给它边界（安全网与权限）、给它记录（日志）。框架不替它决定。

**原则二：时间线是唯一真源，角色只是翻译。** 发生过的一切按顺序记成一条带发起者的时间线：用户说了什么、模型想了什么、调了什么、工具回了什么、人批了什么、系统何时整理、会话何处交接。模型看到的是事情原本的经过，不是被加工成两个角色的剧本。用户随时打断、插话、改主意，只是时间线上多一个条目。各家 API 的角色格式是发请求时的降级翻译，有损处必须显式声明。

推论：功能会随模型换代而过时，这两条立场只会随模型变强而更对。所以每个功能都是宪法下的可拆实例，宪法不变。

## 2. 市场判断（一段话）

给产品接一个 agent 的"底盘"已经饱和且好用（TanStack AI、AI SDK、LangGraph、pi）。让 agent 跑长任务时不迷路、不忘事、不烧钱、不失控、越用越熟的那套"驾驭经验"，只装在 Claude Code、Codex、dsh、OpenClaw 这几台整车里，拆不下来、绑模型、要独立进程。没有任何一个可嵌入的 TS 库把这套经验做成零件，更没有一个库把"决策权在模型"当设计原则。开发者社区最大的抱怨是框架太重、藏东西、拥有循环、频繁破坏性升级；最想要的是自己掌控循环、脏活有人做好。详见调研报告第 6、7 章。

## 3. 产品定义

### 3.1 一句话

**装一个包，配上自己的模型，就得到一辆有驾驭经验的车：底盘小到看得懂、循环归你、脑子预装、每个部件可拆可换、跑在任何服务端与 serverless 上、闲时零占用。已经有底盘的人，只装脑子也行。**

### 3.2 它是什么

- 一个 TypeScript 库，pnpm monorepo，多个小包，核心零 Node 内置依赖
- 自带一个 pi 大小的默认循环，几百行，导出为普通函数，用户可以整个复制走改
- 一套预装的"脑子"：模型对自身上下文的感知、自主整理、跨会话交接、记忆、审批、预算、回放
- 一个标准插座，让脑子能装在 TanStack AI、pi、AI SDK 等已有底盘上
- 随包一套 eval，用数字证明装了脑子省了什么、没丢什么

### 3.3 它不是什么

- 不是框架：不拥有你的循环，不藏提示词，不要求你的项目围着它组织
- 不是运行时竞品：模型对接复用 pi 的协议库，不重写 provider 层
- 不是独立应用：没有 CLI 主进程、没有 daemon、没有自己的 UI
- 不是平台：不自带调度器、持久执行引擎、记忆服务、身份系统，只提供接口与唤醒入口
- 不是万能：多智能体只提供子代理与交接两种组合，不做 swarm

## 4. 目标用户与场景

| 用户 | 现状 | 用 reins 后 |
| --- | --- | --- |
| A. 有产品要接 agent 的团队（Boss 的投放工具这类） | 用 AI SDK 或 TanStack AI 能跑，但改不了循环，跑长任务就忘事、烧钱、无法审计 | 换上 reins 的循环或只装脑子；agent 会管自己的上下文，跑三十轮不迷路，每步可回放 |
| B. 已在用 pi 或 TanStack AI 的开发者 | 喜欢简洁可控，但底盘没脑子 | 装适配器，脑子插上，循环不变 |
| C. 想从零做一个聪明 agent 的独立开发者 | 要么被框架绑死，要么自己写一堆基础设施 | 一行安装，默认就是完整的、可玩的、可拆的聪明 agent |
| D. 面向非 JS 宿主的团队 | 无法装 JS 包 | 通过 AG-UI 与 ACP 协议接入（第三期） |

首个用户是 A 类中的投放工具，作为 dogfooding。

## 5. 用户体验要求

### 5.1 五分钟体验

```ts
import { createAgent, memoryStore } from "reins"
import { anthropic } from "@reins/lowering-pi"

const agent = createAgent({
  model: anthropic("claude-opus-5", { apiKey: process.env.ANTHROPIC_API_KEY }),
  tools: [myTools],
  store: memoryStore(),                // 或 sqliteStore("./agent.db")（M1），或自己实现接口
})
export const POST = agent.handler      // Web 标准 (Request) => Response，缺省 AG-UI 事件流
```

可跑的完整版在 `examples/minimal/`（T14）：`pnpm build && ANTHROPIC_API_KEY=… node examples/minimal/server.ts`，浏览器打开即可对话、看审批、看时间线重放。

得到的不只是一个会调工具的 chat：它会在上下文变满前自己整理并说明整理了什么；关键约束不会在整理中丢失；超大的工具结果不会撑爆上下文；任务太长它会主动交接到新会话并带上总结；它会记住该记的；每一步都在时间线里，可回放、可分叉。

### 5.2 体验原则

1. **可见。** 脑子注入了什么、为什么、什么时候，全部可见；没有暗提示词。
2. **可拆。** 每个机制一行关闭；关掉之后库照常工作。
3. **可换。** 存储、模型、传输、前端协议、每个脑子模块，都有接口，默认实现可替换。
4. **可测。** 每个模型自决类机制附 eval 与数字，没有数字不上默认开启。
5. **可玩。** 循环是普通代码，钩子齐全，事件时间线随手能读，写个插件是一个晚上的事。
6. **稳定。** 事件 schema 带版本、只追加不改义；公开 API 守 SemVer；破坏性变更速度不能快过用户吸收速度。

## 6. 能力范围与分期

### 6.1 第一期：能跑、有脑、有数字

| 能力 | 用户看到的 | 宪法依据 |
| --- | --- | --- |
| 时间线内核 | 一切发生过的事有序可查、可回放、可在任意点分叉 | 原则二 |
| 默认循环 | 几百行、可复制、五个钩子（模型前后、工具前后、轮次结束） | 不拥有循环 |
| 模型对接 | Anthropic、OpenAI Responses 及 pi-ai 覆盖的其余厂商，thinking 回放不丢 | 复用不重写 |
| 上下文感知 | 模型每轮看到自己上下文的规模、各段年龄、预算余量 | 让它看见 |
| 自主整理 | 模型调 `compact` 工具决定何时整理、保留什么；阈值只做兜底；有防死循环上限 | 给它能力 + 边界 |
| 幸存契约 | 声明哪些内容（约束、目标、计划、关键事实）必须存活于整理，整理后重注入 | 给它边界 |
| 结果外溢 | 超大工具结果落到宿主存储，上下文只留取回指引 | 让它看见（不被淹没） |
| 会话交接 | 模型调 `handoff` 带经验式总结开新会话；宿主实现锚点重绑 | 给它能力 |
| 记忆 | 模型自读自写的文件式记忆工具，存储归宿主 | 给它能力 |
| 审批与权限 | 工具可声明需审批；deny 优先、fail-closed；暂停是显式返回值，可跨进程续跑 | 给它边界 |
| 预算 | token、轮次、工具调用、墙钟上限，用量作为事件发出 | 给它边界 |
| 存储接口 | 事件日志、blob、记忆三个接口，内存与 SQLite 默认实现，允许部分实现，附一致性测试 | 可换 |
| 前端 | 时间线到 AG-UI 事件的映射，SSE 由宿主注入 | 不自造协议 |
| TanStack AI 适配器 | 已有 TanStack AI 项目装两个中间件即得脑子 | 插座 |
| eval | 对照无脑子与纯阈值：token、完成率、关键信息召回、治理衰减、死循环、cache 命中 | 可测 |

### 6.2 第二期：可治理、可编程

信任分层（每条时间线条目带来源与信任级，工具输出默认不可信）；principal 透传接口；分层指令文件加载（项目指令、按路径条件加载）；确定性验证 gate 加防死锁上限；钩子生态桥接（直接跑 `.claude/hooks.json`）；pi 与 AI SDK 适配器；Postgres 存储。

### 6.3 第三期：自我成长与跨语言

技能生命周期（SKILL.md 载体、模型提案、审核后生效、试用期到可信、版本化回滚、目录变更即刷新；先只允许流程型技能）；子代理与预算闸；ACP 接入；把时间线事件模型抽成协议草案。

### 6.4 明确不做

见 §3.3。另：不做 MCP 动态工具注册（规范禁止），不在核心路径用子进程、`node:vm`、真实文件系统。

## 7. 成功标准

**第一期发布门槛（缺一不发）：**

1. 投放工具用 reins 跑真实长任务两周，无阻断性问题
2. eval 四项数字公开：对照纯阈值压缩，token 不多于其 100%、任务完成率不低于、关键信息召回不低于、压缩前后约束违规率不上升
3. 五分钟体验在 Node、Bun、Vercel、Cloudflare Workers 四个环境跑通
4. 任意会话可从时间线完整回放并在任意点分叉
5. 公开 API 文档覆盖全部导出，事件 schema 带版本

**半年内的外部信号（观察，不作为门槛）：** 有非我们自己的项目在生产使用；有社区贡献的适配器或脑子模块；pi 或 TanStack AI 社区有人主动提及。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 模型自决整理打乱 prompt cache，抬高成本 | 只在轮次边界整理；感知注入按档位离散化；产物追加不改写；eval 里盯 cache 命中率 |
| 只给工具不给判断依据，模型乱用 | 规则提示是一等交付物；阈值兜底；连续整理次数上限 |
| 某机制随模型换代过时 | 每个机制可单独关闭、按模型族配置、eval 门禁；宪法不变 |
| 依赖全是 pre-1.0（pi-ai、TanStack AI、AG-UI） | 核心运行时无关；对接隔离在薄适配包；锁版本；契约测试 |
| 被看成"又一个框架" | 循环可复制、无暗提示词、脑子可脱离底盘用，三条写进 README 首屏 |
| 厂商在服务端做类似能力 | 我们是跨厂商、宿主掌握数据的那层，厂商给不了 |
| 两个人产能 | 第一期只做 §6.1，其余分期；适配器只做两三个，插座简单让社区写 |
| 自娱自乐 | 先 dogfood、公开数字、脑子可装别人底盘 |
