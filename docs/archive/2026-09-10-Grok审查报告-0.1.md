## 必须修复

### 1. HTTP 预校验把子代理审批当成本会话 pending，asTool 官方续跑走不通

- **严重度**：必须修复（功能；fail-closed，不是权限洞）
- **位置**：`packages/server/src/handler.ts` 461-466 行
- **对照**：`packages/core/src/loop/run-loop.ts` 169-175 行已按 `sessionId` 分两路；指向别的会话的结论不校验、不记事件，经 `ToolContext.decisions` 转发给 asTool
- **官方路径（文档写了）**：
  1. `createAgent` 的 `handler` + `asTool(expert)`，专家工具 `needsApproval`
  2. `POST { input }` → 父 `paused`，`interruptions[0].kind === "subagent"`，`childSessionId = "${parent}:${toolCallId}"`
  3. 按 server README / `types.ts` / reins README 回传：`POST { sessionId, resume, decisions: [{ toolCallId: "c1", sessionId: childSessionId, approved: true, by: "boss" }] }`
  4. 父 pending 只有 `ask_expert`（如 `p1`），子的 `c1` 不在其中 → **409 `unknown_tool_call`**，一条日志不写
- **为何现有测试全绿**：`as-tool.test.ts` 和 `examples/team` 都走 `agent.run()`，不经 handler。handler 单测没有带子 `sessionId` 的 decision。
- **不要做的绕过**：对子会话另起 POST 先跑完，再续父。asTool 看子日志末条是不是 `run_paused` 决定续跑还是新一轮；子若已结束，父会把同一任务再跑一遍。
- **修复**：预校验与循环同一口径，只对 `d.sessionId === undefined || d.sessionId === 本会话` 的结论查 pending，其余原样下传。补一条 handler 级用例，剧本照 `as-tool.test.ts` 那条换进程续跑。
- **与发前清单封口的关系**：不改公开类型，只让已文档化的 asTool HTTP 路径真的能走。asTool 是因为要冻 `Interruption` / `RunResult` 才提前到 0.1 的，这条建议打进 0.1，而不是推到发后。

## 知情项

不阻断 0.1。正常官方路径要么复现不了，要么已文档化，要么要串联异常前提。

- **装配顺序靠宿主**：`approval()` 建议 sockets 末尾；`onTurnEnd` 取第一个非空意见。adrate / eval 顺序是对的。库不强制。
- **demo 最小页**只处理 `reason === "approval"`，批准不带 `decisions[].sessionId`。`examples/minimal` 没有 asTool，这条路上 demo 能用。Finding 1 修好之后，asTool 的 HTTP UI 仍要自己认 `subagent`。
- **MCP 改写后同名静默去重**：`files.read` 与 `files_read`、截到 64 后撞名时，后到的工具被 `resolveSocketContributions` 丢掉。典型 GitHub / filesystem 服务器不撞。
- **stdio `label` 拼完整 command+args**：密钥若写在 args 里，连不上时告警会带出来。HTTP 侧已去掉查询串。官方示例密钥走 `env`。
- **`ctx.emit` 无类型白名单**：恶意进程内工具可 emit `approval_decision`。官方脑子模块与 MCP 包装器不这么做。要串联「装了坏工具」。
- **循环层 `inputDraft` 不剥离 actor/trust**，仍接受 `system_note` / `ext.*`。官方 handler 已剥离。自建队列若把客户端草稿原样交给 `runLoop`，才踩得到。
- **工具拿到完整 EventLog / BlobStore**：`recall` / `fetch_blob` 自己按会话/引用收口；任意 `execute` 理论上能 `ctx.log.read(其它会话)`。不可信工具不要与多租户共用一份 log。
- **lowering-pi / adapter 的 dist `.d.ts` 仍 import 上游类型**（pi-ai、`@tanstack/ai`）。主路径 `anthropic()` / `createAgent` 不依赖这些辅助导出。运行时本来就依赖这两个包。发后再收是 breaking。
- **四环境未测、官方 Anthropic 直连未测「历史含已移除工具」**：已在 TASKS「0.1 之后」。
- **CI 不跑 `check:dist`**：见执行检查项 4，可发后补。
- **`spikes/edge-runtime-check/fake-mcp.mjs` 仍是单例 transport**：`examples/mcp` 已改 `createMcpHandler`。踩坑记录写 spike 也改了，文件未改。

## 已核对、不构成缺陷

以下按刻意设计或已修复排除，避免发前再争论一遍。

| 项 | 结论 |
| --- | --- |
| 伪造 `approval_decision` 绕过审批 | 循环层 + server 层两道白名单，测试覆盖，日志不写、工具不执行 |
| `authorizeSession` 不设等于不检查 | 刻意默认；根 README Security notes 明示；只有字面 `true` 放行，拒绝 404 |
| sessionId 正则 | 挡的是 500 不是注入；CRLF 被 `Response` 挡住 |
| pg `data` 列 json 不是 jsonb | 刻意；`pendingDigest` / `configHash` 按 `JSON.stringify` |
| `fetch_blob` 按本会话引用授权 | 刻意；fork 可读父 blob；未引用与真不存在同一句话 |
| seq 只在 `runLoop.append` 分配 | 投影 emitted 与 handoff 开场都同步了 lastSeq |
| `resolveSocketContributions` | runLoop 起步与 server 预校验共用，依次 await |
| 瞬断重试 | 零输出才重试；有状态码只认 408/409/429/5xx（R3） |
| defer / block | 已批准略过 defer，block 永远不能 |
| compact 清单 + `recall({ seq })` | 按 `tool_result.seq` 取回；pin 两成容差仍在 |
| spill 缺 BlobStore | 关闭外溢，不截断 |
| memory 路径穿越 | 拒 `..` / 反斜杠 / 百分号编码；namespace 是宿主前缀 |
| asTool 进程内 | 审批冒泡、`subagentPause`、预算合算（只加 `tokensSpent`、不写父 `budget_usage`）成立 |
| POST 不读 `Last-Event-ID` | 只认 `body.lastSeq`；GET 才读头 |
| 409 `run_in_progress` | 唯一带 `X-Reins-Session` 的错误响应 |
| 流开后失败 | 200 + `error` 帧；未 `begin` 则 `abandon` |
| `createAgentHandler` vs `createAgent` 编码缺省 | 前者 raw、后者 AG-UI，文档写清 |
| MCP `listTools` `cacheMode: "bypass"`、主入口零 `node:*`、stdio 只在 `/node` | 成立 |
| R5 导入幂等键、R7 漏登记降级为拒绝 | 成立 |
| 密钥文件 | `模型API测试信息.md` gitignore，从未进库 |
| 11 包版本 / LICENSE / examples private | 齐；changeset 无残留 bump 文件 |
