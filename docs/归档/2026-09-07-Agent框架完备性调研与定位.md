# Agent 框架完备性调研与定位（v0.3 讨论稿）

> 日期：2026-09-07
> 目标：回答三个问题——① 2026-09 的 Agent 框架在"完备、智慧、灵活嵌入"上到底做到了哪一步；② 空缺与难点在哪；③ 我们能做出一个什么样的开源框架，凭什么有价值。
> 方法：八路并行调研，逐项以官方文档、源码、npm registry、论文为准；未核实处明确标注。
> 关系：取代 v0.1（元基础运行时）与 v0.2（上下文自主中间件）的定位部分，两者的技术结论作为本稿的素材。

## 0. 问题重述

Boss 的原始诉求是给一个 TanStack 架构的投放工具接入 Agent，要求轻量嵌入、闲时零占用、工具与存储灵活可配、模型对自身上下文有充分自主权、模型能给自己加能力。选型后没有一个现成方案同时满足，于是问题升级为：**市场上是否缺一个"能被大部分框架或项目快速接入、相对完备、智慧、灵活扩展"的开源 Agent 框架？如果缺，我们能做出什么？**

本稿把"完备"拆成 13 个能力维度逐一核实现状，把"智慧"拆成 harness 层的具体机制清单，最后用空缺矩阵推导产品形态。

## 2. 已核实的七个基础维度

### 2.1 运行时与循环：已解决

| | TanStack AI 0.53 | Vercel AI SDK v7 | LangGraph.js 1.4 | pi-agent-core 0.85 | Mastra 1.64 |
| --- | --- | --- | --- | --- | --- |
| 闲时零进程 | `chat()` 是函数，无实例生命周期 | Agent 无状态 | 纯库 4 依赖 | 低层 Agent 无需 Session | 裸 Agent 可跑 |
| 自定义存储 | 读线程/写线程两个函数；空 messages = 从存储续跑 | 零抽象自己写 | checkpointer 5 方法 + 验证套件 | Storage/Session/SessionRepo + 验证套件 | 约 29 方法无文档 |
| 循环钩子 | 19 个钩子 7 个 phase | prepareStep/prepareCall/onStep*/onToolExecution* | wrapModelCall/wrapToolCall | transformContext/before_payload/beforeToolCall | processLLMRequest/Response、hooks |
| 双视图 | 内置 messages 真源 + providerMessages 送模型 | 自维护 | 自维护 | transformContext 非破坏 | 自维护 |
| 风险 | pre-1.0 周更 | Node≥22 纯 ESM | 吞 LangChain 抽象 | 每月 breaking | 解包 64MB、31 依赖 |

排除：Cloudflare Agents（Node 里 import 即崩）、Inngest AgentKit（半停滞）、VoltAgent（13MB、锁 ai@6）。

**结论：这一层不存在空缺。任何新框架若重做循环、存储抽象、钩子系统，都是在复制已有物。**

### 2.2 协议与 provider：已解决

pi-ai 覆盖 10 种线协议、149 个测试文件，thinking signature 与 encrypted reasoning 回放完整，跨 provider 切换自动归一化工具调用 ID；Vercel AI SDK 约 38 个 provider 包；TanStack AI 16 个 adapter。OpenAI Responses 的 item 形状已成为"一条时间线上并排 message / reasoning / function_call"的参考模型。**无空缺，只有选型。**

### 2.3 存储与会话：部分解决

存储接口有多家成熟抽象（见 2.1）。**未解决的是会话语义层**：树形分叉、把会话交接给新会话并带经验总结、多会话共享记忆，各家自造格式，没有通用契约。anima 的 switch_session v3 是我们自己做过的一个实例，绑死了 Slack / 飞书通道。

### 2.4 工具层：范式演进无一环是 provider 独占，空白在结果处置

**三代范式与证据：**

| 范式 | 解决的问题 | 官方实测 |
| --- | --- | --- |
| JSON function calling | 基线 | 30~50 个工具后选择准确率下降 |
| Tool search / 延迟加载 | 工具太多占上下文 | Anthropic：58 工具场景上下文减 85%，MCP 评测准确率 79.5% → 88.1% |
| 代码编排工具（PTC / Code Mode） | 中间结果占上下文、多步往返 | 75 工具场景计费 input 减 38%；MCP 极端案例 150,000 → 2,000 token；**但 τ²-bench 这类每轮 1~2 个串行调用的场景分数不变、成本反而 +8%** |

两家都提供 client 执行版本，Anthropic PTC 文档专门列出自管沙箱为对等方案。**整条链没有一环是 provider 独占的。** harness 侧现成实现：`@tanstack/ai-code-mode` 0.4.8 是唯一可嵌入任意 Node 项目、provider 无关的完整 code mode（driver 可插 isolated-vm、QuickJS-wasm、Cloudflare），且实测不需要顶级模型；TanStack AI 的 lazy tool discovery 完全不依赖 provider 原生能力。

**MCP 客户端：tools 之外落地率极低。** 官方 TS SDK 已 v2 分包。只有 Vercel AI SDK 把 resources、prompts、elicitation 都做了；sampling 无一家实现且已淡出核心规范；OAuth 反而三家都有。

**OpenAPI → 工具：无框架内建。** 生态实际路径是 OpenAPI → MCP server → 框架 MCP client。Stainless 与 Cloudflare 这两个最早做"一 endpoint 一 tool"的先行者双双倒向代码执行路线，且都仍标 experimental。

**沙箱：** 进程内 QuickJS-wasm 亚毫秒启动、无网络、edge 通吃；isolated-vm 7.0.1 仍在维护；托管里只有 E2B（约 150ms）与 Daytona（<90ms）给的是创建口径，Vercel Sandbox 的 Active CPU 计费对"大部分时间在等 LLM"的负载是结构性优势，E2B 是唯一可自托管的。WebContainers 仅浏览器，排除。

**工具结果处置是最大空白。** API 层没有任何 tool_result 大小参数。Claude Code 有官方文档化的做法：MCP 输出超过 25,000 token 落盘并替换为文件引用。**框架层全部空白**：AI SDK 7 全文无截断、LangGraph.js 无、Mastra 仅 webFetch 硬截。tool-call 级依赖 DAG 排序全行业缺失，代码编排就是它的替代品。"agent 操作产品自身 API"没有成熟库。

**HITL 语汇已收敛：** AI SDK、TanStack AI、Mastra 三家的 `needsApproval` 加审批响应几乎一致。MCP Apps 让工具返回可交互 UI，已被 Claude、VS Code Copilot、M365 Copilot 支持。

**对框架设计的推论：** 工具抽象应拆成四个正交维度而不是四种工具类型：执行位置（server / client / sandbox / provider）、暴露策略（lazy、allowedCallers）、结果处置（toModelOutput、溢出策略 truncate 或 spill-to-store）、人机交互（needsApproval、ui）。code mode 不是特殊工具，而是同一批工具的另一种投影。代码执行对非 coding 的 Web 产品默认关闭，工具数 ≥10 或出现 fan-out 时启用；进程内 QuickJS 为 L1，托管为 L2。

### 2.5 记忆：已成熟

- Anthropic memory tool：模型自己 view / create / str_replace / delete 文件，存储由宿主实现，TS SDK 有 helper。
- Claude Code auto memory：官方原话 "Claude decides what's worth remembering"。
- Letta MemFS：git 版本化记忆文件系统，agent 可改自己的 system prompt、自建 skills；Context Constitution 是唯一把"模型拥有自己的上下文"写成纲领的文档。TS SDK 的 local 模式是子进程包装。
- mem0 / zep / cognee 是"外部管理者"范式，模型是记忆的被动消费者，与自决范式不同。

### 2.6 上下文管理：决策权空白

核实过的全部生产级压缩实现（Anthropic compact_20260112 与 context editing、OpenAI compact_threshold、Claude Code、Codex CLI、Cline、Mastra Observational Memory、Vercel AI SDK prepareStep、TanStack AI withCompaction、pi-agent-core、Letta）**没有一个把"何时压缩"交给模型**。Mastra 文档明说是刻意为之，理由是 agent 不暂停、prefix cache 稳定。

唯一实证：论文 Self-Compacting Language Model Agents（arXiv 2606.23525，2026-06）。工具与规则必须成对；比固定间隔压缩省 30~70% 成本且质量不降；模型对自身上下文"proprioceptively blind"，需要框架补感知信号。代码为 8 star Python 原型，TS 零实现。

配套原语只有 Anthropic task budget：服务端注入只对模型可见的剩余预算倒计时。仅 Opus 5 / Fable 5.1 一档支持，客户端改 remaining 会打断 cache。

### 2.7 自扩展：TS 空白，收益证据两面

- 载体事实标准：Agent Skills 规范（SKILL.md），Apache-2.0 开放标准，40+ 客户端。**不自造格式。**
- 完整闭环（生成 → 准入门 → 检索 → 维护）的开源实现全是 Python：OpenSpace（MCP server 形态，provisional → trusted）、SkillOpt（held-out 严格提升才接受编辑）。TS 侧只有 `@cloudflare/codemode` Snippets，绑 Cloudflare。
- 所有成熟实现独立收敛到"必须有验证门才入库"；Voyager 去掉 critic 掉 73%。
- 负面证据：ContinualSkillBench 显示显式技能库对比"把反馈留在上下文里"平均打平；SkillFlow 在 Terminal-Bench 上"用了、零提升"。正面：SkillsBench +16.6pp，出现在任务有真实跨任务复用结构时；"≤3 个模块的聚焦技能优于大 bundle"。
- 安全：26.1% 社区技能含漏洞；自演化 agent 有自毒化与 revision churn，需版本化、可回滚、对冻结快照执行。
- dsh 的模型自改：`dsh-tool-cordis` 让模型现场写插件，但只在进程内存、重启即失、沙箱非安全边界；写 SKILL.md 可持久，靠目录 digest 每步刷新。Hermes 给模型 `skill_manage` 六动作加后台 curator（Python 独立应用）；OpenClaw 让 agent 只能提 proposal、apply 才是唯一写入，SQLite + 不可变 generation + 原子 rename（TS，但是 Gateway 常驻进程）。
- MCP 2026-07-28 规范禁止工具集按连接变化，**模型自建能力必须走进程内注册，不走 MCP。**

## 3. 智慧机制清单：harness 层到底做了什么

术语锚点：METR 2023 定义 "model + scaffolding = agent"；"harness engineering" 一词可核实的最早出处是 Mitchell Hashimoto 2026-02-05。学术分类学 arXiv 2604.03515 对 13 个开源 scaffold 做源码级编码，识别出 5 个循环原语（ReAct、generate-test-repair、plan-execute、multi-attempt retry、tree search），13 个里 11 个是多原语组合。**该文明确拒绝做性能比较**，理由是模型是比 scaffold 更大的混杂因子。

### 3.2 哪些机制有证据支持，哪些被夸大

**高杠杆（有 ablation 或大样本）：**

1. **压缩策略本身。** Self-Compacting（arXiv 2606.23525）：模型自决压缩，数学 +18.1、agentic search +5~9，成本降 30~70%；工具与规则缺一不可。
2. **压缩是一等安全故障面。** Governance Decay（arXiv 2606.22528）：1,323 个 episode，约束在完整上下文时违规率 0%，压缩后升至 30%（某些模型 59%）；约束若存活于摘要仍为 0%。Constraint Pinning 恢复到 0%。Claude Code 的"什么幸存于压缩"表和 dsh 的"模型可见即已记录"不变量都是对此的工程回应。
3. **增益在 tools、middleware、memory，不在 system prompt。** 自动演化 harness（arXiv 2604.25850）把 Terminal-Bench 2 从 69.7% 提到 77.0%，ablation 明确把增益定位到工具、中间件与长期记忆。
4. **周期性计划提醒。** 21,120 条 SWE-agent 轨迹（arXiv 2604.12147）：周期性 plan 提醒减少违反并提升成功率；但劣质 plan 比没有 plan 更糟。
5. **独立评估者。** Anthropic 2026-03：把做事的 agent 与打分的 agent 分开是强杠杆，因为自评"reliably skew positive"。
6. **确定性验证 gate 加防死锁上限。** Claude Code 的 Stop hook 连续阻断 8 次后强制结束，这个上限本身是被低估的细节。

**被夸大的：**

1. **"子代理普遍有效"。** 90.2% 来自研究类 eval，同文披露 token 是聊天的 15 倍且解释 80% 方差；跨厂商实验显示多智能体优于 ReAct 只在 Anthropic 模型家族内成立。可辩护的结论只到：独立只读可并行的子任务受益。
2. **"CLAUDE.md 提升正确率"。** arXiv 2607.27250：3 个真实仓库、288 次评测加 gold test，上下文文件对正确率没有可测量影响（≤10~15pp 等价界）。它管约定和风格，不涨解题率。
3. **"harness 能涨分"。** The Scaffold Effect（arXiv 2607.22585）：同模型内不同 harness 配对差异仅 0~8pp，置信区间多含 0，但"每解一题 token 数"差异最多 40 倍。**harness 主要买的是成本和延迟，不一定是正确率。这是本次调研最反直觉的一条。**
4. **"自验证一定好"。** arXiv 2606.28430：oracle 在环时分数接近满分，但被测行为之外的代码"dead or absent"。
5. **"todo 工具是必需品"。** Claude Code 已在新模型族默认排除 TodoWrite，厂商自己在拆。
6. **Ralph loop。** 作者本人限定只适合 greenfield 且需资深工程师看着；证据全是轶事。

**条件性的：** harness 的每个组件都是对"模型不能独立做什么"的假设，随模型换代要重新压力测试。Anthropic 在 Opus 4.5 到 4.6 之间删掉了 context reset 与 sprint 构造。

### 3.3 已被占的位与没人做的位

已被嵌入式 TS 库覆盖的：Claude Agent SDK（33 个 hook、6 种权限模式、子代理、fork、文件 checkpoint、预算；但 spawn 二进制且绑 Anthropic）；pi-agent-core（真 provider 中立，11 个类型化 hook、压缩、skills 加载、会话 lane；无权限、无子代理、无 plan）；Mastra AgentController（权限策略、plan 与 task 工具、子代理、内置 goal judge；无压缩、无 skills、hooks 近乎没有）；`@anthropic-ai/sandbox-runtime`（OS 级沙箱可独立嵌入，研究预览）。

**确认没有任何嵌入式 TS 库提供、只存在于独立 CLI 里的机制：**

| 13 | 钩子生态桥接（直接跑 .claude 与 .codex 的 hooks.json） | dsh，采纳率杠杆 |

### 3.4 三条硬结论

1. **别把"涨分"当卖点，把"省钱"当卖点。** 同模型内 harness 对正确率的影响常落在噪声里，但每题 token 差 40 倍。框架应以可测量的 token 与延迟预算为一等指标。
2. **压缩契约是最高杠杆且最空缺的一块。** 有 ablation、有安全证据、现有 TS 库全部缺失重注入契约，这是 pi-agent-core 与 Mastra 之间最明显的缝。
3. **子代理别做成默认。** 做成可选 seam，不做架构前提。

## 4. 多智能体、人类介入与长任务

### 4.1 多智能体：证据已收敛到"上下文隔离 + 单写者"

- **正收益边界有论文数据**：可分解、只读、广度优先的任务，多智能体在 Finance-Agent 上 +80.8%（arXiv 2512.08296，Google Research 与 MIT）。这正是 subagent 做搜索、读码的形态。
- **负收益边界也有论文数据**：顺序依赖、需共享上下文、有写操作的任务，全部架构退化 -39% 到 -70%；无通信架构误差放大 17.2 倍。等 thinking token 预算下，单 agent 在多跳推理上持续匹敌或超过多智能体（arXiv 2604.02460）。
- **Anthropic 自己降级了叙事**：2025-06 的 +90.2% 被自家承认 token 用量解释了 80% 方差；2026-01 改口为"设计良好的单 agent 能做的远超多数开发者预期"、"按角色拆分 often counterproductive，应按 context 边界拆"。
- **Cognition 收窄为单写者原则**：写操作保持单线程，额外 agent 贡献智能而非动作；实践中多数只剩只读 subagent，"largely resemble tool calls"。
- OpenAI Swarm 已废弃；Claude Code agent teams 仍是实验特性且明确不在 headless 与 SDK 可用。

**推论：多智能体应降级为一种上下文管理策略，不是编排范式。** 一等能力只需三件：`asTool` 式子代理（独立 context、结果回传）、`handoff` 式同会话接管（单写者）、并发与嵌套深度与预算上限。平级 mailbox、swarm、按角色预置团队模板不进核心。

### 4.2 跨进程协议：已被库解决

| 协议 | 定位 | 成熟度 | TS 库 |
| --- | --- | --- | --- |
| A2A | agent 到 agent，跨组织 | 生产，v1.0，已捐 Linux Foundation | `@a2a-js/sdk` |
| ACP（Zed） | 编辑器到 coding agent 的"LSP" | v1 稳定 | `@agentclientprotocol/sdk`（旧包名已冻结） |
| AG-UI | agent 到前端 UI 事件流 | 准生产，协议仍 0.0.x | `@ag-ui/core`；TanStack AI 全量采用，AWS Bedrock AgentCore 原生支持 |
| MCP 2026-07-28 | agent 到工具 | 生产 | 无状态核心；Tasks 扩展做异步长任务；MRTR 以 `input_required` + 不透明 requestState 取代 elicitation，**是无需常连接的跨进程 HITL** |

IBM 的另一个 ACP 已并入 A2A，不要再实现。

### 4.3 人类介入：能否"暂停后跨进程续跑"是分水岭

| 方案 | 跨进程重启续跑 |
| --- | --- |
| OpenAI Agents SDK `RunState` | 能，设计为可序列化；嵌套 agent 的审批冒泡到外层 |
| LangGraph `interrupt` + checkpointer | 能，需 DB saver |
| Vercel AI SDK 7 | 能，通过 WorkflowAgent；审批带 HMAC 签名，恢复时重校验 |
| TanStack AI orchestration | 架构上能，实践上只有内存 run store，且整个包未合入 main、未发 npm |
| Claude Agent SDK `canUseTool` | **不能**，待批状态在 loop 内不可序列化，必须保活进程 |
| Mastra workflow suspend/resume | 能，agent 原始流仍不支持断线 |

### 4.4 持久执行：纯库与平台的分界

纯库：DBOS Transact（仅需 Postgres，不能被 bundler 打包）、LangGraph checkpointer、Vercel Workflow DevKit（2026-04 GA，开源，但 Postgres 模式需常驻 worker，不适用 serverless）。必须有 server：Temporal、Restate、Inngest、Hatchet、Trigger.dev。平台绑定：Cloudflare Workflows、AWS Lambda Durable Functions。

serverless 跑分钟级循环的现实数字：Vercel Fluid compute 800 秒 GA、1800 秒 beta，等待 LLM I/O 不计费；`waitUntil` 不能突破时长上限；Cloudflare Durable Object 空闲 70 到 140 秒被驱逐；Lambda 单次 900 秒。

### 4.5 后台自主与定时唤醒：库空白

Claude Code 有 Routines、Desktop 任务、会话内 loop 三层调度，Stop hook 退出码 2 是官方认可的自主循环原语，Channels 让 MCP server 主动推事件进会话。但 Agent SDK 本身无 cron 原语。OpenClaw 与 Hermes 的 cron 都依赖常驻 daemon。**唯一成熟的"可嵌入 TS 库 + cron 唤醒"是 Cloudflare Agents SDK 的 schedule（绑 CF）与 Mastra Schedules。**

### 4.6 会话模型

树形 fork：Claude Agent SDK `forkSession` 与 LangGraph `updateState` 是一等公民，只分叉对话不分叉文件系统。OpenAI 的 handoff 是同一会话接管，不是新会话。跨会话记忆：Anthropic memory tool 是 API 原语、存储自实现；Zep 社区版已废弃；Letta 需 server。

### 4.7 对框架设计的推论

通用可嵌入框架要不阻碍使用者接上述能力，最小充分集是七组原语：① 可序列化的 run/turn 状态，任何暂停点都能存到任意 KV 后续跑，这是接任何持久执行后端的唯一必要前提；**暂停与恢复必须是 `run()` 的显式返回值，不是让调用方 await 一个永不 resolve 的回调**，这是 Claude Agent SDK 与 OpenAI Agents SDK 的分水岭，也是能否上 serverless 的分水岭；② 接口先于实现定死的可插拔 Store；③ 不假设连接常在的中断与恢复，把状态放进 payload 让无状态实例接手；④ 能从嵌套 agent 冒泡到最外层的工具审批钩子；⑤ agent 作为一等值，只提供 `asTool` 与 `handoff` 两种组合；⑥ session、fork、resume；⑦ 事件流出口可映射 AG-UI 与 ACP，加一个幂等的 `wake(event)` 唤醒入口，框架不自带调度器。

明确不做：自带 durable execution 引擎、自带调度器、自带记忆后端、平级 mailbox。默认值保守：默认单 agent，派活要显式。Claude Code 甚至在系统提示里加了"没被要求就别调 Agent 工具"，因为 Opus 5 过于愿意派活。

## 5. 安全、治理、评测与观测

### 5.1 现状要点

- **注入防御理论已收敛，工程靠纵深。** Google 等联合论文（arXiv 2506.08837）给出六种可证明抗注入的设计模式，共同思想是不可信数据只能影响动作参数、不能影响"选哪个动作"。CaMeL 是唯一声称强保证的落地，工程复杂度高。Anthropic 的工程实践：所有工具输出视为不可信；子代理隔离不可信内容有效，但若把子代理输出当更高信任级就引入新注入面。OpenAI Model Spec 把 tool output 放在指令层级最低位。
- **框架层几乎没有信任分级与 taint 传播。** 内置注入分类器只有 Mastra 的 processors（TS）和 LlamaFirewall（Python）。
- **权限模型已成型。** Claude Code 的 deny → ask → allow 首匹配即定、deny 不可被 allow 覆盖、managed 策略连命令行都盖不过。两个已踩过的坑：PreToolUse hook 返回 allow 也不跳过后续 deny；`canUseTool` 是最后一道，被 allow 规则提前放行的调用根本到不了它，鉴权只写在回调里会被静默绕过。Cedar 已有官方 WASM npm 包和从 MCP 工具描述生成 schema 的工具，Strands 把它做成每次工具调用前评估、默认拒绝、身份解析失败即全拒。
- **多租户与身份在规范之上是空白。** MCP 授权规范只定了 OAuth 2.1、audience 绑定、不透传 token 三条；WorkOS 指出规范没有多租户模型。"用户 + agent + 上下文三元组每次工具调用都建模"是使用者自己的设计。Auth0 for AI Agents 已 GA（Token Vault、On-Behalf-Of、Agent as Principal），只支持 OAuth。
- **成本控制只有单会话级。** Anthropic task budget 是 advisory；Claude Agent SDK 只有 max_turns 与 max_budget_usd，官方明确不做 token 数上限。per-user 配额所有框架都没有，落在网关层，且本地内存计数器不跨副本。
- **评测：随包交付的最小 eval harness 只有弱先例。** 最接近的是 Mastra built-in scorers（tool-call-accuracy、trajectory-accuracy 等，异步旁路）。promptfoo 2026-03 被 OpenAI 收购，中立性存疑。Inspect AI 是 agentic eval 首选但是 Python。**没有一个主流 TS 库把"注入回归套件 + 轨迹断言"作为包内一等能力交付。**
- **可观测性：OTel GenAI 语义约定仍未 stable**，2026-06 迁到独立仓库只是组织变更。跨框架 trace 通用格式三家并存（OTel GenAI、OpenInference、Open Agent Spec Tracing），无赢家。
- **审计与回放：主流框架无内置 append-only 日志。** 做到的是研究项目 ActiveGraph（append-only 事件日志为唯一真源、记录 model 与 tool 响应实现确定性 replay、任意事件廉价 fork）。EU AI Act 第 12 条对高风险系统要求全生命周期自动日志。

### 5.2 嵌入式 TS 已做好 vs 空白

| 能力 | 判定 |
| --- | --- |
| 权限规则引擎、guardrail 管道、HITL 中断恢复、Cedar 接入、OTel 发射、session 持久化 | 已做好 |
| 单会话预算与循环上限 | 部分（无 token 数上限、无跨会话） |
| 工具结果 taint 标记与信任传播 | **空白** |
| principal 透传、租户隔离、工具级用户鉴权 | **空白** |
| per-user 配额 | **空白** |
| append-only 审计日志与确定性回放 | **空白** |
| 随包 eval harness | **近空白** |
| 跨框架 trace 通用格式 | **空白** |

### 5.3 安全默认值的共识

有共识的：默认 ask 或 deny-by-default；deny 不可被 allow 覆盖；只读操作默认放行以对抗审批疲劳；所有工具输出视为不可信；自主性是挣来的，任务结束立即回收；bypass 仅限隔离容器；权限层与沙箱层不可互替；可观测性是安全控制不是运维选项。

有分歧的：guardrail 失败时 fail-open 还是 fail-closed。Mastra 建议内容检测 fail-open，Cedar 与 OWASP 路线是 fail-closed。合理拆法：**授权决策 fail-closed，内容检测默认 fail-open 但强制告警**。

### 5.4 对框架设计的推论

应做成一等能力的是"事后加不上的环境结构"：每条消息与工具结果带 provenance 与信任级；单一权限决策管线且决策本身是可审计事件；principal 透传接口只定义传播不做 IdP；预算与上限并把用量作为事件发出；append-only 事件日志加确定性 replay，一次解决审计、回放、fork、eval fixture 四件事；最小 eval harness 随包交付。留给外部的：IdP 与 token vault、策略语言求值、租户配额限流、trace 后端、沙箱、注入分类器模型。

## 6. 嵌入性、前端协议与开发者痛点

### 6.1 跨运行时的硬约束

| 运行时 | 时长 | 文件与子进程 | 后台续跑 |
| --- | --- | --- | --- |
| Cloudflare Workers | CPU 默认 30 秒可配至 300 秒，HTTP wall-clock 无硬上限 | 有虚拟内存 fs，请求间不共享；`child_process` 是 stub | `waitUntil` 共享 30 秒预算 |
| AWS Lambda | 硬上限 15 分钟 | 有 /tmp 与子进程 | 断连不中止但全程计费 |
| Vercel Fluid | 默认 300 秒，GA 800 秒，beta 1800 秒 | Edge Functions 已废弃 | `after()` 吃路由自身时长，无独立预算 |
| Deno / Bun | 无限制 | Deno 默认拒绝权限；Bun 至今无沙箱 | 自管 |

**关键结论：`waitUntil` 与 `after()` 不能用来跑"响应已发、后台继续多轮 LLM"，只够 flush 日志。要长跑必须上队列、Durable Object 或 Workflow。** OpenAI Agents SDK 在 Workers 上是 experimental，Genkit 直接报错，Vercel AI SDK 没有运行时兼容矩阵页。

### 6.2 框架适配：一个 handler 通吃已基本成立，靠 Web 标准

Hono 只用 Fetch 的 Request 与 Response，因此 Workers、Deno、Bun、Lambda、Vercel 同一份代码，只有 Node 需要 adapter。TanStack Start 的服务端引擎是 Nitro，20+ 部署预设自动探测。规范侧 WinterCG 已改组为 Ecma TC55，Minimum Common API 成为 ECMA-429。

SSE 是最大暗坑：Nginx 默认整段缓冲需加 `X-Accel-Buffering: no`；Express 需 flushHeaders 且 compression 中间件吞块；EventSource 不能 POST 也不能带 header，用 fetch 加 ReadableStream 要自己写重连。

### 6.3 前端流协议：AG-UI 正在成为事实标准

- AG-UI 事件全集覆盖生命周期、文本、工具调用、状态快照与 JSON Patch 增量、推理、子代理、活动、自定义。
- **TanStack AI 的选择是最强背书**，官方原话：客户端发 AG-UI 请求、消费 AG-UI 事件，"no proprietary stream format and no translation layer"，同一客户端指向 Python、Go 或 PHP 的 AG-UI 运行时照常工作。
- 官方集成清单已含 LangGraph、CrewAI、Microsoft Agent Framework、Google ADK、AWS Strands、Bedrock AgentCore、Mastra、Pydantic AI、Agno、LlamaIndex、Claude Agent SDK；10 种语言 SDK。`@ag-ui/core` 周下载 177 万。
- 两个保留：核心包版本仍是 0.0.59，立项一年半未 1.0；百万下载高度依赖 CopilotKit 作为传递依赖。
- AI SDK UI Message Stream 是 Vercel 单方定义，`x-vercel-` 前缀，无稳定性承诺，14 个月内三次大版本。做 adapter，不做地基。
- 断线重连在 AI SDK 里不是内置的：需要 resumable-stream 包加 Redis 加自建 activeStreamId 持久层，且关标签页不停止模型生成。AG-UI 侧的恢复语义未核实。

### 6.4 状态外置 vs 绑定实例

状态外置的代表是 LangGraph checkpointer、Mastra 按 domain 切分的 storage（适配器可只实现部分 domain）、Vercel Workflow、DBOS；绑定实例的代表是 Cloudflare Durable Object，零延迟、状态同步白送，但强绑 Cloudflare。**"存储无关 + 同步无关"的最小接口共识尚未形成**，Mastra 的 domain 切分是最接近的设计，但是产品私有接口。Vercel AI SDK 没有 persistence 抽象。

### 6.5 开发者痛点，按证据强度

**A 级，多来源反复印证：**

1. **过度抽象与调试不透明。** Octomind 生产用 12 个月后移除 LangChain，HN 高赞原话"改一个细节要穿 5 层抽象"、"death by abstraction"；LangChain CEO 亲自承认初版"absolutely abstracted away too much"。
2. **破坏性变更疲劳。** `ai` 包 14 个月内 v5、v6、v7 三个大版本，v6 被称为"自 3.0 以来最大破坏性发布"；有 provider 维护者公开表示不再维护旧版兼容。
3. **隐藏提示词与不掌控循环。** Anthropic 官方建议"start by using LLM APIs directly"，框架"obscure the underlying prompts"，进生产时"strip away abstraction layers"。12-Factor Agents 的 Factor 8 "Own Your Control Flow"，GitHub 25,743 star：**you should own the while loop**。

**B 级：** 抽象目标本身在漂移；TS 侧是 Python 的逐字移植、类型不安全；Mastra npm 组织 2026-06 被投毒（社区来源，需二次核实）。

**反面，为什么还是用框架：** 批评者主动点名"请聚焦 provider 无关这部分"；不想自己写的具体清单是重试退避、流式解析与 SSE 细节、工具 schema 生成校验、token 计数与压缩、持久化恢复、tracing、人机审批、断线恢复。Mastra 1.0 的 HN 讨论整体正面，主诉求是"TS 原生、无 vendor lock-in、feature-complete"。**反框架不等于反库。**

### 6.7 非 JS 世界：跨语言只走协议

未发现任何 JS agent 框架被 Python 项目大规模采用的案例。先例都是协议：AG-UI 十种语言 SDK；ACP 以子进程 JSON-RPC over stdio 自比 LSP，TanStack AI 已能把 Claude Code、Codex、OpenCode 或任何 ACP agent 当作聊天后端，工具活动以 AG-UI 事件回流。

### 6.8 对框架设计的推论

"能被大部分框架或项目快速接入"在工程上意味着八条约束：① 核心是 `(Request) => Response` 的 Web 标准 handler，零 Node 内置依赖；② 核心路径禁用 `child_process`、`node:vm`、真实 fs，文件与 shell 工具做成可插拔 provider；③ 不假设进程能活到循环结束，每步可挂起可从外部存储恢复；④ 持久化是接口且允许部分实现，默认零依赖内存实现；⑤ 核心产 async iterable 事件流，传输由宿主注入；⑥ 断线恢复设计在协议层；⑦ 跨语言只走协议，ACP 加 AG-UI 是现成两条腿；⑧ SemVer 纪律，破坏性变更速度不能超过生态吸收速度。

前端协议：AG-UI 为一等输出，AI SDK UI stream 做 adapter，绝不自造第三种。AG-UI 编解码隔离在薄适配包里，核心保持"产生结构化事件"的中立形态。

## 7. 空缺矩阵与难点

### 7.1 把八路结论压成一张表

| 层 | 嵌入式 TS 已解决（不要重做） | 嵌入式 TS 空白或只在独立 CLI 里 |
| --- | --- | --- |
| 运行时与循环 | 循环、19 个钩子、双视图、存储接口、provider 适配（TanStack AI / AI SDK v7 / LangGraph.js / pi） | — |
| 工具 | 进程内工具、MCP tools + OAuth、客户端工具、审批语汇、code mode、lazy discovery、托管沙箱 SDK | **大结果截断/落盘/引用**；工具结果 taint 与信任级；产品自身 API 直转 |
| 记忆 | Anthropic memory tool 原语、mem0 | 经验到技能的自动晋升闭环 |
| 上下文管理 | 阈值压缩（各家都有） | **模型自决何时压缩**（工具+规则+安全网）；**压缩幸存契约与约束钉死**；**上下文自感知信号**；spill 外溢存储 |
| 会话 | fork、resume、handoff（同会话接管） | **带经验总结交接到新会话**的通用契约；日志版本迁移契约；写者租约 |
| 自扩展 | SKILL.md 格式与校验库 | **提案 → 准入门 → 持久化 → 刷新 → 维护的完整闭环**（Python 有，TS 无）；skills 渐进披露预算 |
| 智慧机制 | Mastra 有 goal judge、plan 工具；pi 有压缩与 hooks | **分层指令加载器**；**确定性验证 gate 加防死锁上限**；tool search 中立实现；钩子生态桥接 |
| 多智能体与长任务 | asTool、handoff、A2A / ACP / AG-UI、可序列化 RunState（OpenAI）、checkpointer | 中立的定时唤醒入口；TanStack 的持久 run store 未落地 |
| 安全治理 | 权限规则引擎、guardrail 管道、HITL、Cedar 接入、OTel 发射 | **信任分层上下文模型**；**principal 透传接口**；per-user 配额；**append-only 事件日志与确定性回放**；审批 fail-closed 状态机 |
| 评测 | Mastra scorers、外部平台 | **随包交付的 eval harness**（轨迹断言 + 注入回归 + 压缩决策质量） |
| 嵌入性与前端 | Web 标准 handler、AG-UI、AI SDK UI stream | 断线恢复在协议层；存储无关最小接口共识 |

**空白不是散落的，它们聚成一个层。** 已解决的全是"一轮对话怎么跑"：循环、协议、传输、工具调用。空白的全是"agent 在时间轴上怎么活"：上下文如何不衰减、如何自主压缩与交接、经验如何沉淀成能力、行为如何被治理与回放、效果如何被评测。前者是运行时，后者是 harness 里那些让 Claude Code、Codex、dsh 显得"智慧"的机制，目前只存在于独立 CLI 应用里，没有一个被抽成可嵌入任意循环的库。

### 7.2 难点，按对方案的影响排序

1. **harness 买的是成本、延迟与安全，不是正确率。** 同模型内不同 harness 的正确率差异常落在噪声里，但每题 token 差 40 倍；压缩后约束违规率从 0% 升到 30%。价值主张必须是可测量的 token、延迟、治理衰减，不能是"更聪明"。这也决定了 eval 必须随包交付，否则主张不可验证。
2. **每个 harness 组件都是对"模型不会什么"的假设，会随模型换代失效。** Anthropic 在两代模型之间删掉了 context reset 与 sprint 构造；Claude Code 在新模型族默认关掉了 TodoWrite。框架的每个机制都必须可单独关闭、按模型族配置、有 eval 证明其仍有效，否则半年后变成负资产。
3. **模型自决压缩与 prompt cache 稳定性冲突。** Mastra 明确为此拒绝把决策权给主模型。要正面解决：只在轮次边界压缩、状态注入按档位离散化、产物追加不改写、用 eval 里的 cache 命中率验证。
4. **开发者要自己拥有 while 循环。** Anthropic 官方建议、12-Factor Agents 25,743 star、HN 共识都指向同一条。这意味着我们不能是"框架"，不能拥有循环、不能隐藏提示词。**v0.1 的 D1"是库不是框架"是对的，且比当时想的更重要。**
5. **自扩展的收益是条件性的，风险是确定的。** 显式技能库对比"把反馈留在上下文"平均打平，只在有跨任务复用结构时正收益；26.1% 社区技能含漏洞，自演化有自毒化。自扩展必须是可选包、带准入门、先只允许流程型技能。
6. **依赖全是 pre-1.0。** TanStack AI 0.53 周更、AG-UI 0.0.59、pi 每月 breaking、AI SDK 14 个月三个大版本导致维护者弃坑。核心必须运行时无关，所有对接隔离在薄适配包里，自己守 SemVer。
7. **跨运行时约束是硬的。** 核心路径不能有 child_process、node:vm、真实 fs；暂停与恢复必须是显式返回值；状态必须可序列化到任意 KV。这排除了很多顺手的实现方式。
8. **两个人的产能。** 上表空白有十几项，第一版只能选一个聚簇做深、配 eval 证明，其余按阶段。

## 8. 我们能做什么：候选形态与建议

### 8.1 四种候选形态

| 形态 | 描述 | 判定 |
| --- | --- | --- |
| A. 再做一个运行时框架 | 比 Mastra 轻、比 AI SDK 灵活的完整框架 | **否决。** 这一层已饱和（`ai` 周下载 2164 万，TanStack AI 与 Boss 诉求逐条命中），开发者对框架疲劳，无差异化。v0.1 走的就是这条路。 |
| B. 运行时无关的 harness 智慧层 | 把 CLI harness 里的智慧机制抽成可嵌入任意循环的库：上下文生命周期、治理与回放、自扩展、eval。核心是纯函数与接口，靠薄适配包接 TanStack AI、AI SDK、LangGraph、pi | **推荐。** 空白全在这里且聚成一层；有论文与官方证据支撑；符合"开发者拥有循环"；与现有运行时互补而非竞争，采纳阻力最低。 |
| C. 定义协议 + 参考实现 | 像 AG-UI 之于前端那样，为"agent 上下文生命周期"定一个跨语言协议 | **第三阶段再说。** 两个人先做协议会空转；但 B 的事件模型要为此预留，先在 TS 里被用起来再抽协议。 |
| D. 独立 agent 产品 | 像 OpenClaw、Hermes 那样的常驻应用 | **否决。** 与嵌入性目标相反，且这个位置已有 21 万到 39 万 star 的项目。 |

### 8.2 推荐形态：一句话

> 2026-09-08 修订：与 Boss 对齐后，定位收敛为两条原则之下的"整车"。**原则一：决策权默认在模型**，框架只做四件事：让它看见、给它能力、给它边界、给它记录。**原则二：时间线是唯一真源，角色只是翻译。**功能全部降级为原则下的可拆实例。产品定义与分期以 `docs/PRD.md` 与 `docs/技术方案.md` 为准，下文保留作推导过程。

**一个运行时无关的 TypeScript 库，把只存在于 Claude Code、Codex、dsh 这类独立 CLI 里的 harness 智慧机制，做成任何 agent 循环都能插入的中间件：让模型在长任务里看得见自己的上下文、自己决定何时压缩与交接、约束不随压缩衰减、大结果不撑爆上下文、经验能沉淀成能力、每一步可治理可回放可评测。它不拥有循环，不隐藏提示词，不绑 provider，不绑运行时，闲时零占用。**

对外的价值主张用三个可测量指标说话，不说"更聪明"：**每任务 token 与延迟**（对照阈值压缩与无压缩基线）、**治理衰减**（压缩前后约束违规率）、**长任务存活**（跨压缩、跨会话、跨重启后关键信息召回）。

### 8.3 模块与分期

**第一期：上下文生命周期 + 事件日志 + eval（核心，先做深）**

| 模块 | 内容 | 证据与借鉴 |
| --- | --- | --- |
| 上下文自感知 | 每轮向模型注入结构化状态：总量、各段大小与年龄、预算余量、上次压缩位置；按档位离散化以保 cache | 论文 2606.23525 的"proprioceptively blind"；Anthropic task budget 可选桥接 |
| 模型自决压缩 | `compact` 工具 + 规则提示（子任务解决、轨迹收敛时压；推导中途、卡住时不压）+ 阈值安全网 + 连续压缩上限 | 2606.23525 工具与规则缺一不可；Codex 死循环事故 |
| 压缩幸存契约 | 声明哪些内容必须存活于摘要：约束、目标、当前计划、关键事实；压缩后从真源重注入 | 2606.22528 Constraint Pinning 把违规率 30% 恢复到 0%；Claude Code 的"什么幸存于压缩"表 |
| 结果外溢存储 | 超阈值工具结果落到宿主 store，上下文只留 locator 与取回指引；同一 store 可挂进 code mode 沙箱 | Claude Code 25,000 token 落盘；dsh spill；框架层全部空白 |
| 会话交接 | `handoff` 工具：模型写经验式总结与触发消息，库建新会话、写交接记录、停当前循环；宿主实现锚点重绑回调 | anima switch_session v3 通用化 |
| 记忆 | provider 中立的文件式记忆工具，存储接口由宿主实现 | 形状对齐 memory_20250818 |
| append-only 事件日志与回放 | 所有模型输出、工具结果、审批、压缩摘要追加进日志；记录 model 与 tool 响应实现确定性 replay；任意事件可 fork | ActiveGraph 路线；一次解决审计、回放、fork、eval fixture |
| eval harness | 对照组为纯阈值压缩与无压缩；指标：任务完成率、总 token、关键信息召回、治理衰减、死循环计数、cache 命中率 | D8 保留；无 eval 的模型自决机制不上 |
| 适配器 | TanStack AI 中间件（`beforeModel` 注入与替换 providerMessages，工具接口注册 compact / handoff / memory）；随后 AI SDK v7 的 prepareStep 与 onStepEnd | Boss 的投放工具做第一个宿主 |

**第二期：治理与可编程性**

信任分层上下文模型（每条消息与工具结果带 provenance 与信任级，可传播可查询）；单一权限决策管线（deny 优先、拦截点无条件生效、决策本身是事件、fail-closed；暂停是 `run()` 的显式返回值）；principal 透传接口（只定义传播不做 IdP）；预算与循环上限并把用量作为事件发出；分层指令文件加载器；确定性验证 gate 加防死锁上限；钩子生态桥接（直接跑 .claude 与 .codex 的 hooks.json，采纳率杠杆）；AG-UI 事件映射。

**第三期：自扩展与协议**

技能生命周期（SKILL.md 载体、模型提 proposal、apply 是唯一写入、provisional → trusted 准入门、不可变 generation 与回滚、目录 digest 刷新、curator 维护；第一版只允许流程型技能不允许可执行代码；前置条件是宿主场景有跨任务复用结构）；LangGraph 与 pi 适配器；把事件模型抽成跨语言协议草案。

### 8.4 明确不做

- 不拥有 while 循环，不做运行时，不做 provider 层，不做传输层
- 不自造前端流协议，AG-UI 为一等输出，AI SDK UI stream 做 adapter
- 不自带调度器、持久执行引擎、记忆后端、IdP，只提供接口与唤醒入口
- 不做平级 mailbox 与 swarm，多智能体只提供 asTool 与 handoff 两种组合加预算闸
- 不在核心路径用 child_process、node:vm、真实文件系统
- 不做 MCP 动态注册（规范禁止），模型自建能力走进程内

### 8.5 与最接近对手的差异

| 对手 | 它有的 | 我们的差异 |
| --- | --- | --- |
| Letta | 唯一把"模型拥有自己的上下文"写成纲领；MemFS、自建 skills、dreaming | 它是子进程 harness 产品，绑自己的运行时；消息历史压缩仍由系统自动。我们是进程内库、运行时无关、压缩决策交给模型 |
| pi-agent-core | 真 provider 中立，11 个 hook，压缩，skills 加载 | 它是运行时，无幸存契约、无自感知、无治理、无 eval。我们可以做它的上层，也能做它的适配器 |
| Mastra | 权限策略、goal judge、observational memory | 解包 64MB 的全家桶；明确拒绝把压缩决策给主模型。我们轻量且立场相反，需用 eval 证明 |
| Claude Agent SDK | 33 个 hook、幸存契约、fork、预算，最完整 | spawn Claude Code 二进制，绑 Anthropic 模型，暂停不可序列化。我们把同类机制做成中立库 |
| TanStack AI / AI SDK | 运行时最好用 | 它们是我们的宿主，不是对手 |

### 8.6 第一期验收标准

一个 TanStack AI 项目加两个中间件、实现一个 store 接口，就能得到：模型看得见自己的上下文状态并自主压缩与交接；压缩前后约束违规率不上升；超大工具结果不进上下文；任意会话可从事件日志完整回放并在任意点分叉；随包 eval 给出对照阈值压缩的 token、完成率、召回、cache 命中率四项数据。
