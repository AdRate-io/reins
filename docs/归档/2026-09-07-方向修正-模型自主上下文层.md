# 方向修正：不做运行时，做"模型自主上下文层"（讨论稿 v0.2）

> 日期：2026-09-07
> 状态：替代 v0.1 的定位部分；v0.1 中事件日志、复用 pi-ai 等技术结论保留但降级为实现细节
> 依据：三路并行调研，对 TS Agent 运行时、模型自决记忆/压缩、模型自扩展三个领域按 2026-09 现状逐项核实（来源见文末）

---

## 0. v0.1 跑偏在哪

Boss 的原始诉求有四条：① 轻量嵌入 TanStack 产品，闲时零占用，有会话才组装上下文；② 工具与上下文存储灵活可配；③ 模型对自身上下文有充分决策权（自主压缩、整理记忆、带经验进入下一段）；④ 像 dsh 那样模型能快捷灵活地给自己加能力。

v0.1 的问题：

| v0.1 写的 | 与诉求的冲突 |
| --- | --- |
| D4：可插拔点是有限枚举的接缝，不借"万物皆插件" | 直接否掉了诉求 ④ |
| D7："上下文管理交给模型"只是一个内置配方 | 把诉求 ③ 从核心身份降成了可选项 |
| 全文未讨论运行形态 | 诉求 ① 完全没有回应；且 MCP stdio 子进程工具与"闲时零进程"相悖 |
| "第一版只服务自己项目，不为陌生人付元框架成本" | Boss 要的是有差异化价值的开源项目 |
| 80% 篇幅在事件 schema 版本、降级矩阵、八个元基础 | 这些正是现成运行时已经做好的部分，差异化最低 |

一句话：**v0.1 在设计一个运行时，而 Boss 要的是运行时之上那层"模型的自主权"。**

## 1. 2026-09 现状核实：哪些已经有了，哪些是空白

### 1.1 运行时层：已被解决，不值得重做

| 诉求 | TanStack AI 0.53 | Vercel AI SDK v7 | LangGraph.js 1.4 | pi-agent-core 0.85 |
| --- | --- | --- | --- | --- |
| 闲时零进程 | `chat()` 是函数不是对象，无生命周期 | Agent 无状态，每次传 messages | 纯库 4 个依赖 | 低层 Agent 连 Session 都不需要 |
| 自定义存储 | `loadThread`/`saveThread` 两个函数；空 messages = 从存储续跑（官方契约） | 零抽象，自己写 | checkpointer 5 方法 + 官方验证套件 | Storage/Session/SessionRepo + conformance 套件 |
| 循环钩子 | 19 个钩子 7 个 phase，`beforeModel` 可改 messages/tools/prompts，`onBeforeToolCall` 可改参/跳过/中止 | `prepareStep`/`prepareCall`/`onStepStart|End`/`onToolExecutionStart|End` | `wrapModelCall`/`wrapToolCall` | `transformContext`/`before_payload`/`beforeToolCall` |
| 双视图（存全量、送裁剪） | 内置：`messages` 为真源，`providerMessages` 为送模型视图 | 自己维护 | 自己维护 | `transformContext` 非破坏 |
| provider | 16 adapter + 5 harness adapter | 约 38 包 | 依赖 LangChain 抽象 | 约 40 个 |
| 风险 | pre-1.0，周更 minor，无 TanStack Start 官方示例 | Node≥22 纯 ESM | 吞下 LangChain core | 每月一次 breaking，8 月刚重写 session API |

结论：**TanStack AI 与 Boss 的四条运行时诉求逐条正面命中**，且与项目技术栈同源。Vercel AI SDK v7 是稳妥的第二选择。pi-agent-core 设计最强但不宜做依赖。Mastra、VoltAgent 偏重（解包 64MB / 13MB），Cloudflare Agents 在 Node 里 import 即崩，Inngest AgentKit 半停滞。

v0.1 打算自写的事件日志、降级层、循环、装配，在这些库里都有对应物。自己再写一套没有差异化价值。

### 1.2 模型自决"记忆"：已成熟

- Anthropic memory tool（`memory_20250818`）：模型自己 view/create/str_replace/delete 文件，存储由宿主实现，TS SDK 有 `betaMemoryTool` helper。
- Claude Code auto memory：官方原话 "Claude decides what's worth remembering"。
- Letta MemFS：git 版本化记忆文件系统，agent 可改自己的 system prompt、自建 skills；Context Constitution 是唯一把"模型拥有自己的上下文"写成纲领的文档。但 TS SDK 的 local 模式是子进程包装，不是进程内库。

### 1.3 模型自决"何时压缩上下文"：全线空白，这是核心缺口

核实过的所有生产级压缩实现，**没有一个把"何时压缩"交给模型**：

| 实现 | 决策者 |
| --- | --- |
| Anthropic `compact_20260112` | 服务端 `input_tokens` 阈值，唯一支持的 trigger 类型 |
| Anthropic context editing | 服务端规则；模型只在临界前收到一次"保存重要信息"警告 |
| OpenAI `compact_threshold` / `/responses/compact` | 服务端阈值 / 开发者决定 |
| Claude Code、Codex CLI、Cline | 阈值 + 手动斜杠命令 |
| Mastra Observational Memory | 旁路模型 + 阈值；文档原话：**设计上刻意把决定从主 agent 手里拿走**，理由是 agent 不暂停、prefix cache 稳定 |
| Vercel AI SDK `prepareStep` + `pruneMessages` | 开发者写阈值 |
| TanStack AI `withCompaction` | 框架 `maxTokens` 阈值 |
| pi-agent-core | 框架阈值（用 provider 真实 usage） |
| Letta | 消息历史压缩仍由系统自动 |

唯一的实证是论文 Self-Compacting Language Model Agents（arXiv 2606.23525，2026-06）：

- 结论一：**工具与规则必须成对**。只给压缩工具，模型要么乱调要么不调；规则内容是"子任务已解决、轨迹收敛时压；推导中途、卡住时不压"。
- 结论二：比固定间隔压缩**成本低 30~70%**，质量不降，数学最高 +18.1 分，agentic search +5~9 分，training-free。
- 结论三：模型对自己的上下文是"proprioceptively blind"，看不出各块多大、多旧。这是需要框架补的感知信号。
- 代码是 Python 研究原型，8 star。**TS 生态零实现。**

配套的官方原语只有 Anthropic task budget：服务端向模型注入只有模型可见的剩余预算倒计时。但它只给 token 余额不给结构信息，Sonnet 5 不支持，客户端改 remaining 会打断 cache。

### 1.4 模型自扩展（写 skill → 持久化 → 下次可用）：TS 空白，且收益证据两面

- 载体已有事实标准：Agent Skills 规范（SKILL.md），40+ 客户端支持，有 TS 校验库。**不要自己发明格式。**
- 完整闭环（生成 → 准入门 → 检索 → 维护）的开源实现全是 Python：OpenSpace（可作 MCP server 挂任意 host，provisional → trusted）、SkillOpt（held-out 严格提升才接受编辑）。TS 侧只有 `@cloudflare/codemode` 的 Snippets，绑 Cloudflare。
- 所有成熟实现独立收敛到同一条：**必须有验证门才入库**，Voyager 去掉 critic 掉 73%。
- 负面证据：ContinualSkillBench 显示显式技能库对比"把反馈留在 context 里"平均打平；SkillFlow 在 Terminal-Bench 上"检索到了、用了、零提升"。正面证据 SkillsBench +16.6pp 出现在任务有真实跨任务复用结构时。
- 安全：26.1% 社区技能含漏洞；自演化 agent 有自毒化与 revision churn 问题，需要版本化、可回滚、对冻结快照执行。

### 1.5 dsh 现状与"万物皆插件"的真实形态

- 仓库 2026-08-13 创建，MIT，npm 最新 0.1.2-rc.1，README 大写警告会有破坏性变更；内核 Cordis 4.0.0-rc.9 自称 API 未稳定。
- "万物皆插件"的机制：每个部分（模型适配器、工具注册表、会话日志、agent loop 本身）都是 Cordis 插件，通过 `package.json` 的 `dsh` 字段声明 bundle/patch，profile 是真实 npm 项目，叠加顺序固定。**这是开发者侧的可组合性，靠一个元框架换来的。**
- 模型运行时自加能力有两条路，都有硬限制：
  - `dsh-tool-cordis`：模型现场写 Cordis 插件，可注册新工具、prompt 贡献、监听器，失败可自主重试。**但定义只在进程内存，重启即消失；纯 JS 沙箱且官方明说沙箱不是安全边界；不在任何交付 profile 里。**
  - 写 SKILL.md：模型用 write/edit 写入 `.dsh/skills/`，每步前算目录 digest，变了就整值替换注入，落盘持久。**但没有专用的 skill 管理工具，模型面向的只有一个 loader。**
- 运行形态：新增了 `dsh-sdk-client`，但仍是子进程 stdio JSON-RPC；架构文档明确排除进程内挂载，并有 CI 脚本拒绝绕过 `dsh` 的 Node 入口。
- 值得直接抄的一条：**技能目录的失效与刷新机制**（写入观测失效 + 每步 digest diff + 整值替换注入），这就是"模型写了 skill，下一轮就能用"的最小实现。

对比其他两个自增能力最完整的项目：Hermes Agent 给模型 `skill_manage` 六个动作加后台 self-improvement 与 curator 整合，Python 独立应用；OpenClaw 让 agent 只能提 proposal、apply 才是唯一写入，SQLite 存 canonical 记录、磁盘按不可变 generation 存、原子 rename 后再提交，TypeScript 但定位是 Gateway 常驻进程。

### 1.6 MCP 不能承载"模型自建工具"

MCP 规范 2026-07-28 版明确：工具集 **MUST NOT 按连接变化或作为其他请求的副作用变化**，只允许按时间和鉴权凭证变。`list_changed` 改为必须走订阅流，且 Claude Code、Gemini CLI、Vercel AI SDK 都不处理该通知。结论：**模型给自己加的能力必须走进程内注册，不走 MCP。** MCP 保留为宿主接外部工具的通道。

## 2. 重新定位

### 2.1 一句话

**一个运行时无关的 TS 库，把"模型对自身上下文与能力的自主权"做成可嵌入的中间件：模型能看见自己的上下文状态，自己决定何时压缩、何时交接会话、记住什么、给自己加什么能力；库负责感知信号、工具、准入门、安全网与评测。第一版以 TanStack AI 中间件形态交付。**

它不是运行时。运行时用 TanStack AI（或 AI SDK v7），我们只站在它的 `beforeModel` 钩子和工具接口上。

### 2.2 与现有项目的差异（这就是价值主张）

| | 现有做法 | 我们 |
| --- | --- | --- |
| 压缩时机 | 框架/服务端阈值 | 模型调 `compact` 工具，配规则提示；阈值只做安全网 |
| 上下文感知 | 模型盲 | 每轮注入结构化状态：总量、各段大小与年龄、预算余量、上次压缩位置 |
| 会话交接 | 无标准契约，各家自造 | 模型调 `handoff`，写一段"经验式总结"进入新会话；宿主只需实现锚点重绑回调 |
| 记忆 | 已成熟（Anthropic memory tool） | 复用其形状，provider 中立，存储走宿主 |
| 自扩展 | Python 有闭环，TS 空白 | SKILL.md 载体 + provisional→trusted 准入门 + 版本化回滚，进程内 TS |
| 评测 | 无人评"压缩时机决策质量" | 随库交付最小 eval：对比阈值压缩的任务完成率、总 token、关键信息召回、无死循环 |
| 形态 | Letta 是子进程 harness，Hermes 是独立应用 | 进程内库，闲时零占用，随宿主请求生灭 |

最接近的对手是 Letta 的 Context Constitution 理念，但 Letta 是一个 harness 产品，TS 侧仍是子进程；而且它的消息历史压缩也还是系统自动的。**"进程内、运行时无关、模型自决压缩"这个位置目前没有人占。**

### 2.3 必须正面回答的两个反对意见

1. **Mastra 的反对：模型自决压缩会打乱 prefix cache、让 agent 暂停。**
   回应：压缩只在轮次边界执行（工具调用本身就是轮次边界）；状态注入放在 system 之后、历史之前的固定位置并按档位离散化（70%/80%/90%），不是每轮变化的数字，避免每轮打散 cache；压缩产物追加而非改写（v0.1 的 append-only 日志思想保留在这里）。这些都要用 eval 里的 cache 命中率指标验证，不是嘴上说。
2. **论文的警告：只给工具不给规则，模型会乱用。**
   回应：规则提示是库的一等交付物，不是文档建议；同时保留阈值安全网兜底"该压不压"，并设连续压缩次数上限防死循环（Codex 事故）。

## 3. 第一版范围

### 3.1 做

| 模块 | 内容 | 依托 |
| --- | --- | --- |
| 感知 | `beforeModel` 钩子注入结构化上下文状态（分档），可选桥接 Anthropic task budget | TanStack AI `onConfig` |
| `compact` 工具 | 模型给出保留要点与覆盖范围；库生成摘要块替换 `providerMessages` 对应段，真源 `messages` 不动 | TanStack AI 双视图 |
| `handoff` 工具 | 模型给出经验式总结与触发消息；库建新 thread、写交接记录、停当前循环；宿主实现 `onHandoff` 重绑 | 通用化 anima switch_session v3 |
| 记忆工具 | provider 中立的 view/create/replace/delete，存储接口由宿主实现 | 形状对齐 memory_20250818 |
| 规则提示 | 迁移 anima CONTEXT_MANAGEMENT_PROMPT 语义 + 论文 rubric，去专有词 | anima |
| 安全网 | 阈值兜底压缩、连续压缩上限、每档只提醒一次 | TanStack AI `withCompaction` |
| eval | 四项指标：任务完成率、总 token、关键信息召回、死循环计数；对照组为纯阈值 | 自建，D8 保留 |

### 3.2 第二版再做

- 自扩展：SKILL.md 载体、provisional→trusted 准入门（借 OpenClaw 的 proposal→apply 与不可变 generation）、目录 digest 刷新（借 dsh）、宿主存储、进程内注册不走 MCP。第一版只允许模型自建"流程型技能"（提示词与工具编排），不允许自建可执行代码，避开沙箱安全问题。前置条件：先用 §1.4 的判据确认投放工具场景有真实跨任务复用结构，再动手。
- AI SDK v7 适配器：核心保持运行时无关，只暴露"给我当前 messages 与预算，返回注入内容与工具定义"。

### 3.3 不做

- 自写运行时、事件日志、provider 降级层（v0.1 §2、§4、§5 全部撤销）
- 万物皆插件的元框架（dsh 那种零特权内核）
- MCP stdio 子进程工具作为默认（与闲时零进程相悖；宿主要用可自行接 TanStack AI 的 MCP 支持）
