# "动过手"的收尾结果带调用开始时间（AdRate 建议 10）

> 状态：✅ 已完成（2026-11-09）

## 背景与根因

AdRate 建议 10（`docs/archive/2026-11-05-AdRate给reins的优化建议.md` 末节）：不可重放的调用开始动手后中断，core 补的结果是固定文案 `OUTCOME_UNKNOWN_TEXT`，不带时间。模型"先查再定"时要在查回的业务对象里认出"是不是这次提交"；参数完全相同的旧任务与这次唯一的区别是创建时间，而模型看不到事件的 `at`，没有时间锚点。AdRate M3-3a 剧本 6e'（DeepSeek）两次都把更早一次同参数任务认成了这次提交。

这是感知缺口（宪法 1"让它看见"）：库只补时间锚点，"哪条是这次"仍由模型判。

AdRate 已确认：其工具输出的任务时间是 UTC ISO 8601、带 `Z`、毫秒精度；任务创建时间由同机数据库在调用执行中写入，必然晚于开始时间。

## 具体设计

- core `loop/stop.ts` 新增两个纯函数（真源索引登记）：
  - `toolStartedAt(timeline): Map<toolCallId, at>` —— 取 `core.tool_started` 的 `at`；`startedToolCallIds` 改为由它派生（返回类型不变）。
  - `withStartedAt(text, at)` —— `at` 是有限数时在句末缀 ` This call started at <Date#toISOString()>.`，否则原样返回。
- **缀在句末而非句中**：五句常量仍是实际文案的逐字前缀，宿主按 `startsWith` 判断不受影响；规则只有一条。
- **毫秒精度、不截秒**：与 AdRate 的时间格式同类，`toISOString()` 原样输出，不自造格式。
- **范围 = 所有说"动过手"的结果**：`OUTCOME_UNKNOWN_TEXT`（三处：停止收尾、续跑见 started、感知 signal 的写工具被掐断）与两句"做了一半"（`STOPPED_IN_PROGRESS_TEXT` / `INTERRUPTED_IN_PROGRESS_TEXT`）。两句"没执行"不带——没开始就没有开始时间。
- **时间源只有 `core.tool_started`**：凡落这几句的路径，前提都是该调用已有 started（runLoop 掐断路径在 execute 前刚写）。不取 `tool_call` 兜底——取不到说明前提不成立，原样文案即可。
- TanStack 适配器：`Verdict` 的 `unknown` 带 `startedAt`，两处落"结果未知"走同一函数。
- 不改事件结构、不加状态；时钟是循环的 `now()`（宿主可注入）。

## 公开行为变化

被拼接后的文案不再 `===` 常量。core minor（0.13.0）、adapter-tanstack-ai / agent 随依赖升；changeset 写明"用 `startsWith` 判断"。
