# 暂停原因码（AdRate 建议 16）

> 状态：✅ 已完成（2026-11-23）

## 背景与根因

AdRate 建议 16（`docs/archive/2026-11-05-AdRate给reins的优化建议.md` 末节）：Socket 的 `onTurnEnd` 只能返回 `pause: { reason: "budget" | "host"; note? }`。`note` 只进本次返回的 `Interruption`，落库的 `core.run_paused` 只有 `{ reason, state, awaiting, stopped? }`，`RunStatus` 也只带 `reason`。事后（另一个请求、另一个进程、列表轮询）只看得到 `budget` 或 `host`，分不清是谁、为什么停的。

AdRate 的三个场景：积分用完与整理失败都报 `budget`，后台结算只能再查一次余额猜原因，用户已充值就猜错；前端只能统一显示"继续"，积分不足要等点了继续才出"去充值"；续跑时宿主想给模型补一句说明也只能猜。

核实源码，根因是**暂停的原因只活在一次返回值里，不在时间线上**（与建议 8 的续跑状态、建议 12 的会话状态同一类缺口）。我们自己也有三处落库后分不清：

| 来源 | 位置 | 落库的 reason |
| --- | --- | --- |
| `budget()` 触顶 | `brain/src/budget/budget.ts` | `budget` |
| `compact()` 连续整理达到上限 | `brain/src/compact/compact.ts` | `budget` |
| 循环自带的 `maxTurns` 兜底 | `core/src/loop/run-loop.ts` | `budget` |

宿主今天的绕路办法是 Socket 暂停前自己 `emit` 一条 `ext.*`（`endTurn` 先 flush 再暂停，写得进去）。但 `pgRunStates` 只读最后一条 run 标记，宿主要再查一次，丢掉"一条 SQL 一个快照"的保证，不算解法。

## 方案

| | 做法 | 判断 |
| --- | --- | --- |
| A（选） | `pause` 加可选原因码 `code`，随 `note` 一起写进 `core.run_paused`；`RunStatus.paused` 带出 `code`；内置三处各给一个码 | 原因进时间线（宪法二）；`reason` 仍是闭集，库不按 `code` 做任何分支 |
| B | 把 `reason` 放开成任意字符串 | 否：宿主对 `reason` 的穷尽判断、`pauseReasonOf` 的优先级都依赖闭集 |
| C | 自动记下给出意见的 `socket.name` | 否：一个 Socket 可以有两种原因（余额用完 / 账户冻结），名字分不开 |
| D | 加开放的 `detail: Record<string, unknown>` | 否：状态查询是给机器分类的，开放袋子会越装越大；余额这类数据宿主照旧写自己的 `ext.*` |

### 公开形状

```ts
// ---- core：Socket 的暂停意见 ----
export type TurnDecision =
  | "continue"
  | "stop"
  | { handoff: HandoffIntent }
  | { pause: { reason: "budget" | "host"; code?: string; note?: string } }

// ---- core：中断（实时返回）----
export type Interruption =
  // …
  | { kind: "budget"; note: string; code?: string }
  | { kind: "host"; note: string; code?: string }

// ---- core：run_paused 载荷（只加可选字段，不升 schemaVersion）----
interface RunPausedPayload {
  // …
  /** 这次暂停的原因码：Socket 给的，或内置来源的 `reins.*`。只是标注，库不按它做任何分支 */
  code?: string
  /** 给人看的说明，与本次 `Interruption.note` 同一句。排查用，不进 RunStatus */
  note?: string
}

// ---- core：会话运行状态 ----
// RunStatus 的 paused 一支多一个可选字段
{ state: "paused"; seq; endedAt; reason; stopped; awaiting; code?: string }

// ---- core：新增导出（真源）----
/** 原因码的格式：小写字母数字开头，其后小写字母 / 数字 / `_` `.` `:` `-`，总长 1～64 */
export const PAUSE_CODE_RE = /^[a-z0-9][a-z0-9_.:-]{0,63}$/
export function isPauseCode(x: unknown): x is string
/** 循环自带 maxTurns 兜底的原因码 */
export const MAX_TURNS_PAUSE_CODE = "reins.max_turns"
/** Socket 的暂停意见 → 一条中断（补缺省 note、校验 code，不合规抛 RangeError）。runLoop 与 TanStack 适配器共用 */
export function socketPauseInterruption(pause): Extract<Interruption, { kind: "budget" | "host" }>
/** 中断列表 → run_paused 里的 { code?, note? }：取 budget / host 那一条（至多一条） */
export function pauseDetailOf(interruptions: readonly Interruption[]): { code?: string; note?: string }

// ---- brain ----
export const BUDGET_PAUSE_CODE = "reins.budget"
export const COMPACT_STALLED_PAUSE_CODE = "reins.compact_stalled"
interface BudgetOptions {
  // …
  /** 原因码，缺省 BUDGET_PAUSE_CODE；要按触顶维度区分的宿主自己算（与 note 选项对称） */
  code?: (hits: readonly BudgetHit[]) => string
}

// ---- ui-agui ----
// budget / host 中断带 code 时：{ id, reason, message, metadata: { code } }
```

### 规则

- **`code` 只是标注。** 库不解释、不按它做分支；续跑语义、`pauseReasonOf`、签名材料、`configHash` 都不看它。`code` 不进 `SerializedRunState`。
- **`reins.` 前缀留给内置来源，靠约定不靠校验。** 循环分不出一个 Socket 是内置的还是宿主的；宿主用自己的前缀（如 `adrate.credits_exhausted`）。
- **写入口径只有一处。** `pause()` 用 `pauseDetailOf(interruptions)` 取 `code` / `note` 写进 `run_paused`，所以循环自己的暂停（`maxTurns`、宿主中止、用户停止）的 `note` 也一并落库；审批 / 客户端工具 / 子代理的暂停没有 budget / host 那条，两个字段都不写。用户停止盖过 Socket 的暂停意见（`pause()` 里停止优先），此时 `code` 不写。
- **不带码的暂停**：宿主中止、丢租约、用户停止不给码。用户停止已有 `stopped`；其余几种"在哪一步被中止"对宿主不构成不同的动作。
- **格式不合规以 error 收口。** Socket 返回的 `code` 不满足 `isPauseCode` 时，runLoop 走 `fail({ category: "input", detail: { phase: "onTurnEnd" } })`，TanStack 适配器写同样的 `core.error` + `run_ended(error)` 并结束。依据是现成先例：`pullInput` 返回值不合规就是这样收口（确定性的宿主代码错误，fail-closed）。run 照样停下，边界守住；原因码写错的 Socket 第一次暂停就会暴露。不新增错误分类，免得宿主的终态分类跟着漂。
- **读侧守卫。** `runStatusOf` 见到 `code` 在场却不满足 `isPauseCode` 判 `unknown`（与 `stopped` / `awaiting` 的形状守卫同口径）；`note` 不进 `RunStatus`，不守卫。
- **子代理不上浮。** 子会话因带码的原因暂停时，实时返回的 `SubagentInterruption.interruptions` 里自然带着子的 `code`；父会话的 `run_paused` 不写它，事后按 `awaiting[].childSessionId` 查子会话（与"不往父会话上浮子状态"同一边界）。
- **内置码不编维度。** `budget()` 可能多维同时触顶，一个字符串装不下；缺省 `reins.budget`，维度在 `note` 里，要机器可读就用 `code` 选项自己算。
- **兼容**：新旧版本混跑安全。老 core 读带 `code` 的事件会忽略未知字段；老事件读出来 `code` 为 undefined。

### 与评估时口头方案的一处偏差

评估时说的是"格式不合规时照常暂停、丢掉 `code` 并告警一次"。落笔前核实，core 没有告警出口（`warn` 只在 brain / server / 适配器里），照做要么给 core 新开一个出口，要么静默丢弃。改为上面的 error 收口。没变的是：run 一定停下、不合规的码不会进时间线。

### 不做

- 不把 `reason` 放开，不加 `detail`，不自动记 Socket 名字（见方案表）。
- 不自动把"上次为什么停"告诉模型。这是行为改动，目前没有模型因此做错的样本；宿主可按 `code` 自己写一条说明（进程内 `input` 收 `system_note` 草稿）。
- 不给宿主中止 / 丢租约编码。
- `note` 不设长度上限（宿主自己的文本，与 `core.error.message` 同待遇）。

## 方案审查（2026-11-23，独立子代理）

审查只给代码与需求原文，不给结论。变异 19 处拦住 18 处。采纳后与上文的偏差如下，以全景图「核心设计决策」为准。

应修 3 条，全部采纳：
1. **不合规的处置从"以 error 收口"改为"改正后照常暂停"**。上文「规则」与「与评估时口头方案的一处偏差」两节写的 `fail()` 不再成立：码不合规就丢掉，改正处记一条模型不可见的非终结 `core.error`（category `input`、`detail.phase: "onTurnEnd"`），照常暂停。审查实测 `fail()` 有三处后果：非停止的中止落在工具批中途时，没执行的调用被带进 error 结局；用户停止遇到不合规码被盖成 error；TanStack 在已暂停的轮次上再写 error + run_ended。上文说"core 没有告警出口，只能二选一"漏了第三条路——非终结 `core.error` 是现成的声明方式（`pullInput` 抛错同款），`awaitingOf` 也早有同一条原则：一个元数据字段不能把暂停变成崩溃。函数随之改名 `resolveSocketPause`，返回 `{ interruption, error? }`，永不抛错。
2. **TanStack `onShouldContinue` 在本 run 已写过终结事件时不再问 Socket**。既有缺口：工具阶段因客户端工具 / 审批写了 `run_paused` 之后，Socket 的暂停或交接还会再落一条终结事件，盖掉"在等谁"。与 runLoop"有中断不进 onTurnEnd"同口径。
3. **`budget({ code })` 的示例照抄会出错**：五个维度名四个带大写，过不了格式。示例与 README 改成先转小写。

建议 5 条：
1. 采纳：`reason` 不在闭集（JS 宿主想自定义原因）按 host 暂停并记错——照原样写进去 `runStatusOf` 只能判 unknown。
2. 采纳：TanStack"不合规"用例首轮改成带工具调用（原先首轮是纯文本，"引擎没有再问模型"是空断言）。
3. 采纳：`PAUSE_CODE_RE` 只许收紧不许放宽，写进注释与 AGENTS.md。
4. 采纳：补漏掉的文档路由（store 盘点、brain README 的 compact 行、刻意不对称清单里 TanStack 的 `note`、fail-open 登记表一行）。
5. 未采纳：`note` 的类型校验。它不进 `RunStatus`，宿主把怪值写进自己的日志只影响自己。

复核：五处变异（去掉 `s.ended` 守卫、暂停分支返回 true、两条路径各自不记改正错误、用原 reason 而不是改正后的）全部被新用例拦住。
