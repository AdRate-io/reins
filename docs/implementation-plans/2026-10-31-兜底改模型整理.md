# 兜底改由模型整理（OPT-261031-1）

> 状态：✅ 已完成（2026-10-31）

## 背景与根因

OPT-261030-3 已落地"过 75% 请模型整理一次"，官方线路照做 12/12。但 OnSet 走公司中转站（号池），长上下文末尾的**中途 system 说明送到了却不被执行**（踩坑 42：0/54 种措辞、暗号指令 0/6），同一说明改成 user 身份 + `<system_note>` 标签就照做（3/3）。OnSet 不愿把 `midConversationSystem` 整体关掉——那会让感知、钉住等所有说明都变成 user 身份。结果是 OnSet 上请求层基本失效，到 85% 几乎都落进机械裁剪，摘要只剩类型计数与清单。

Boss 的诉求：兜底尽量也由模型写摘要，宁可舍掉整理那一次的缓存。

## 方案对比

| | 做法 | 缓存 | 改动 | 判断 |
| --- | --- | --- | --- | --- |
| A（推荐） | 请求说明**单条**按 user 身份送达；请求分两级（75%、80%），85% 机械裁剪只兜两次都不理或一步越过三条线的情况 | 全程不额外丢；只有整理本身那次（机械裁剪同样要丢） | core 加一个可选字段；三条 fetch 线 + pi + TanStack 各一处分支；brain compact 两级；约 150 行 + 用例 | 在主对话里请模型整理，模型照做后接着干活，最贴宪法一 |
| B | 85% 时另发一次"只写摘要"的旁路请求（前缀不变、末尾加一句），拿到摘要落 compaction | 旁路请求前缀照命中；之后与 A 相同 | core 要给 Socket 或投影开"调模型"的口子（投影是纯函数，现在调不了），旁路输出怎么进日志（宪法二"模型可见 ⟺ 已记录"）、模型在旁路里调了别的工具怎么办都要新定；约 400 行，动公开接口 | 中转站上旁路请求的指令一样得走 user 身份，绕不开 A 的那个字段；收益只多覆盖"一步越过三条线"，而 spill 缺省把单个结果压在 16k（400k 窗口的 4%），这种跳跃很少 |
| C | 只留 compact 一件工具 | 实测 DeepSeek 1.7%、Haiku 0%（工具表是前缀的一部分） | 小 | 否：DeepSeek thinking 模式强制 tool_choice 400，不强制则只剩一件工具时模型照样可以回一段话就走 |
| D | 兜底整理交给宿主自己实现 | 视宿主 | 库里只加扩展点 | 否：每个宿主都会踩同一个坑（OnSet 已踩）；"驾驭经验"本该由库带；宿主想自定义已经可以 `force: false` + 自己的 Socket |

选 A。B 留作 A 上线后看数据的后手：若 OnSet 录像里"一步越过三条线"真的常见，再立项。

## 具体设计（A）

### core

- `SystemNotePayload` 加可选字段 `deliver?: "user"`：注入者声明"这条说明是要模型执行的指令，请以 user 身份送达"。只是提示，角色仍由降级层决定（宪法二：角色只在降级层出现）。可选字段，不升 schemaVersion。
- JSDoc 写清：只给需要模型**行动**的说明用；陈述类（感知、钉住）不用。

### 降级层

- lowering-fetch 三条线（chat / anthropic / responses 的 `system_note` 分支）：`capabilities.midConversationSystem && note.deliver !== "user"` 才走 system，否则走现有的 user + `<system_note>` 标签分支。落点仍记 `lossy(user-role)`，`note` 补一句"the note asked to be delivered as user"。共用层 `eventsToIr` 把 `deliver` 带进 IR。
- lowering-pi：`onPayload` 改写 system 的地方同样跳过 `deliver: "user"` 的条目。
- adapter-tanstack-ai：本来就全部走 user，无改动，矩阵用例补一条。
- 三份有损矩阵测试各加一条。

### brain / compact

- `force.at` 接受数字或升序数组，缺省改为 `[0.75, 0.8]`；每一级在"上次整理之后"只请一次（判据从时间线读：本段已有几条请求 = 已用掉几级）。
- 第二级文案更直接（"已请过一次……这是最后一次，下一步必须是 compact"），`render` 收到 `attempt` 序号。
- 请求说明缺省 `deliver: "user"`；`force.deliver: "system"` 可改回。感知等其他说明不变。
- `decidedBy` 判定不变：本段有过请求即 `forced`。

### 不动

投影链、85% 触发线与 60% 回落线、感知、spill、compact 工具与折叠算法、tool_choice、工具表。
