# 常驻快照按段刷新（OnSet 建议 5 的改写）

> 状态：✅ 已完成（2026-10-31）

## 背景与根因

OnSet 建议 5（`docs/archive/2026-10-30-OnSet反馈-compact与perception改进建议.md` 末节）：宿主在每次 run 的输入里附常驻上下文（角色记忆快照、正在处理的条目快照），压缩后这些内容随输入一起被折掉；宿主只能等下一次 run 再整份重附，而且不知道哪些还留着，会重复附。OnSet 提议加"压缩后钩子"，回调里给出被折 / 保留的事件。

与 Boss 讨论后的定位（2026-10-31）：问题的本质不是"压缩后补回来"，而是**压缩不该丢掉本色**。盘点压缩后各层的去留：

| 层 | 现状 |
| --- | --- |
| 宿主系统提示、Socket 规则、技能菜单、工具表 | 不在时间线，压缩碰不到 ✅ |
| pin（宿主 / 模型）、最近一条用户消息、感知说明 | 按契约幸存或每轮重给 ✅ |
| 宿主附在输入里的常驻上下文（记忆索引、条目快照） | **随输入被折掉** ❌ |
| 开局读过的记忆 / 技能正文 | 被折，可经清单 `recall` 或重读取回 ⚠️（任务线上的事，模型自己会去读；Boss 否决了"整理后提醒重读"） |

缺的是第三行：**会变、但该一直在手边的东西没有一个压缩不掉的位置**。宿主 pin 已经是"压缩不掉"的通道（OnSet 没装 pins），但它的抽取函数每轮比对、只能同步，定位也写成"一两句约束"，没人会把记忆索引放进去。

对照 Claude Code（Boss 认可的口径）：常驻的只放索引，正文按需取；索引是开场拍的快照，段内自己写记忆不刷新（写的过程就在上下文里）；**一压缩就按当前实际重拍一份**（写记忆的那段上下文被收走了）。

## 方案对比

| | 做法 | 判断 |
| --- | --- | --- |
| A（选） | pins 加一种宿主声明：`{ name, snapshot }`，只在"段起点"取快照、与视图里那份逐字比，变了才追加并取代旧的 | 从源头不丢：快照本身是 pin，压缩前后一直在；不动 core |
| B | OnSet 原提议：Socket 新钩子 `afterCompaction(ctx, compaction, { folded, survivors })` + 重附笔记标记 | 否：先丢再补，宿主要算"补什么、补没补过"；被折 / 保留在 `beforeModel` 里本就能从 `ctx.events` 与时间线算出，新钩子只是第二条路 |
| C | 宿主自己用 `extract` 每轮比对 | 否：段内自己写记忆也会触发刷新，视图里新旧两份并存；且只能同步，读不了异步存储 |

## 具体设计（A，审查后修订）

### 公开接口（brain / pins）

`PinSpec` 加第四种形态：

```ts
| { name: string; snapshot: (ctx: TurnContext) => string | undefined | Promise<string | undefined> }
```

快照 pin 的 `meta.pin` 多一个 `snapshot: true`（handoff 据此不带它，见下）。

### 时机（日志定）

"段"= 会话开头或最近一次整理（任何 `decidedBy`，含本轮投影新造的阈值兜底）之后到下一次整理之前。本 spec 在以下任一成立时调用 `snapshot`：

1. **段起点**：本段模型还没动过（无 `model_text` / `tool_call`）**且**本段还没有本 spec 的快照 pin。开场与整理后同一判据；后半句保证"取到了就不再取"，模型调用失败、只出 thinking、续跑都不会重复刷新。
2. **从没取到过**：完整时间线里没有本 spec 的任何 pin（老会话第一次装上、或此前一直取到空）。只为接入老会话；取到一次后不再适用。

判据是新的纯函数 `atSegmentStart(timeline)` 与"本段有无本 spec 的 pin"，放 `brain/src/shared/segment.ts`；compact 的 `modelActedSinceLastCompaction` / `timelineSoFar` 一并挪过去（`compact/request.ts` 原样 re-export，公开导出不变），避免 pins ↔ compact 互相引用。登记真源索引。

### 内容（数据定）

- trim 后为空 → 不追加。
- 与视图里本 spec 最后一条 pin 逐字相同 → 不追加（旧的本来就穿越了折叠）。
- 不同 → 追加 `system_note(kind=pin, meta.pin = { source: "host", spec, snapshot: true })`，`supersedes` 指向时间线里本 spec 的上一条。
- **本轮视图同步剔除旧的**：投影先于 beforeModel，此刻旧 pin 尚未被取代、仍排在摘要之后；若它已被某次整理覆盖（下一轮 fold 就会隐藏它），本轮就用 `events` 补丁把它从视图里拿掉——本轮请求与下一轮视图一致、只有一份，不为此多断一次缓存。未被覆盖的旧 pin 不剔，否则下一轮又冒出来。

### handoff

`carriedPins` 跳过 `meta.pin.snapshot` 的 pin：新会话就是新段，由它自己在段起点取一份当前的，而不是带过去一份旧的再被取代。

### 其它

- 只有声明了 `snapshot` 的实例返回 Promise；静态 / 抽取式路径保持同步，现有用例不动。
- `snapshot` 抛错照常抛出（与 `extract` 一致，fail-closed）；想降级的宿主在自己的函数里 catch 返回 undefined——JSDoc 写明。
- 构造期：`snapshot` 非函数拒绝；同一 spec 同时给 `extract` 与 `snapshot` 拒绝。
- 不加字数上限：pin 总量超过回落线时阈值兜底每轮都裁（审查第 5 条）属于宿主把全文当索引放，README 写明"只放索引"；不为此加代码。
- 刻意不做：core 新钩子、重附笔记标记、整理后提醒重读、memory 模块自动生成索引（"什么算索引"由宿主定）。

### 已知边界（写进 JSDoc / README）

- 段内别人（其它角色、宿主）改了记忆，本段看不到，下一次整理后才刷新——与 Claude Code 中途不刷新同一取舍；要实时就用 `extract`。
- 快照是 pin，永久占上下文：只放索引与简要状态，正文让模型按需读。

| 用例 | 判据 |
