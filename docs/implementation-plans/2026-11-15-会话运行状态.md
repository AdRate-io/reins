# 会话运行状态（AdRate 建议 11 / 12）

> 状态：📋 待实施

## 背景与根因

AdRate 建议 12（`docs/archive/2026-11-05-AdRate给reins的优化建议.md`「会话运行状态建议」）：会话列表要标出每个会话的状态：正在跑、等人处理、出错、跑完没看。宿主现在只能在 run 登记表外包一层，自己订阅最终信号、自己写状态表。这条路上 AdRate 碰到五个问题：假异常空档、新旧 run 互相覆盖、终态分类跟着版本漂、审批等待起点对不上、进程被杀拿不到终态。建议 11 要的是 `RunLease` 提供只读的"是否持有中"查询，用于删除会话时"运行中拒绝"；AdRate 现在是直读 `reins_runs`，自己写 SQL 判据。

核实源码后发现，根因不是"run 结局不在任何存储上"，而是**时间线上的终结记号不全**：

| 结局 | 时间线现状 |
| --- | --- |
| 暂停 | 有 `core.run_paused`，且一定是 run 的最后一条 |
| 交接 | 有 `core.handoff` |
| 出错 | 有 `core.error`，但不一定是最后一条：重试前那条（`detail.willRetry`）和 `pullInput` 回调抛错那条（category `host`）写完后 run 还在继续 |
| 正常跑完 | 什么都不写 |
| 进程被杀 / 生成器抛错 | 什么都不写（也写不了） |

另外还缺三样：
- "等外部答复的是哪些调用"分不出来。客户端工具的暂停原因记成 `host`，用户停止与断线中止也都是 `host`。
- 判断"在跑"只能拿 `acquire` 去探测。
- 先读租约、再读日志，两次查询之间有空档。

## 方案

| | 做法 | 判断 |
| --- | --- | --- |
| A（选） | 时间线补齐终结记号，每个 run 以恰好一条终结事件收尾；分类交给一个纯函数，输入是"租约 + 最后一条 run 标记"；store-pg 用一条 SQL 取同一时刻的快照 | 结局进时间线（宪法二），所有执行路径的结局都有记录；单条语句就是快照，没有空档；宿主不用迁移 |
| B | AdRate 原形态：`reins_runs` 加列、不删行，释放租约时一并写结局 | 否。结局只活在旁表，"跑完了"不在时间线上；只有经 handler 且配了租约的 run 才写，`agent.run()`、asTool 子会话、TanStack 都漏；宿主要做 DDL 迁移 |
| C | 不加事件，按日志推断"跑完"（最后一轮没有工具调用且无 pending） | 否。要靠启发式：Socket 可以在纯文本轮 continue；终结 error 要靠枚举非终结 error 来排除，往后每加一种 error 都得回来改 |

### 公开形状

```ts
// ---- core：新事件（模型不可见，运维事件）----
/**
 * run 的终结记号（暂停之外）。每个 run 恰好以一条终结事件收尾：暂停是 core.run_paused，其余三种结局是这条。
 * 暂停不写这条：server 补发判"末尾是带状态的 run_paused"才交出续跑凭据（handler.ts 的 resumableTailState），
 * 暂停后再落一条会让关页回来的客户端拿不到 state。
 */
export type RunEndedPayload =
  | { status: "done" }
  | { status: "handoff"; toSessionId: string }
  | { status: "error"; category: string }
// "core.run_ended": RunEndedPayload    （schemaVersion 1）

// ---- core：已有载荷加可选字段（只加可选字段，不升 schemaVersion）----
interface ToolsBoundPayload {
  // …
  /** 写入方承诺本 run 以终结事件收尾（0.14 起只有 runLoop 写 true；TanStack 适配器有不经终结钩子的出口，不写）。没有这个字段 = 判不出是否中断 */
  marksEnd?: true
}
interface RunPausedPayload {
  // …
  /** pending 调用中等外部答复的那些，从时间线算（awaitingOf）。用户停止收尾后为 []。TanStack 适配器写的 run_paused 不带（与 state 同） */
  awaiting?: AwaitingCall[]
  /** 这次暂停是停止（RunStop，用户或宿主收尾）造成的。与断线中止、丢租约中止（同为 reason host）区分 */
  stopped?: true
}
export type AwaitingCall =
  | { kind: "approval"; toolCallId: string; name: string; /** 该调用 approval_request 的 at（每个调用只写一次） */ requestedAt: number }
  | { kind: "client_tool"; toolCallId: string; name: string }
  | { kind: "subagent"; toolCallId: string; name: string; childSessionId: string; reason: PauseReason }

// ---- core：分类真源 ----
/** 会话里"最后一个 run"的标记事件类型；store 查最后一条标记时按这张表过滤（store-pg 绑参数，不在 SQL 里另写一份） */
export const RUN_MARKER_TYPES: readonly ["core.tools_bound", "core.run_paused", "core.run_ended"]

/** 纯函数：一段时间线里最后一条 RUN_MARKER_TYPES 事件。非 pg 宿主（内存 / SQLite、自己的登记表）用它取 lastMarker */
export function lastRunMarker(events: readonly Event[]): Event | undefined

export type RunStatus =
  | { state: "running" }
  | { state: "idle" }        // 没有任何 run 标记：新会话、交接目标会话还没起过 run
  | { state: "unknown" }     // 最后一个 run 没承诺收尾（老版本、TanStack），或标记读不出 / 形状不合规
  | { state: "interrupted"; seq: number; startedAt: number }
  | { state: "done"; seq: number; endedAt: number }
  | { state: "handoff"; seq: number; endedAt: number; toSessionId: string }
  | { state: "error"; seq: number; endedAt: number; category: string }
  | { state: "paused"; seq: number; endedAt: number; reason: PauseReason; stopped: boolean; awaiting: AwaitingCall[] | undefined }

/** 纯函数。held 来自租约；lastMarker 是原始行即可（函数内过注册表 upcast，再自己做形状守卫——注册表不校验 payload） */
export function runStatusOf(input: {
  held: boolean
  lastMarker: Event | undefined
  registry?: EventSchemaRegistry
}): RunStatus

// ---- store-pg ----
/**
 * 一条 SQL 取租约与每个会话最后一条 run 标记，再交给 runStatusOf。单条语句看到的是同一时刻的快照，
 * 而终结事件一定写在释放租约之前，所以任何时刻都处于"在跑"或"有标记"之一。
 * 前提：run 经 handler 起、且 handler 用租约登记（createAgent + pgStores 缺省即是）。agent.run()、asTool 子 run、
 * TanStack 路径不占租约，结局照样能查，"在跑"判不出（在跑时显示为 interrupted 或 unknown）。
 */
export function pgRunStates(client: PgClient, sessionIds: readonly string[]): Promise<Map<string, RunStatus>>
```

建议 11 不单独加 `RunLease.held?`。AdRate 只用 pg，删除会话前查 `pgRunStates(client, [id])` 是不是 `running` 就够了；少一个接口，也少一套一致性套件，"未过期"的判定在 store-pg 里只写一处。

### 规则

**终结事件（core `runLoop`）**

- done：`endTurn` 判 stop、`flush()` 之后，append `run_ended { status: "done" }` 再返回。`RunResult.lastSeq` 自然包含这一条。
- error：`fail()` 一次 append `[core.error, run_ended { status: "error", category }]`，同批原子写入。非终结的 `core.error`（重试前、`pullInput` 抛错）不带 run_ended。
- handoff：旧会话 append `core.handoff`，新会话写入开场之后、调 `onHandoff` 之前，在旧会话 append `run_ended { status: "handoff", toSessionId }`。开场写失败时 run 抛错，旧会话判 interrupted，这与"交接没完成"的事实一致。
- paused：仍只写 `run_paused`，并加两个字段：
  - `awaiting` 用纯函数 `awaitingOf({ timeline, pending, tools, interruptions })` 计算，以时间线的 pending 为准，**不从 interruptions 推**。起步时已中止的 run，以及工具批中途中止（`break` 之后排在后面的调用），interruptions 里都没有这些调用，但它们可能仍在等审批。
  - 判法：pending 调用如果有 approval_request 而没有 approval_decision → approval（`requestedAt` 取那条请求的 `at`）；否则工具按 `isClientTool` 判是客户端工具 → client_tool；否则本次 interruptions 里有它的 subagent 冒泡 → subagent；都不是就不列（没执行、下次补跑）。
  - `isClientTool(tool)` = `!tool.execute || tool.side === "client"`，从 `executeBatch` 抽出来，两处共用。
  - 找不到对应事件时只跳过该条，**不抛错**：一个元数据字段不能把暂停变成崩溃，否则续跑凭据就丢了。
  - `stopped: true` 在 `texts` 有值（RunStop）时写。
- 起步：把 `tools_bound` 挪到 `run_resumed` / `approval_decision` 之前，两者都在续跑校验之后。这样 tools_bound 是每个 run 的第一条事件（起步时已中止的 run 不写，但它会写 run_paused）。原来的写法下，进程如果死在写完 approval_decision、还没写 tools_bound 之间，状态会停在旧的 paused(approval)，而那个调用其实已经有了结论。审批类事件模型看不见，换序不影响模型看到的内容。tools_bound 带 `marksEnd: true`。
- 生成器抛错（续跑校验不过、`seq_conflict`、存储故障、Socket 抛错）不写终结事件。续跑校验在 tools_bound 之前，最后一条标记仍是上一个 run 的结局，这样判是对的；起步之后才抛的判 interrupted。不兜底 catch 补写：`seq_conflict` 和存储故障本来就写不进去，补写只能覆盖一部分情形，反而让语义变模糊。
- 不变式用例：runLoop 的每个出口返回时，日志最后一条事件 ∈ {run_paused, run_ended}，且本 run 内只有这一条；第一条是 tools_bound（起步时已中止的除外）。

**分类（`runStatusOf`）**

1. `held` 为真 → running，不看标记。acquire 先于 tools_bound，这段时间里最后一条标记还是上一个 run 的。
2. 没有标记 → idle。
3. 标记读不出（未来版本），或形状守卫不过（status / awaiting / 时间字段不合规）→ unknown（fail-closed，不猜）。
4. `run_paused` → paused（老事件的 `awaiting` 为 undefined、`stopped` 为 false）；`run_ended` → 按 status 分；`tools_bound` 带 `marksEnd` → interrupted（`startedAt` 取它的 `at`），不带 → unknown。
5. `seq` 用来区分前后两个 run 的结局；`endedAt` 与事件 `at` 用同一时钟（循环时钟）。

已知误判窗口（写进 JSDoc 与 README，不用代码兜）：
- 续期抛错只告警、不中止（`leased-runs.ts`）。如果存储持续不可用到租约过期，而 run 还在跑，会误判 interrupted，下一次心跳恢复后自愈。
- 释放失败只告警。最多 ttl（缺省 30 s）内误判 running，删除也会被拒这么久。
- 进程被杀，要等租约到期后才显示 interrupted。
- 在 run 中途 `fork` 出来的会话会继承"未收尾"，判 interrupted（eval 探针用 fork，不受影响：它不查状态）。

**快照（store-pg）**

- `run-lease.ts` 抽出 `HELD_SQL = expires_at >= ${DB_NOW_MS}`，renew 与 `pgRunStates` 共用；acquire 的抢占条件是它的取反（写法不改，用例锁住口径）。
- SQL 思路：
  - `unnest($1::text[])` LEFT JOIN `reins_runs`；
  - 再 LEFT JOIN LATERAL 取最后一条标记：`type = ANY($2::text[])`，`$2` 绑 `RUN_MARKER_TYPES`，`ORDER BY seq DESC LIMIT 1`，走主键 (session_id, seq) 倒序；
  - 读 `data::text`，**复用 event-log 的解码**（含旧行二次编码的兼容分支，踩坑 47），不另写 `JSON.parse`。
  - 不加索引：终结标记通常就在末尾；被杀的长 run 和没有标记的老会话要倒扫，成本留在实施时用真库量一次。
- 入参：数组；空数组回空 Map；最多 500 个，每个是非空字符串，不合规按 `X must be …, got …` 抛；重复 id 静默合并（Map 天然去重）。结果包含每个入参 id，不存在的会话为 idle。
- READ COMMITTED 下单条语句看到语句开始时的快照。终结事件的 append 先于 release 提交：release 在 `ActiveRun` 收尾钩子里，收尾钩子在生成器返回之后执行。所以快照里只要租约已经不在，就一定看得到终结事件。这对 handler 的所有路径都成立：普通 POST、续跑、停止请求起的收尾 run 都经 `runs.create` 占租约；`abandon` 只发生在 begin 之前，不写任何事件，结果仍是上一个 run 的结局。

**TanStack 适配器**

- 写 `run_ended`，但 `tools_bound` **不带** `marksEnd`。原因是有些出口不调任何终结钩子：`InterruptReplaySignal`、其它中间件在 beforeModel / afterModel 发起的通用中断。这些出口之后时间线上只剩 tools_bound，判 unknown，不会被误判成 interrupted。这条路径本来也没有租约，"在跑"判不出。
- 三个终结钩子共用一个"本 run 已写终结事件"守卫。原因是 wait 路径返回之后如果连接被取消，引擎会在 `finally` 里再调一次 onAbort。没有守卫的话，`run_paused(approval)` 后面会再追加一条 `run_paused(host)`，把审批暂停盖掉。
  - `onFinish`：已写过 run_paused 的不写；做过 handoff 的写 `run_ended(handoff)`；否则写 `run_ended(done)`。
  - `onError`：`core.error` 与 `run_ended(error)` 同批写入。
  - `onAbort`：守卫通过才写 `run_paused(host)`。
- run_paused 不带 `awaiting` / `stopped`。

**各降级层与编码器**：`core.run_ended` 进 `DEFAULT_MODEL_INVISIBLE_TYPES`。各家的有损矩阵（fetch 三条线、pi、TanStack）都记 dropped（运维事件）；ui-agui 映射为 `CUSTOM`。老版本降级层遇到它会走 default 分支，结果是 dropped，向前兼容。

### 不做

- 不建状态表，不改 `reins_runs` 结构，不改 release 删行的语义；宿主不用迁移。
- 不加 `RunLease.held?`（见上）。
- 不提供 `startedAt` / `runId`。宿主不再自己写状态，就不需要"起跑时刻"来做条件更新；区分前后 run 用终结事件的 `seq`。interrupted 带 `startedAt`，因为它是唯一能说明"哪次没跑完"的信息。
- 不管已读：已读是宿主的产品概念，宿主拿自己的 `last_read_at` 与 `endedAt` 比。
- 不做推送。
- 不给 store-sqlite / 内存存储做批量查询。单进程宿主用 `runs.get(id) !== undefined` 当 held，用 `lastRunMarker(timeline)` 取标记，再调 `runStatusOf`。
- 不在 `runLoop` 里兜底 catch 补写终结事件。
- 子代理审批的等待起点不往父会话上浮：按 `awaiting` 里的 `childSessionId` 再查一次子会话的状态即可（AdRate 第一期不用 asTool）。

## 发版

- core minor（0.14.0，手改 `REINS_VERSION`）、store-pg minor、adapter-tanstack-ai minor（写入的日志形状变了）。server / agent / ui-agui 也升 minor：实时流多了一种事件，raw 编码下是新 type，AG-UI 下多一条 CUSTOM，按 type 严格 switch 的前端能看到这个变化。lowering-fetch / lowering-pi / brain / eval 等 patch。
- **滚动升级约束**写进 core CHANGELOG：老版本 core 读到 `core.run_ended` 会抛 `unknown_type`。多实例部署必须一次全部升到同一版 core，不能新老混跑；含这条事件的会话也回滚不到 0.13（与 0.10 引入 `tool_started` 时 CHANGELOG 写的 Rollback risk 同类）。
