# 补发带续跑状态（AdRate 建议 8）

> 状态：✅ 已完成（2026-11-06）

## 背景与根因

AdRate 建议 8（`docs/archive/2026-11-05-AdRate给reins的优化建议.md` 第四批）：签名的暂停状态 `SerializedRunState` 只在 `runLoop` 暂停时算一次，放进 `RunResult.state`，经 live 流的 `result` 帧发给当时挂在流上的客户端。时间线里的 `core.run_paused` 只有 `{ reason }`；GET（或带 `lastSeq` 的 POST）补发以 `end` 帧结束，只带 `sessionId` / `lastSeq`，ui-agui 编成 `RUN_FINISHED(replayed)` 也没有 `state`。

关页、刷新、第二个窗口、换设备回到等审批的会话：客户端从补发里看得到 `approval_request`、画得出确认卡，却拿不到 `resume`，批不了、也不能"不批而发新消息"。续跑凭据只活在一条连接里、不在时间线上——违反宪法二。

## 方案

| | 做法 | 判断 |
| --- | --- | --- |
| A（选） | 暂停时把**签好名的同一份状态**写进 `core.run_paused.payload.state`；补发结束时若日志末尾正是这条事件，`end` 帧带出它 | 状态反映暂停那一刻（配置摘要不在 GET 时重算）；一份来源，live 与补发同一个对象 |
| B | `run_paused` 只存配置摘要，补发时按日志 pending + 密钥现场签 | 否：多一条签名路径，两处算状态要靠真源函数锁同口径，换来的只是事件小几十字节 |
| C | GET 时按当前配置重算 | 否：暂停后改过的工具也会被签成"一致"，配置漂移校验失效（AdRate 已指出） |

### 公开形状

```ts
// core RunPausedPayload 新增可选字段（只追加可选字段，不升 schemaVersion）
/** 暂停那一刻签好的可续跑状态，与 RunResult.state 同一份；模型不可见。TanStack 适配器写的 run_paused 不带 */
state?: SerializedRunState

// core 新增纯函数（真源：补发判"末尾是否可续跑"只走它）
export function pausedStateOf(event: Event | undefined): SerializedRunState | undefined

// server StreamItem 的 end 项
| { kind: "end"; sessionId: string; lastSeq: number; state?: SerializedRunState }
// rawEncoder 的 end 帧 data 在有 state 时带 state；ui-agui RUN_FINISHED(replayed).result 同
```

### 规则

- `pause()`：先按日志算 pending，`lastSeq + 1`（即将落下的 run_paused 自己的 seq）入状态并签名，再 append `run_paused { reason, state }`；返回的 `RunResult.state` 是同一个对象。用户停止收尾后 pending 为空，状态照样写（与 live result 同口径），客户端看 `pendingToolCallIds` 决定画不画卡。
- 补发判据：补发读完后再取一次日志末尾，**末尾 seq 等于本次 `end.lastSeq` 且 `pausedStateOf(末尾)` 有值**才带。补发读完后末尾又前移（并发的续跑、停止收尾）就不给。注意给的是**最近一次暂停**的状态，不论原因：续跑之后到再次暂停前不给；停止、预算、中止各自又写一条带状态的 `run_paused`（停止后 pending 为空）。画不画审批卡看 `pendingToolCallIds` 与补发里的 `approval_request`，不看有没有 state。客户端 `lastSeq` 已在末尾、一条不用补发时也给。
- 状态被别的窗口抢先用掉时，现有校验 fail-closed：同时提交撞 `run_in_progress`（跨实例靠租约）；先者跑完后撞 `pending_mismatch` / `unknown_tool_call`；先者只续跑未给结论又停在同一批调用上，旧状态仍有效（批的还是同一批调用）。
- 安全：今天任何能 GET 挂上 live run 的主事人本就收到带状态的 result 帧，这次只是把可得时间延长到暂停之后，范围仍由 `authorizeSession` 定。

### 不做

- 不改 `SerializedRunState` 形状、不改续跑校验。
- 不在 `run_paused` 里存 `interruptions`：直接审批的卡从补发里的 `approval_request` 画；子代理暂停时子会话的审批请求在子日志里，缺省 `childSessionId`（`父会话:调用id`）可推出，自定义的推不出——记为已知限制，等宿主有需求再议。
- BUG-261105-2（只带 decisions 不带 resume 也能续跑）本方案不修；状态可从补发取到后"带结论必须带状态"才变得可行，另起。
