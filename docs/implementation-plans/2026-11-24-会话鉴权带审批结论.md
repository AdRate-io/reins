# 会话鉴权看得见审批结论（BUG-261105-2 第二步）

> 状态：✅ 已完成（2026-11-24）

## 背景与根因

BUG-261105-2（`docs/待处理任务.md`）：`runLoop` 与 server 都接受只带 `decisions`、不带 `resume` 的续跑。`run-loop.ts` 以 `resume !== undefined || ownDecisions.length > 0` 判"在续跑"，`validateResume`（签名、`pendingDigest`、配置漂移）只挂在"带了 resume"上；`decisions` 只对照本会话 pending id。

两个后果分开处理：

1. **完整性**（签名 / pending / 配置漂移）：改成"带 decisions 必须带 resume"就补上。2026-11-06 起状态可从补发 end 帧取回，这条路已可行；但它改了所有宿主的 HTTP 约定，AdRate 已确认总带 resume，OnSet 尚未确认。**本方案不做，等 OnSet 回复。**
2. **授权**（审批人与会话主人不是同一人）：就算带了 resume 也补不上——能 GET 会话的人都拿得到状态。`authorizeSession` 只拿得到 header（body 已读完），分不出这次请求在交审批结论，挡不住"用户自己批自己"。**本方案做这一半。**

另外文档与代码不符：AGENTS.md「鉴权与安全默认值」与全景图 R6 都写"审批结论只走签名保护的 decisions"。先改准。

## 方案选择

| | 做法 | 判断 |
| --- | --- | --- |
| A（选） | `SessionAuthzInput.decisions: readonly ApprovalDecisionInput[]`，handler 把已过壳校验的结论原样给（GET / STOP / 没带为空数组） | 宿主能分清"批准"与"拒绝"：AdRate 在用户不批而发新话时会带 `approved: false`（停止语义方案的宿主职责），只给布尔就会把这条也挡掉；只加字段，不改放行语义 |
| B | `carriesDecisions: boolean` | 否：上面那条——会话主人必须能拒绝，审批人才能批准，布尔分不开 |
| C | 只在带结论时新增 `method: "DECIDE"` | 否：按 `method === "POST"` 放行写的宿主会把所有续跑拒掉，是破坏性改动；与投递沿用 POST 的取向也不一致 |
| D | 现在就强制带 resume | 见上，等 OnSet |

## 公开形状（只加不改）

```ts
export interface SessionAuthzInput {
  // ...原有字段不变
  /**
   * 这次请求带的审批结论（已过壳校验，原样给出；GET / STOP / 没带时是空数组）。
   * `by` 是客户端自报的，不可信；判断审批权要看 principal。
   */
  decisions: readonly ApprovalDecisionInput[]
}
```

是输入接口新增必有字段：宿主实现 `authorizeSession` 不受影响；自己构造 `SessionAuthzInput` 的代码（测试桩）需补字段，按 minor 发。

## 不做

- 不改 `runLoop` 的进程内语义（进程内宿主本来就是信任方）。
- 不在 handler 里做"谁能批"的判断：审批人是谁是宿主的业务，reins 只把信息交出去。

## 验证矩阵（无真模型臂）

| 格 | 断言 |
| --- | --- |
| POST 新会话 / 普通续聊 | `decisions` 为 `[]` |
| POST 续跑带结论（含子会话 id 的一条） | 原样等于请求体里的数组 |
| 钩子对 `decisions.some(d => d.approved)` 回 false | 404，日志一条不写、不起 run；同一请求改成只带拒绝 → 放行 |
| GET | `[]` |
| STOP | `[]` |
| 进行中投递（midRunInput） | `[]`（投递不带 decisions） |

`pnpm check` 全绿；server 有 `/node` 子路径，跑 `pnpm check:dist`。
