# 图片引用形态：字节放 BlobStore，日志只存引用（AdRate 建议 17 第二步）

> 状态：📋 待实施（2026-11-24 经独立审查修订一版，修订要点见文末）

## 背景与根因

AdRate 建议 17（`docs/archive/2026-11-05-AdRate给reins的优化建议.md` 末节）：要支持用户在对话里贴截图（TikTok 后台报错、数据面板、素材图）。现状下 `ImagePart` 只有内联 base64 一种形态（`core/src/events/base.ts`），字节随事件进日志：

1. **字节永久在事件表里**：一张压缩截图 base64 后约 0.3～0.5MB，一个排查会话十来张就是几 MB；pg 的 `data` 列只能是 `json`（不能 jsonb），每次访问解析整行。
2. **读会话的成本随图片数线性涨，与图在不在视野内无关**：run 起步读整条时间线、宿主回放历史、宿主在事件上做的查询，都要把字节读出来再解析。
3. **前端展示要再取一遍**：只能从事件里取 base64 下发，或宿主另存一份。
4. **重复存储**："重新查看某张图"只能再存一份字节。

"折叠后取不回"已由第一步（`12d9343`，`recall` 取回被折叠用户消息含媒体）解决。

核实："媒体不外溢"（`brain/src/spill/spill.ts` 文件头）是**上下文**层面的取舍（一张图对模型是固定开销，没有分页读的意义），与续跑校验无关：`pendingDigest` / `configHash` 都不算消息内容。改成引用不碰续跑语义。

## 方案选择

| | 做法 | 判断 |
| --- | --- | --- |
| A（选） | 图片片段加引用形态 `{ type: "image", mime, blobId }`，与 `data` 二选一；core 在调降级层之前把**在视野内的**引用换回内联 | 降级层合同不动；被折叠的图一个字节都不读；字节单份存储 |
| B | 存储层透明外置：store-pg 写事件时把 base64 挪进 blob 表、读时拼回 | 否：读时照样全量拼回，第 2 点不解；存储层改写载荷违反"事件只按文本过库" |
| C | 降级层自己按 blobId 取字节 | 否：`Lowering.toRequest` 是同步纯函数（`lowering/types.ts:146`，四份实现 + eval 包装），改异步要动整个降级层合同 |
| D | 只让 AdRate 控制大小张数 | 否：第 2～4 点是结构问题 |

**范围只做图片。** 建议 17 原文说"AdRate 目前只需要图片"；视频 / 音频没有引用形态的真实样本，它们的估算还依赖字节大小（无 `durationSec` 时按字节折算），一并做就得往片段里补 `size`、改写宿主写的片段。等有样本再按本方案同一套机制扩展（视频 / 音频引用届时要求必带 `durationSec`，不引入 `size`）。

## 公开形状

```ts
// ---- core：图片片段变成判别联合（读 `.data` 的消费点编译期必须处理引用）----
export type ImagePart =
  | { type: "image"; mime: string; data: string }      // 内联，与现在相同
  | { type: "image"; mime: string; blobId: string }    // 引用：字节在 BlobStore

// ---- core：新增导出（真源，登记全景图真源索引）----
/** 图片引用形态的形状判定：mime 以 "image/" 开头，blobId 非空且 ≤ 128 字符，且不带 data */
export function isImageRef(p: ContentPart): p is ImageRefPart
/** 本会话时间线里被媒体引用过的 blob id 集合：只看 user_message / tool_result 的 content 里的图片引用，
 *  不看 spilled、不看文本、不看 ext.*。与 fetch_blob 的"外溢引用集合"刻意分开 */
export function mediaRefsOf(timeline: readonly Event[]): ReadonlySet<string>
/** 一个 blob 能不能被这个会话当图片用：meta.sessionId === sessionId，或已在 mediaRefsOf(timeline) 里。
 *  循环写入校验、server 预校验、宿主自建的下发路由共用这一份 */
export function blobUsableBy(sessionId: string, meta: BlobMeta, id: string, timeline: readonly Event[]): boolean
/** 校验一批片段里的图片引用，不过返回统一的一句话；顺手把取到的字节放进 cache */
export function checkImageRefs(parts, ctx: { sessionId; blobs?; timeline; cache }): Promise<string | undefined>
/** 视图里的图片引用换回内联；只换 not_found 之外都成功的，其余见规则 */
export function hydrateImageRefs(events, ctx: { blobs?; cache }): Promise<Event[]>
/** 零 Node 的 base64 编码（分块 btoa），core 里此前没有 */
export function bytesToBase64(bytes: Uint8Array): string
```

`BlobStore` 接口不变（不加 `stat`）：写入校验用 `get`，取到的字节进 run 级缓存，下一轮本来就要用。JSDoc 补两条它已隐含、本方案依赖的合同：**id 不复用、字节写入后不可改**；**`put` 要传原始字节，不要传 base64 串**（否则换回时会把 base64 再编一次）。

## 规则

### 形状
- **`isContentPart` 对图片引用 fail-closed**：mime 必须以 `image/` 开头（防止把同会话的外溢文本 blob 当图片引用，每轮发给厂商 400、会话卡死）；`data` 与 `blobId` 恰好一个；blobId 非空、≤ 128 字符。内联形态的校验保持现状（不追加 mime 前缀要求，免得历史会话读不出）。server 白名单同口径，跨包用例锁住。

### 写入校验（fail-closed，一条不写）
- **统一一句话，越权当不存在**："Blob <id> not found in this session"。不存在、不归本会话、没配 BlobStore 都是这一句；**先判归属、后比 mime**，mime 不符也报同一句——不给客户端探测别的租户 blob 是否存在、是什么 mime 的机会。
- **归属**：`blobUsableBy`。常见情况（`meta.sessionId === 本会话`）不扫日志；只有不等时才算 `mediaRefsOf`（循环里时间线已在内存）。fork 出的会话凭"已引用"用父会话的图；`recall` 取回的结果里是引用，自然合规。
- **入口**：
  - 起步 `input`：不过抛 RangeError、一条不写（与现有片段校验同口径）。
  - 中途 `pullInput`：不过走 `fail()` 落 `core.error(input)`（与现有"中途不合规"同口径；进程内宿主队列里的失效消息会让后续 run 反复失败，与现有"形状不合规"一致，在回复里告诉 AdRate）。
  - 工具结果：放在 afterTool 之后、`settle(result)` 之前（`run-loop.ts` 现在 `yield* await settle(result)` 那一处），覆盖 `toModelOutput` 输出、afterTool 换掉的结果和 isError 结果；不过整条结果换成 isError 的那一句。
  - **HTTP**：handler 在 `deliver`（进行中投递）之前与 `runs.create` 之前，对所有含图片引用的 input（含片段数组形）调同一个 `checkImageRefs`，不过回 **400**、一条不写；循环内校验保留为第二道。不做的话，片段数组形 input 只能拿到 200 + error 帧，进行中投递会先回 202、再让正在跑的 run 以 error 结束。
- **校验阶段存储抛错（非 not_found）**：不当成"不合规"。起步原样抛出；中途按 `pullInput` 抛错的既有口径（记 `core.error(host)`、当这次没有）；工具结果回"Could not read blob <id>: storage error"的 isError，不说"not found" 误导模型；HTTP 回 500 / 503 而非 400。

### 换回
- **时机**：beforeModel 之后、重试循环之外、`toRequest` 之前，对本轮视图调 `hydrateImageRefs`；换回后的事件只交给 `toRequest`，不回写 `ctx.events`（Socket 与估算看到的仍是引用）。瞬断重试复用同一份。
- **图片一律换回，不看能力位**：能力判定的真源在降级层（`lowering-fetch/src/media.ts` `acceptsMedia`；pi 版对图片不看能力位照发），core 按能力跳过会让"内联与引用逐字节相等"在能力位关时破功、落点原因也说错。
- **run 级缓存**：`Map<blobId, base64>`，写入校验取到的字节一并放进去；失败结果不进缓存。
- **只有 `StoreError("not_found")` 才落占位**（与 `spill.ts` `loadReferencedBlob` 同一写法）：片段保持引用形态交给降级层，四份降级层对"未换回的引用"落 `[image unavailable]` 文字占位、记 `lossy`，run 照跑。没配 BlobStore 而日志里有引用时同样处理。**其它存储错误**在 `toRequest` 那个 try 里抛出，走既有模型调用失败与重试判定——瞬时故障不能让模型对着占位作答、再把回答永久写进日志。登记 fail-open 例外表。

### 版本
- **`user_message` / `tool_result` 一律升 v2**（v1 → v2 恒等升级），不按载荷选版本。理由：注册表读时会把 `schemaVersion` 改写成当前版本（`registry.ts` `read` 末尾），按载荷选会让同一事件实时下发是 v1、补发读回是 v2；且选版本逻辑得进 `createEvent` 公开形状，TanStack 中间件与宿主自建事件才绕不过。一律升 v2 两行改动，老版本读新会话按现有规则拒读（fail-closed）。代价：升级后写过的会话不能回滚到 ≤ 0.15——按 0.10 / 0.14 先例写进 README，全实例同时升级（AdRate 本来就这样做）。

### 其它
- **token 估算不变**：图片每张固定 1600（`projection/estimate.ts`），不看字节，不需要宽高。
- **会话分叉**：fork 只复制事件，blob 不复制、归属不变；宿主按 `session_id` 物理清理父会话后，子会话里的这些引用落"unavailable"占位。README 写明。
- **"模型可见的一切都在日志里"改述为"日志 + 不可变 blob"**：AGENTS.md 工程硬约束同一提交改措辞；"按日志逐字节回放"要带上同一个 BlobStore（`core/src/replay/replay.ts` 文件头写明调用方先换回）。宪法不变（Boss 2026-11-24 同意）。
- **"重新查看某张图"不需要新工具**：降级层不把 blobId 给模型，模型想再看就是 `recall({ seq })`，取回的结果里是引用、不重复存字节。在回复里告诉 AdRate。

## 不做

- **视频 / 音频引用**（见范围）。
- **`BlobStore.stat`**：用 `get` + 缓存代替。handler 预校验因此会多读一次字节（每次 POST 每张图一次），可接受；将来有量再加。
- **"会话还没有事件时先 put"的特殊支持**：`put` 本来就不检查会话是否存在（三份实现已核实），告知 AdRate。
- **下发 blob 字节给前端的 HTTP 端点**：宿主自建路由，先过自己的会话鉴权，再用 `blobUsableBy` 判（不要只比 `meta.sessionId`，否则 fork 会话显示不了父会话的图）。README 给做法。
- **ui-agui 不改**：图片仍以占位文本 + `dropped` 表达；要 blobId 的宿主读 raw 时间线（AdRate 前端就这样读）。
- **TanStack 适配器不做换回**：该路径没有落点记录，引用片段落占位文本、记进 `dropped`；它的工具结果经 `toTanstackContent` 转出、`fromTanstackToolResult` 转回，引用会被永久写成文本进日志，即使会话之后改由 runLoop 跑也看不到图；这条路径写不出引用，因此也不需要归属校验。登记「刻意不对称清单」。
- **MCP 结果不自动转引用、不自动把内联图转存成引用**：形态由写入方定，库不改写宿主写的片段。

## 验证矩阵

全部假模型，**不花真钱**：引用只是存储形态，模型看到的请求与内联逐字节相同。

| 项 | 断言 |
| --- | --- |
| 等价 | 内联与引用两种写法，四份降级层 `payload` 逐字节相等；含能力位关的格子 |
| 只换视野内 | 被 compact 折叠的引用不调 `get`（计数 BlobStore） |
| 缓存 | 同 run 多轮、瞬断重试、写入校验后同轮使用，同一 blob 只 `get` 一次；失败不进缓存 |
| 取不到 | not_found / 没配 BlobStore：占位、落点 lossy、run 照跑；其它存储错误：不落占位、走重试判定 |
| 统一文案 | 起步 / 中途 / 工具结果 / HTTP 四入口，"别的会话的 blob""不存在""别的会话 + 错 mime""没配 BlobStore"文案逐字相同 |
| HTTP | 片段数组形 input、进行中投递带别人的 blobId → 400、一条日志不写；存储故障 → 5xx |
| 工具结果覆盖面 | afterTool 改写后的结果、`toModelOutput` 输出、isError 结果里的引用都被校验 |
| 形状 | 引用 mime 非 `image/`、`data` 与 `blobId` 并存、空 / 超长 blobId 被拒（core 与 server 同口径） |
| fork | 子会话引用父会话已引用的 blob 通过；父会话未引用的拒绝 |
| 引用集合分离 | `fetch_blob` 读不到只被图片引用过的 blob；图片引用不能指向外溢 blob（mime 不过） |
| base64 | ≥ 64KB、含 ≥ 0x80 字节的数据往返一致 |
| 版本 | 新写 user_message / tool_result 为 v2；实时与补发版本一致；模拟老注册表读 v2 拒读 |
| recall | 取回含引用的用户消息，结果里是引用不是字节；下一轮视图换回成功 |

发版：core minor，其余按改动走 minor / patch；发后空目录真实安装冒烟。完成后在建议文档末尾写 reins 回复（含：不需要"重看"工具、可以先 put、失效消息会让中途输入反复失败、不可回滚），请 AdRate 在测试服核实：贴两张图 → 折叠 → recall，事件表里该会话的 `data` 不含 base64。

## 修订要点（2026-11-24 独立审查后）

初版与本版的差异：范围收窄为只做图片、不加 `size`、不加 `stat`；版本改为一律升 v2；补齐"越权当不存在"的统一文案与"先归属后 mime"顺序；HTTP 入口预校验回 400；"已引用过"定义为图片引用集合、与 `fetch_blob` 的外溢集合分开；引用 mime 必须 `image/`；只有 not_found 落占位，其它存储错误走重试并登记 fail-open；换回不看能力位；改动清单补四份有损矩阵、examples、replay 文件头、base64 函数。审查第 15～17 条（可不加 stat、中途毒消息、重看工具已解决）全部采纳。
