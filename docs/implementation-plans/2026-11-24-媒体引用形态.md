# 媒体引用形态：字节放 BlobStore，日志只存引用（AdRate 建议 17 第二步）

> 状态：📋 待实施

## 背景与根因

AdRate 建议 17（`docs/archive/2026-11-05-AdRate给reins的优化建议.md` 末节）：要支持用户在对话里贴截图（TikTok 后台报错、数据面板、素材图）。现状下 `ImagePart` 只有内联 base64 一种形态（`core/src/events/base.ts`），媒体字节随事件进日志：

1. **字节永久在事件表里**：一张压缩截图 base64 后约 0.3～0.5MB，一个排查会话十来张就是几 MB；pg 的 `data` 列只能是 `json`（不能 jsonb），每次访问解析整行。
2. **读会话的成本随图片数线性涨，与图在不在视野内无关**：run 起步读整条时间线、宿主回放历史、宿主在事件上做的查询，都要把字节读出来再解析。
3. **前端展示要再取一遍**：只能从事件里取 base64 下发，或宿主另存一份（两份存储、两处清理）。
4. **重复存储**：AdRate 要给模型一个"重新查看某张图"的工具，它只能再返回一份字节。

第 4 点里"折叠后取不回"已由第一步（2026-11-24，`recall` 取回被折叠用户消息含媒体）解决，不在本方案内。

核实："媒体不外溢"（`brain/src/spill/spill.ts` 文件头）是**上下文**层面的取舍：一张图对模型是固定开销，没有分页读的意义。它与续跑校验无关，`pendingDigest` / `configHash` 都不算消息内容。所以改成引用不碰续跑语义。

## 方案选择

| | 做法 | 判断 |
| --- | --- | --- |
| A（选） | 媒体片段加引用形态 `{ type, mime, blobId }`，与 `data` 二选一；core 在调降级层之前把**在视野内的**引用换回内联 | 降级层基本不动；被折叠的图一个字节都不读；字节单份存储 |
| B | 存储层透明外置：store-pg 写事件时把大 base64 挪进 blob 表、读时拼回 | 否：读的时候照样全量拼回，第 2 点不解；存储层改写载荷违反"事件只按文本过库" |
| C | 降级层自己按 blobId 取字节 | 否：`Lowering.toRequest` 是同步纯函数（四份实现 + eval 包装），改成异步要动整个降级层合同 |
| D | 只给 AdRate 说"自己控大小张数" | 否：第 2、3、4 点是结构问题，控制大小解不了 |

## 公开形状

```ts
// ---- core：内容片段（三种媒体同一做法）----
export interface ImagePart {
  type: "image"
  mime: string
  /** 内联 base64；与 blobId 二选一 */
  data?: string
  /** BlobStore 里的引用；与 data 二选一。字节不进日志，调模型前由循环取回 */
  blobId?: string
}
// VideoPart / AudioPart 同样加 blobId?，data 改可选；durationSec 不变
// 类型上用判别联合表达"二选一"，具体写法实现时定（目标：读 `.data` 的消费点编译期必须处理引用）

// ---- core：BlobStore 加可选 stat（只取元数据，不读字节）----
export interface BlobStore {
  // …put / get / slice 不变
  /** 可选：只取元数据；不存在返回 null。没实现时循环退回 get */
  stat?(id: string): Promise<BlobMeta | null>
}

// ---- core：新增导出（真源）----
/** 片段是不是引用形态 */
export function isMediaRef(p: ContentPart): boolean
/** 校验一批片段里的引用：存在、归属本会话或本会话日志已引用过、mime 与元数据一致。不过返回原因 */
export function checkMediaRefs(parts, ctx: { sessionId; blobs; timeline }): Promise<string | undefined>
/** 视图里的引用换回内联（只换在视野内、能力位收的那些）；取不到的原样留着交给降级层落占位 */
export function hydrateMediaRefs(events, ctx: { blobs; capabilities; cache }): Promise<Event[]>
```

## 规则

- **引用只是存储形态，模型看到的与内联逐字节相同。** 循环在 beforeModel 之后、`toRequest` 之前调 `hydrateMediaRefs`，只处理本轮视图里的事件。同一 run 内按 blobId 缓存（blob 写入后不可改，缓存安全）。重试复用同一份结果，不重取。
- **能力位不收的不取字节。** 模型不收视频 / 音频时不读那段字节，降级层照旧落占位记 lossy。
- **取不到的引用交给降级层声明有损。** blob 被清理或读失败时，片段保持引用形态进 `toRequest`；四份降级层（三条 fetch 线 + pi）对"未换回的引用"落文字占位（"[image unavailable]"）记 `lossy`，矩阵测试断言。run 照跑，不抛错。理由：落点声明的真源在降级层，core 自己换成文字会让降级层误记 exact。
- **写入前校验，fail-closed，一条不写。** 引用必须：① blob 存在；② `meta.sessionId === 本会话` **或** 本会话日志里已有片段引用过它（与 `fetch_blob` 按引用授权同一口径，fork 出的会话照样能用父会话的图，`recall` 取回的结果自然合规）；③ 片段 mime 与 `meta.mime` 一致。三个入口：
  - 起步 `input`：不过抛 RangeError、一条不写（与现有片段校验同口径）；
  - 中途 `pullInput`：不过走 `fail()` 落 `core.error(input)`（与现有"中途不合规"同口径）；
  - 工具结果：不过整条结果换成 isError 文本 "Blob … not found in this session"，不泄露该 blob 是否存在于别处（越权当不存在）。
- **HTTP 入口必须走这道校验。** server 白名单放行 `{ type, mime, blobId }`，归属校验在循环层统一做——不做的话，客户端填别的租户的 blobId，模型就会把别人的图"看"一遍。server 白名单与 core `isContentPart` 是两份，按惯例补一条穿过两个入口的跨包用例。
- **token 估算不变。** 图片现在按每张固定 1600 估（`projection/estimate.ts`），不看字节，引用形态照旧，不需要宽高。视频 / 音频没有 `durationSec` 时现在按字节折算：引用形态在写入校验时由循环把 `meta.size` 记进片段的 `size?` 字段，估算按它折算；有 `durationSec` 时照旧优先。
- **老版本读到引用要拒读，不能静默乱发。** 老 core 读到无 `data` 的片段会把 `undefined` 当字节发出去。做法：`user_message` / `tool_result` 升 v2，**只有含引用片段的事件按 v2 写**，其余仍写 v1（v1 → v2 的升级函数是恒等）。老版本读到 v2 按现有规则拒读（fail-closed），没用引用的会话照常可回滚。需要注册表支持"按载荷选写入版本"，这是本方案唯一的机制新增；实现时若发现代价超出预期，退回 0.14 先例（README 回滚说明 + 全实例同时升级），在本文件状态行下写明偏差。
- **会话分叉**：fork 只复制事件，blob 不复制、归属不变；子会话凭"日志已引用"读父会话的 blob。宿主按 `session_id` 物理清理父会话时，子会话里的这些引用变成"取不到"，按上一条落占位。在 README 写明。
- **"模型可见的一切都在日志里"改述为"日志 + 不可变 blob"。** AGENTS.md 工程硬约束同一提交改措辞：日志里存不可变 blob 的引用，等价于存原件；"按日志逐字节回放"的测试要带上同一个 BlobStore。宪法不变（Boss 2026-11-24 同意）。

## 不做

- **不提供"会话还没有事件时先 put"的特殊支持**：三个存储的 `put` 本来就不检查会话是否存在，已经可以。在回复里告知 AdRate。
- **不提供下发 blob 字节给前端的 HTTP 端点**：宿主用自己的路由，授权须先过自己的会话归属判断再读 `meta.sessionId` 核对。README 给一句做法。
- **ui-agui 不改**：媒体仍以占位文本 + `dropped` 表达；要 blobId 的宿主读 raw 时间线（AdRate 的前端就是这样读的）。
- **TanStack 适配器不做换回**：引用片段在该路径落占位、记 lossy，登记进「刻意不对称清单」。没有宿主走这条路发图；它的消息转换是同步的，补异步换回要动适配器的转换链。
- **MCP 工具结果不自动转引用**：tools-mcp 照旧内联。宿主要省存储，自己在 `afterTool` 里 put 并改写。
- **不自动把内联图转存成引用**（例如 spill 把大图挪出去）：形态由写入方定，库不改写宿主写的片段。

## 验证矩阵

全部假模型，**不花真钱**：引用只是存储形态，模型看到的请求与内联逐字节相同，这一点用"同一会话分别用内联 / 引用写，两次 `toRequest` 产出逐字节相等"的用例锁住，三条 fetch 线 + pi 各一份。

| 项 | 断言 |
| --- | --- |
| 等价 | 内联与引用两种写法，四份降级层的 `payload` 逐字节相等 |
| 只换视野内 | 被 compact 折叠的引用不调 `get`（计数 BlobStore）；能力位不收的视频不调 `get` |
| 缓存 | 同 run 多轮、瞬断重试，同一 blob 只 `get` 一次 |
| 取不到 | blob 删除后落占位、落点 lossy、run 照跑 |
| 校验 | 不存在 / 别的会话 / mime 不符：起步抛错一条不写、中途 `core.error(input)`、工具结果 isError 且文案与"不存在"同一句 |
| fork | 子会话引用父会话已引用的 blob 通过；引用父会话未引用的 blob 拒绝 |
| HTTP | server 收引用片段走同一校验；跨租户 blobId 被拒（跨包用例） |
| 版本 | 含引用的事件写 v2、不含的写 v1；模拟老注册表读 v2 拒读 |
| 存储 | 一致性套件 stat 用例，pg 真库（`REINS_PG_URL`）/ sqlite / 内存共跑 |
| recall | 取回含引用的用户消息，结果里是引用不是字节；下一轮视图换回成功 |
