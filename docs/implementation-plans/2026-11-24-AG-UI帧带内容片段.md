# AG-UI 帧带内容片段，前端能显示发过的图（AdRate 建议 19）

> 状态：✅ 已完成（2026-11-24）（实施前经独立审查修订一版，修订要点见文末）

## 背景与根因

AdRate 建议 19（`docs/archive/2026-11-05-AdRate给reins的优化建议.md` 末节）。已逐行核对 ui-agui 0.7.2 源码：

- `map-event.ts` 的 `partsToText` 把图片 / 视频 / 音频换成 `[<类型> <mime>]` 占位，`dropped` 只记 `<类型>:<mime>`，**不带 `blobId`**。`core.user_message` 与 `core.tool_result` 都走它。
- `@reinsjs/agent` 的 `createAgent` 缺省 `aguiEncoding()`，POST 实时流与 GET 补发都经 `mapEvent`。
- server README「Images by reference」教宿主按 `blobId` 搭取图路由，缺省的 AG-UI 编码却不给前端这个 id。

**这是对上一条决策边界的修订**：媒体引用方案（`2026-11-24-媒体引用形态.md`「不做」节）定了"ui-agui 不改，要 blobId 的宿主读 raw 时间线（AdRate 前端就这样读）"。建议 19 说明这个前提不成立——AdRate 前端按 AG-UI 帧建时间线。那份方案冻结不改，全景图那条决策的边界措辞同步改为指向本方案。

AG-UI 0.0.59 原生的多媒体位（`Image` / `Audio` / `Video` / `Document` 四种 `InputContent`）只在 `UserMessage.content` 里，用于 `RunAgentInput` / `MESSAGES_SNAPSHOT`，来源只有 `data`（字节）或 `url`；我们发的流式 `TEXT_MESSAGE_*` 与 `TOOL_CALL_RESULT` 只装文本。`blobId` 不是 url，reins 也不知道宿主路由，所以只能挪到 `metadata.reins`（与 `provenance` 同一处）。

**审查顺带挖出的既有缺陷**：AG-UI 客户端拼消息时把 START / CONTENT / END 三帧的 `metadata` 按顶层键"后写整个替换"合并（`@ag-ui/core` `mergeMetadata`："never recurses … replaced wholesale"；`@ag-ui/client` 三个 case 都调它）。我们的 CONTENT / END 只带 `{ seq, eventId, type }`，于是按 `messages` 状态渲染的前端（CopilotKit 一类）拼完消息后 `provenance` / `dropped` 已经被 END 冲掉——进行中投递靠 `provenance` 对账，这类前端一直拿不到。新加的 `parts` 照现有写法会一样丢，必须一并修。

## 方案选择

| | 做法 | 判断 |
| --- | --- | --- |
| A（选） | 有媒体片段时，user_message 的 START **与 END** 都带完整 `metadata.reins`（含 `parts`），`TOOL_CALL_RESULT` 带 `parts` | 前端按原顺序渲染，不用猜占位；官方客户端拼出的消息也保得住；纯文本消息输出不变 |
| B | `metadata.reins.media`：只列媒体 + content 下标 | 否：前端要拿按 `\n` 拼的 `CONTENT` 反推位置，正是建议里说的"按占位文字去猜" |
| C | 用户消息改发 `MESSAGES_SNAPSHOT`、走原生 `ImageInputContent` | 否：来源只有字节或 url，前者违反"不输出字节"，后者要 reins 知道宿主路由；改帧类型破坏现有前端 |
| D | 编码器加 `imageUrl(blobId)` 选项让宿主给 url | 否：流式帧没有原生位，最终仍落 metadata；多一个公开选项换不来什么 |
| E | 只做用户消息 | 否：只多一处调用；只做一边要登记一条没有理由的不对称 |
| F | `parts` 只挂 START（初稿） | 否：官方客户端拼消息时被 END 冲掉（审查第 1 条） |

## 公开形状（只加不改）

```ts
// ---- ui-agui types.ts ----
/** 前端展示用的内容片段：永不含字节。与时间线 content 逐个对应、顺序相同 */
export type AguiDisplayPart =
  | { type: "text"; text: string }
  | { type: "image"; mime: string; blobId?: string } // 引用形态才有 blobId；内联图片只给 mime
  | { type: "video"; mime: string }
  | { type: "audio"; mime: string }

export interface ReinsMetadata {
  // ……现有字段不变
  /**
   * 展示片段。只在 user_message 的 TEXT_MESSAGE_START / END 与 TOOL_CALL_RESULT 上出现，
   * 且只在 content 含媒体片段时出现（与 `dropped` 同出同缺）。前端有它就按片段渲染，没有就照旧读正文
   */
  parts?: AguiDisplayPart[]
}

// ---- ui-agui map-event.ts（新增公开纯函数；partsToText / reinsMetadata 签名不动）----
export function displayPartsOf(content: readonly ContentPart[]): AguiDisplayPart[]
```

`index.ts` 已是 `export type * from "./types.js"`，类型自动导出；`displayPartsOf` 加进值导出那行。总包 `export *` 自动带出、名字不冲突。

## 规则

1. **出现条件 = `dropped` 非空**：纯文本（含只有 `tool_reference`）的消息与结果不带 `parts` 键；长文字只在带图的消息里多发一遍。
2. **位置**：
   - user_message：START 与 END 带**同一份**完整 `metadata.reins`（基础字段 + `dropped?` + `provenance?` + `parts?`），CONTENT 不变。这对**所有** user_message 生效——带 `provenance` 或 `dropped` 的 END 从此也带它们（修既有缺陷）；两者都没有的纯文本消息 END 与改前逐字相同。
   - tool_result：`TOOL_CALL_RESULT` 只有一帧，`parts` 与 `isError` / `spilled` 并存。
   - model_text / thinking / CUSTOM / encoder 状态机不变；SSE id 仍挂最后一帧。
3. **映射**（`displayPartsOf`，逐类型显式分支、`never` 收口）：
   - `text` → `{ type: "text", text }`；`tool_reference` → `{ type: "text", text: renderToolReference(p) }`（与正文同一写法）；
   - 图片：`isImageRef(p)` 为真 → `{ type: "image", mime, blobId }`，否则 `{ type: "image", mime }`（畸形片段退成只给 mime，方向安全）；
   - 视频 / 音频 → `{ type, mime }`，不带 `durationSec`；
   - 逐个对应，不合并相邻文本。
4. **永不输出字节**：只按白名单挑字段新建对象，绝不展开原片段（`{ ...p }` 会把 `data` 带出去）。
5. **不变的**：`TEXT_MESSAGE_CONTENT` 占位文字、`dropped` 内容、帧类型与顺序、事件日志、模型请求。

### 安全口径

- 前端从此看得到图片 id（缺省 AG-UI 编码下，工具产出的图片 id 以前不进浏览器；先例是 `TOOL_CALL_RESULT.metadata.reins.spilled.blobId` 早就在帧里）。**id 本身不给权限**。
- 取图路由三道缺一不可：先过会话鉴权 → `blobUsableBy` → **检查 `meta.mime` 以 `image/` 开头**。`blobUsableBy` 对本会话自己的任何 blob 都返回真，包括外溢的文本 blob；改后 `parts` 里的图片 id 与 `spilled.blobId` 并排出现在同一个 `metadata.reins` 里，只靠前两道就能拿外溢 id 去图片路由取文本。server README 配方已有 mime 检查，本次在两份 README 里明说它是必需的。
- 自定义 BlobStore 不要用存储路径或签名 URL 当 id——这个 id 现在会到浏览器（建议 19「不输出存储位置」的边界）。
- 前端必须能退回占位显示：内联图片没有 id；blob 被保留策略清掉后路由 404；`blobId` 是不透明字符串，拼 URL 要 `encodeURIComponent`。

## 审查修订要点

1. `parts` 只挂 START 会被官方客户端的 `mergeMetadata` 用 END 冲掉，且 `provenance` / `dropped` 早已如此 → START / END 共用完整元数据，加折叠用例。
2. 安全口径初稿说"不是新暴露"不准 → 改为"看得到但不给权限"，写明 mime 检查是必需的第三道（外溢文本 blob 也过 `blobUsableBy`）、id 不放存储位置、前端退回占位。
3. 推翻了媒体引用方案"ui-agui 不改"的边界 → 背景交代原因，全景图旧条边界措辞同步改。
4. 改 `partsToText` 返回值会挂现有 `toEqual` 用例、牵连宿主 → 改为新增 `displayPartsOf`，`partsToText` / `reinsMetadata` 不动。
5. 验证矩阵补畸形片段、混排顺序、实时路径、独特字节标记、两项变异；文档路由补齐盘点三处、两份 README、全景图旧条。
