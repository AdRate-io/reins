Modules that bring their own tools — `compact()` (`compact`, `recall`), `spill()` (`fetch_blob`), `pins()` (`pin`), `handoff()`, `memory()`, `skills()` (`skill_read`) and `lazyTools()` (`tool_find`) — now stand down when a tool of the same name is already bound before them (a host tool, or one from a socket registered earlier such as an MCP server). The loop keeps the first tool of a name, so before this the module's rules sent the model to someone else's tool and its hooks treated that tool's calls as its own: a spilled result fetched from an MCP server, an MCP `handoff` call ending the session, an MCP `compact` call folding history. Now the module registers neither its tools nor its rules for that run, its hooks stay idle, and it warns once. `spill()` then passes results through unspilled, as without a `BlobStore`; `pins()` keeps the host's pins and drops only the `pin` tool, as with `tool: false`. Passing the module's own tool object in the host's `tools` is not a clash. `compact()`, `pins()` and `handoff()` gain a `warn` option for this. Because the check needs the tool table, these modules' `tools` and `systemPrompt` contributions are now functions of the socket setup: code that read `spill().systemPrompt` or `handoff().tools` as plain values should resolve them with `resolveSocketContributions` from `@reinsjs/core`.
