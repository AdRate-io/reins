Images can be stored by reference: `{ type: "image", mime, blobId }`, with the bytes in the `BlobStore` and only the id in the log. Right before each model call `runLoop` swaps the references in view for inline images (`hydrateImageRefs`, at most one read per blob per run), so lowerings see exactly what the inline form would give; folded images are not read. References are checked before anything is written — initial `input` (`RangeError`), `pullInput` (run ends with a `core.error` of category `input`), tool results (only the offending part is replaced; the rest is kept) — and every rejection reads `Blob <id> not found in this session`. A blob that no longer exists is passed on as a reference and becomes `[image unavailable]` in the lowering; other storage errors fail the model call like a network error. New exports: `isImageRef`, `mediaRefsOf`, `blobUsableBy`, `checkImageRefs`, `imageRefNotFound`, `hydrateImageRefs`, `bytesToBase64`, `ImageInlinePart`, `ImageRefPart`; `ImagePart` is now a union of the two, so code reading `.data` must check `isImageRef` first. `core.user_message` and `core.tool_result` are written as schema v2 (v1 upgrades unchanged): sessions written by this version cannot be read by 0.15 or earlier — upgrade every instance together.
