## 结论

1. **规则文案改不动这个行为。** 补的两句话在 DeepSeek v4.1 flash 上没有可测的效果（1/13 对 0/12）。
2. **模型根本没在想上下文。** 29 格本轮输出的思考里，"compact / context window / 上下文 / 70% / 85%"一次都没出现；冒烟那次整理的思考里也没有。感知说明报"≥85%、预算余量 5%–20%（最紧的是上下文）"，它照常开工。系统提示末尾的规则在 28 万 token 的上下文里不进入决策。
3. **副作用没出现：** <50% 的对照切点两臂都 0 次整理，没有"宽裕时也整理"；没有 `mid`。
4. **召回：** 候选臂 100%；现行臂 work 78%、wrapup 89%（三格都没整理过，丢分不是整理造成的：两次答成了原文里更早的旧合计，一次探针里没作答）。

## fixture 本身的问题（第二轮要修）

- **回放泄底：** 录像里没有的读 / 生成调用回 "This is a replayed environment"，模型思考里会写"这是回放，那就收尾"，干扰了"什么时候停"的判断。两臂吃同一个干扰，比较仍成立，但绝对比例不可信。
- **阈值兜底在 ≥85% 切点一次没触发：** 感知按校准后的真实用量报"≥85%、85% 自动折叠"，兜底按未校准的投影估算判（低约 7K），两者口径不一 —— 模型看到的"85% 会自动折叠"在这里不成立。另记一条待查。
